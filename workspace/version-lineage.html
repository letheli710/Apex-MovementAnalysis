会话怎么往日志里写

每做一个决定、拿到一份数据、出一个新版本、合并一个 PR，就用 ArtifactData 往这个页面的 log 集合写一条（set，新文档不用 if_version）。文档 id：日期-会话短名-主题，例如 2026-10-30-cam-k8。一个决定的每个选项各写一条：选中的 role=version，没选的 role=parallel。这样旧版本和没选的都留档。完整规则在工作区根目录的 CLAUDE.md。

{
  "topic": "镜头",            // 已有的功能名，或者新功能名（会自动多一条横带）
  "role": "version",          // version 新的现在版本 | parallel 平行保留 / 没选 | pending 还要定 | note 只进日志
  "kind": "decision",         // decision | data | version | milestone | issue | plan
  "phase": "U",               // M 正线 | N REA | S 副线 | R 按 R5 复刻 | T TF2 | U 10-30 以后
  "date": "10-30", "sortDate": "2026-10-30", "order": 1,
  "name": "K-8 下滑索 punch 按 R5 加",
  "data": "Unity 0° → 12–14°（R5 12–14°）",
  "why": "D-36：以 R5 为准", "sw": "NativeCameraParams.zipDetachPunch",
  "rec": "HSD-Unity#50, D-66", "session": "会话短名",
  "ts": "2026-10-30T08:00:00Z", "resolved": false
}

一个"还要定"的事定下来以后，把那一条 update 成 "resolved": true（不删），再写一条新的 version。

旧档部分整理自研究仓库 DECISIONS.md、R5-DIFF-ARCHIVE.md、TODO.md、TF2-Research 报告（标"seed 10-30"）。之后的条目由各会话写入。页面连不上数据库时显示内嵌的快照。
