Read-only source study for M4 (legend movement primitives). Nothing was run. Paths are abbreviated:

- `P:` = `research-src/s21-platform/scripts/vscripts/`
- `PW:` = `research-src/s21-platform/scripts/weapons/` (weapon `.txt` settings, **readable**)

## 0. Blockers that apply to every ability (read first)

1. **The fs_1v1 playlist gives no abilities and no passives.** `Survival_PlayerCharacterSetup` skips passives, tactical and ultimate when `FS_Is1v1Playlist()` (`P:gamemodes/_gamemode_survival.nut:4121-4139, 4143-4163`). On spawn, 1v1 also calls `TakeAllPassives` and strips the offhands unless the playlist var `give_legend_tactical` is set (`P:gamemodes/fs_1v1/_gamemode_1v1.nut:2621-2624, 2208`; `P:gamemodes/fs_1v1/_1v1_legends.nut:264-273`). **`Agent_SetLegend` (`P:agent/sv_agent_api.nut:739-774`) therefore changes only the setfile (class vars). It does not equip the kit.** [S]
2. **Equip by hand (server EVAL).** Resolve class names at runtime instead of guessing them:
   ```squirrel
   ItemFlavor c = LoadoutSlot_GetItemFlavor( ToEHI(p), Loadout_Character() )
   p.GiveOffhandWeapon( CharacterAbility_GetWeaponClassname( CharacterClass_GetTacticalAbility( c ) ), OFFHAND_TACTICAL, [] )
   p.GiveOffhandWeapon( CharacterAbility_GetWeaponClassname( CharacterClass_GetUltimateAbility( c ) ), OFFHAND_ULTIMATE, [] )
   foreach ( ItemFlavor a in CharacterClass_GetPassiveAbilities( c ) ) GivePassive( p, CharacterAbility_GetPassiveIndex( a ) )
   p.Server_TurnOffhandWeaponsDisabledOff()
   ```
   This is the same pattern 1v1 uses (`_1v1_legends.nut:239-248, 272`). `GivePassive` is SERVER-only (`P:sh_passives.gnut:408-424`). Run `print` on the classnames, or use `Agent_State`, which lists `offhands` (`sv_agent_api.nut:102-140`), to confirm. **Do not use `Agent_Give` for abilities.** It puts any `mp_ability_*` into a *primary* weapon slot (`sv_agent_api.nut:665-692`). [S]
3. **Slots and buttons.** `OFFHAND_TACTICAL = OFFHAND_LEFT = 1`, `OFFHAND_EQUIPMENT = 3`, `OFFHAND_ULTIMATE = OFFHAND_INVENTORY = 4` (`P:sh_consts.gnut:803-813`). Console `+offhand1` is the tactical and `+offhand4` is the ultimate (`P:client/cl_input_overlay.gnut:120-121`). The button bits are IN_OFFHAND0..4 = bits 20..24 (0x100000, **0x200000 = tactical**, 0x400000, 0x800000, **0x1000000 = ultimate**) (`SDK:game/server/energize.cpp:1531-1536`, `SDK:game/shared/offhand_slots_ext.cpp:143-146`, `SDK:game/server/jetpack.cpp:128`). Airborne jump abilities read IN_DODGE (bit 28). The client presses it together with `+jump` while `+dodge` is unbound (`SDK:game/shared/jump_input_gate.h:1-6`). From a client EVAL: `player.ClientCommand("+offhand1")` … `("-offhand1")` on counted frames, as M1–M3 already do for movement keys. [S]
4. **Refill (server EVAL), no cheats needed.** This is `ReloadTactical` (`_1v1_legends.nut:275-291`): `w.SetNextAttackAllowedTime(Time()-1)`; charge weapons use `w.SetWeaponChargeFractionForced(0)`, others `w.SetWeaponPrimaryClipCount(w.GetWeaponPrimaryClipCountMax())`; then `p.SetSuitGrapplePower(100)`. For both slots plus the glide/jet meter, use `DevAbilities_RefillPlayer(p, true)` (`P:weapons/_weapon_utility.nut:3810-3865`), or the client command `recharge` (needs `sv_cheats 1`, `P:_clientcommands.gnut:834-842`). **Do not use `infinite_abilities`** for grapple trials. It adds the mod `infinite_abilities_grapple`, which **doubles grapple range** (`_weapon_utility.nut:3867-3888`, `PW:mp_ability_grapple.txt:136-141`). [S]
5. **Map triggers.** 1v1 disables every `trigger_cylinder_heavy` / `trigger_no_grapple` that exists at match init (`_gamemode_1v1.nut:1880, 2542-2565`). Pads and lifts we create later are not affected. [S]
6. **Aim.** The trigger direction is the client-predicted eye direction at fire time (grapple `attackParams.dir`, `P:weapons/mp_ability_grapple.nut:105-120`; pounce `EyeAngles()`, `mp_ability_revenant_shadow_pounce_free.nut:350-391`). The reset recipe's `SetAngles`/`SnapEyeAngles` plus a settle wait (as in `hsd_trial.py`) is enough. Log the client `EyeAngles()` on the fire frame. [I]
7. **MOVE-TRACE coverage.** `bridge_move_trace` samples at `CGameMovement::FullWalkMove` (`SDK:game/server/move_sim_trace.cpp:1-45`; the client twin is `game/client/move_sim_trace.cpp`). It logs maxspeed, origin, velocity, ground, duck, slide, sprint and **`m_cachedMoveScale`**. It logs no ability state. Add a per-frame client EVAL logger for ability flags (listed per ability below).

## 2. Priority 1

### 2.1 Pathfinder grapple (`mp_ability_grapple`)
- **Trigger:** tap `+offhand1` (offhandInstant → `OnWeaponPrimaryAttack` → `owner.Grapple(dir)`, `mp_ability_grapple.nut:78-127`). Auto-aim can bend `dir` toward a target entity when one is present (`:109-118`). Keep dummies away. Switching in is refused unless `GetSuitGrapplePower() >= 100`. While refused, it calls `Grapple(<0,0,1>)` (`:140-161`). This is probably the press-again release [I]. Bleedout forces detach (`:452-458`).
- **Charges:** clip 300, min-to-fire 300, regen 10/s (30 s) (`PW:mp_ability_grapple.txt:52-57`). On attach the drain thread **holds clip at 0** while grappling or while |v| > 500, for up to 5 s. It then charges 100 + distance-scaled ammo, using playlist `pathfinder_grapple_drain_*` (`mp_ability_grapple.nut:27-45,265-384`). Refill = clip 300, remove mod `grapple_regen_stop`, `RegenerateAmmoReset()`, `SetSuitGrapplePower(100)` (`_weapon_utility.nut:3834-3840,3858`). **Wait ≥ 5 s or until |v| < 500 before refilling**, or the drain thread re-zeroes the clip.
- **Parameters:** range `grapple_maxLength 850`, `grapple_maxLengthVert 850`, `grapple_power_required 100` (`PW:mp_ability_grapple.txt:47-50`). Pull/swing/retract speeds are native setfile values [?]. Netvars `m_grappleVel`, `m_grapplePoints`, `m_grappleAttached/Pulling/Swinging/Retracting` exist (`SDK:game/shared/s21_dt_schema.h:3202-3210`). Fit them from MOVE-TRACE.
- **Phase detection:** server `AddCallback_OnGrappled(fn(player,hitent,hitpos,normal))` / `AddCallback_OnGrappleDetached(fn(player))` (`mp_ability_grapple.nut:435-451`). `CodeCallback_OnGrappleAttach` also runs on the client (`:201-263`). Per-frame client poll: `player.IsGrappleActive()`.
- **Geometry:** a solid surface within 850 u along the aim. The map-editor rock (`CreatePropDynamic(..., SOLID_VPHYSICS)`, `P:mapeditor/_mapeditor.nut:428`) or the floor works. Put the attach point at a known distance (for example 600 u) and a known height.

### 2.2 Octane stim (`mp_ability_octane_stim`)
- **Trigger:** tap `+offhand1`. Charge weapon, `OnWeaponChargeBegin` fires immediately (`mp_ability_octane_stim.nut:62-103`). It cannot be re-activated while `stim_visual_effect` is active (`:115-125`).
- **Effect:** `GivePlayerSettingsMods(["stim_sprint"])` for `duration` (6 s, playlist `octane_stim_duration`, `:6,28-32`; `sh_stim.gnut:58-60,82-94`). Also `speed_boost` severity **0.15** for duration + 0.5 s with a 0.5 s fade-out, and `anti_slow` (`sh_stim.gnut:62-64`). Move-scale product on both engines: `cachedMoveScale = msss·(1−slow)·(1+2·sev_boost)·landing·weapon` (`SDK:game/server/melee_lunge_probe.cpp:406-421`; "extraScale 2.0" `sh_stim.gnut:12`) → **×1.30**. The contents of `stim_sprint` are setfile [?]. Run a class-var census during the stim. Also: −20 HP (min 1) (`:7,77-82`), and slows are cleared (`:68-75`).
- **Refill:** charge weapon: `SetWeaponChargeFractionForced(0)` + clip 1. Regen is 2/s on clip 1 (`PW:mp_ability_octane_stim.txt:20-27,41-52`). Refill health with `Agent_SetHealth`.
- **Detection:** MOVE-TRACE `m_cachedMoveScale` steps (best signal). Client poll `StatusEffect_GetSeverity(p, eStatusEffect.speed_boost)`.

### 2.3 Octane jump pad (`mp_weapon_jump_pad`)
- **Two ways to trigger.** (a) Natural: `+offhand4` down → toss prep, up → throw. Projectile 1000 u/s, pitch offset +2°, inherits owner velocity; it lands, plays its unpack anim, then arms (`PW:mp_weapon_jump_pad.txt:85,99-101`; `mp_weapon_jump_pad.nut:10-49`; `sh_jump_pads.gnut:231-277`). Ult clip 90, regen 1/s (`txt:105-113`). (b) **Recommended (reproducible):** server EVAL `JumpPad_CreateAtLocation(<x,y,294.92>, <0,0,0>, player, true)` creates the authentic pad and trigger at once (`sh_jump_pads.gnut:279-320`). Then walk or drop into it. Use (b) for kinematics and (a) only as a sanity check.
- **Parameters (script constants):** `JUMP_PAD_PUSH_VELOCITY 1150` (×1.2 with `PAS_ULT_UPGRADE_ONE`), `JUMP_PAD_VERT_OVERRIDE 2.0`, trigger radius 32, above 32 / below 16, double jump granted (`sh_jump_pads.gnut:27-41,143-151,342-358`). SDK parity: ducked vert scalar **0.5**, double-jump grant delay **0.1 s**, relaunch debounce **1.0 s**, air launches allowed (`SDK:game/server/jumppad_parity.cpp:63-71,98,199`). The launch formula itself is native [?]. Fit vz and vxy against approach speed and duck state.
- **Detection:** server `player.WaitSignal("JumpPadStart")` (signalled by `JumpJetsWhileAirborne`, `sh_jump_pads.gnut:508-516`). In MOVE-TRACE, a vz step on one command.

### 2.4 Horizon gravity lift (`mp_ability_space_elevator_tac`) and passive
- **Trigger:** natural `+offhand1` down/up (toss, 1000 u/s; clip 250, regen 10/s; `PW:mp_ability_space_elevator_tac.txt:13,23,114-115,184-190`). **Recommended:** server EVAL `thread SpaceElevator_PropDeploy(player, <x,y,294.92>, <0,0,0>, null)` (`sh_space_elevator.gnut:172-260,346-358`).
- **Parameters (script constants, playlist-overridable):** height 1200, radius 70, `up_speed 300`, `up_accel 100000`, `horizontal_speed 170` / `accel 2000`, `tocenter_speed 50` / `accel 0`, `eject_up 450`, `eject_horizontal 400`, `max_eject_time 0.5`, `max_hover_time 0.5`, lifetime 10 s (`P:mp/sh_space_elevator.gnut:51-72,511-547`). Dedi algorithm (mirrors the client): vz → clamp(vz + upAccel·dt, 5, upSpeed) below 90 % height, then a hover band. Input steers at airSpeed/airAccel and no input pulls toward the centre. Leaving the volume, or hovering longer than 0.5 s, ejects with `eject·min(dwell/0.5,1)` along the flat view (or travel > 40 u, or the move dir). Re-entry is blocked for 2 s after an eject (`SDK:game/server/trigger_gravity.cpp:72-79,655-910,912-1010,1290-1361`).
- **Detection:** `StatusEffect_HasSeverity(p, eStatusEffect.in_space_elevator)` (client and server). Dedi `[TRIG-GRAV]` lines with `bridge_trigger_gravity_diag 1` (DEVELOPMENTONLY, `trigger_gravity.cpp:137-140`). Net bit `m_gravityLiftActive`.
- **Passive (PAS_NOVA):** the script part is visual only. Air control and soft landing should appear as **class-var differences of Horizon's setfile** (airAcceleration, airSpeed, landing slowdown keys) [I]. Method: `Agent_SetLegend` Horizon vs Pathfinder, then run the `bridge_classvar_get` census for each and diff. Also give `PAS_NOVA` in case code reads the passive [?].

## 4. Priority 2/3: short notes and feasibility

- **Revenant (S21 Reborn): feasible, good primitive.** Hold `+offhand1` (toss-prep charge, max 1.3 s) and release to launch. Speed = lerp(700, 1150, charge), divided by up to 1.5 when looking above −15° pitch. The aim pitch is raised by up to 35° (`mp_ability_revenant_shadow_pounce_free.nut:48-67,344-394`). `PlayerLaunch` is predicted and dedi-bridged. Wall climb: compare against the Revenant setfile (VWallClimb).
- **Valkyrie: feasible (passive).** `GivePassive(PAS_VALK)` → equipment jets. Hold `+jump` while airborne (IN_DODGE path, `offhand_activates_on_jump_hold_time`, `SDK:game/server/offhand_jump_toggle.cpp:1-50`). Fuel is `glideDuration` / `SetGlideMeter`. The flight model is setfile + VJetpackBridge. Skyward (ult): medium, since it is server-authoritative skydive.
- **Vantage: medium.** The natural path needs the Echo companion (send, then relaunch). Shortcut: server `player.BeginJetDrive(787, 1575, targetPos, targetEnt, <0,0,-69>, timeout)` (constants `mp_ability_companion_launch.nut:79-88,794-811`) plus `EnableJetDriveDoubleJump(<512,0,394>, 0.5, ...)`. Dedi tunables are replicated cvars (`jetdrive.cpp:30-56`).
- **Wraith Into the Void: feasible.** `speed_boost` 0.3 (msc ×1.6), fades over the last 30 % of 4 s, `move_slow` 0.2 during deploy (`mp_ability_phase_walk.nut:52,113-146`). It is predicted. **Portal / Ash Phase Breach: low value.** Server-only path replay with prediction disabled (`mp_weapon_phase_tunnel.nut:1522,1576,1642`). Breach travels at 1200 u/s over 0.3–1.8 s (`mp_weapon_phase_breach.nut:36-49,355`). Exit velocity = the recorded node velocity, and controls are locked. The client MOVE-TRACE is not physics truth here.
- **Ash passive dash: feasible.** Equip `PAS_ASH` and use `+dodge`/airborne jump. Values are setfile mod `ash_dash` [?].
- **Loba: low value.** Velocity is set to 0 on teleport, and restored only on failure (`loba_tactical_translocation.nut:1103-1114`). Carried in = discarded, out = 0, not predicted.
