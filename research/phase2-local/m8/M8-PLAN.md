本文件存档用户的 M8 长任务计划，要点逐条保留。基线：HSD-Unity main `3fba896`（M7-A 已合并）；研究仓库 main `af3c57c`。执行记录见仓库根目录 `EXECUTION-LOG.md`。

阶段编号：
- **M8-A**：第一阶段，Movement 基础完善；
- **M8-B**：第二阶段，高级身法深化与组合优化；
- **M8-C**：第三阶段，新机动能力扩展，以及之后的扩展评估。

## 用户计划要点

### 第一阶段（M8-A，优先）
1. **跳跃与技能输入冲突**：
   - 修复跳板和通用二段跳同帧触发时，二段跳被消耗却没有生效（M7-A 遗留）；
   - 理清 Valkyrie 喷气、通用二段跳、跳板专属二段跳之间的冲突；
   - 覆盖同帧、提前一帧、延后一帧、长按、快速连按；
   - 被覆盖、拒绝或取消时，不错误消耗、不重复触发、不异常叠速；
   - 做成可复用的输入仲裁规则，不针对每种组合打补丁。
2. **斜坡滑铲与地形运动**：
   - 下坡加速、上坡减速、不同坡度对滑铲速度的影响；
   - 平地和坡面之间、连续变坡时的速度连续性；
   - 高速落地接滑、跳上坡面、滑铲起跳；
   - 坡面边缘、坡度突变、短暂离地再接地；
   - 防止反复切换地面状态刷出无限加速，也防止正常操作突然丢失大量速度；
   - 数值以 HSD 手感为准。
3. **Zipline 特殊交互**：
   - 先核对 M6-A 已做的部分（乘绳、Super Jump、钩爪自动接绳），不重复开发；
   - 测空中抓绳、主动跳离、快速重新接绳、连续跳跃、快速交互；
   - 测钩爪接绳和脱绳后的动量继承、控制权恢复；
   - 测高速接绳、端点、异常角度、重复按键；
   - 测和 Lurch、滑铲、跑墙、二段跳的衔接；
   - 保留 Reference/Fun 两套规则，只修真正的缺陷。

### 第二阶段（M8-B）
4. **Bunny Hop**：
   - 先确认现有机制能否自然做出兔跳；
   - 测不同初速度、连续落地、跳跃间隔和输入时序；
   - 测滑铲跳、兔跳、落地接滑之间的连续转换；
   - 已经满足就只补测试和操作指引。
5. **Lurch、LS/RAS 与空中变向**：
   - 测连续 Lurch、Tap Strafe、对角输入、快速反向输入；
   - 研究并尝试复现 LS/RAS 的回旋、折返和蛇形变向，明确区分已验证、社区技巧和待验证；
   - 测墙跳、跑墙跳、钩爪释放、跳板发射之后的转向；
   - 用现有 Lurch 和空中变向机制自然产生，不为每个花式单独硬编码。
6. **Superglide 与墙面连招**：
   - 复核 SG 在不同墙高、速度、方向和时序下的表现；
   - 横向 SG、SG 接 TS、SG 落地接滑；
   - 跑墙 → 跳离 → 墙跳/空控，以及双墙之间的连续机动；
   - 抓边、攀爬、翻越、跑墙之间的切换；
   - 设计长链，例如钩爪 → 滑铲 → 跑墙 → 墙跳 → TS；
   - 高速下的碰撞、速度继承、镜头和输入响应专项检查。
7. **训练场与自动化验证**：
   - 复用 M6-C 设施，补必要的测试区域；
   - 重要技巧都要有真实按键演示、成功条件和失败对照；
   - 扩展 fuzz，检查卡死、穿模、状态残留和异常叠速；
   - 记录真实缺口、无法复现的技巧和需要真人判断的参数。

### 第三阶段（M8-C）
8. **Octane 跳板专属二段跳**：
   - 补齐 S21 跳板发射后的二段跳，和 HSD 通用二段跳分开管理（资格、消耗、重置、状态）；
   - 研究站立/下蹲触板、发射、二跳时机和空中方向控制；
   - 二跳后接 Lurch、TS、滑铲、墙面机动；
   - 测两种二段跳同时开启时的冲突（是否允许同时装备以后再定）；
   - Reference 尽量用本地 S21 实测，测不准的标为设计值。
9. **Horizon 升梯与空中控制**：
   - 核对已有 Gravity Lift 和 Spacewalk，只补缺口；
   - 进入、持续上升、梯内横移、顶部停留、侧向退出；
   - 退出后的动量、空控、落地；
   - Horizon 软着陆和普通落地的区别；
   - 升梯 → 空中转向 → 落地滑铲，以及升梯 → 墙面机动；
   - 只针对以前精度不足的项目补测。
10. **扩展评估**：
    - Revenant 蓄力扑跃、长攀爬和墙面衔接；
    - 可以单独研究 Vantage Echo、动态钩爪锚点；
    - 按独特性、复用价值、成本和测试结果，推荐下一批任务。

### 原则（用户原话要点）
- 目标是完整的 Movement 能力库，不是一个角色拥有全部技能。技能槽、角色分配和互斥以后再设计。
- 保留 Reference/Fun。Reference 原有回放必须一致；HSD 原创数值标为设计值。
- 不追求无依据的 Apex 精确参数，优先稳定性、自由度和手感。
- 不提前做正式美术、战斗系统或大规模无关重构。
- 每个阶段完成后自动测试、修复、提交并继续下一阶段，不必逐项等确认。可以并行，但要避免代码冲突。
- 延续 PR、自动化测试和 Windows 构建流程。只有验收通过的改动才合并。遇到无法解决的阻碍时记录原因，继续其他独立任务。
- 最终交付：
  - 中文操作指南；
  - 测试和回放结果；
  - 已完成/未完成清单和遗留问题；
  - 明确区分「数值通过」（自动化检查通过）和「真人手感未验收」（还没有人试玩）。
