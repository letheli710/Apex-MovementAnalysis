## 1. 方法

- R5 本地私服（Gibraltar、火力训练场、120 fps、`mantle_boost_enabled=1`），B1 的岩石墙 lane A，`--geometry h<H>`，`--mb-log` 逐帧记 S27 量，客户端 `[HSD-MD]` 逐帧记位置、蹲状态、镜头角（`cang − eang`，Source：+ = 向下）。
- 新计划表 `d72_<cr|st>_d<D>_e<E>`（`tools/hsd_trial.py`）：B1 的冲刺跳，起跳后 D 帧按下蹲并一直按住；E = 起跳提前的帧数（E12 / E24 / E36 让空中时间更长，拿到 0.3–0.5 s 的提前量和"接触前已经蹲到底"的情况）；`st` = 不蹲（站姿对照）。`--interleave` 让各档轮流跑，不让会话漂移和某一档对齐。
- 档位：h80 / h100 / h120 的 D = 0、4、8–16（每条命令一档）、20、24、28、32、36，每档 5 次；h120 另加 E12 / E24 各 5–6 档 × 5 次。h130 / h140 / h160 / h200 D = 0、4 … 36（每 4 条命令一档）× 5 次。h160x：E12 / E24 / E36 补测。
- **样本：610 次正式试次（蹲 553、站 57）+ 试测 13 次，9 个会话，0 次帧率超差（1 次 h100 的试次多跑一帧，丢掉）。** 原始日志不进公开仓库（见 §6）。
- 脚本（`research/phase2-local/d72/`）：`analyze_d72.py`（每次一行 → `out/runs.csv`、逐帧镜头 `out/cam.csv`）、`summarize_d72.py`（表格 → `out/summary.md`）、`unity_d72.py`（同一输入的 Unity 结果并排 → `out/unity_pre.csv`）、`curves_d72.py`（平均俯仰曲线 → `out/pitch_curves.csv`）、`pilot_probe.py`（试测用）。
- **Unity 改前**：同样的 R5 输入（`feel/camera_to_trial.py` 转成 606 个片段）喂给 HSD-Unity main（c97e804）的 Reference 身体，`CameraFeelBatch`。Unity 没有改动。
- 词：**提前量** = 翻越开始那一帧 − 按下蹲的那一帧（客户端时间）。**蹲到底** = 客户端蹲标志变 1（眼高从下蹲过程中的约 48.5 跳到 32）的时刻；空中下蹲从按下到蹲到底中位约 **0.43 s**（553 次，95 % 分位 0.45 s；更短的是先翻上台面、落到台面时蹲到底的），比在地上慢得多。时长分类：A < 0.60、S 0.60–0.69、M 0.69–0.79、L ≥ 0.79 s。

### 2.4 原生代码（r5apex_dx12）

- `TraversalMove` **0x140a45380** 每一帧重算翻越状态 `+0x2b34`：先按离台面还剩的高度选基础状态 3 / 4 / 5 / 6，然后**如果下蹲状态 `+0x2a70 == 2`（蹲到底）且状态不是 11 / 12，state += 4**（蹲姿 7–10）。状态一变就换动画序列（活动号 = state + 0x244，`FUN_1409e5cc0`），进度速率按状态读。`Traversal_PickAnim` 0x140a41af0 在翻越开始时把状态清 0。
- 所以"蹲姿翻越"不是开始时选好的一种，而是**翻越中途蹲到底的那一刻切成蹲姿动画**。空中下蹲约 0.43 s，在实测的大部分情况下，这一刻正好落在翻越中间，时长取决于切的那一刻、以及那一刻是哪个基础状态。
- h120 长短混着的推测：h120 的接触高度正好在基础状态 3 / 4 的分界附近（站姿 h120 的 SDK 日志里 3 和 4 两个状态都出现），亚 1 u 的高度差决定蹲到底时是在 3 还是 4 → 切成 7 还是 8 → 0.65 还是 0.81。h130 离分界远，所以稳定。**没验证**：要逐帧读 `+0x2b34`（脚本读不到，SDK 日志只有每秒一次），需要 Frida 一次。
- 反编译文本含游戏代码，只留在本地（`DecompileList.java`，Ghidra 持久工程 `r5apex_dx12`）。

## 3. 问题 (2)：蹲着爬墙

| 高度 | R5 蹲：上台面 / n | 怎么没上去 | Unity 改前 |
|---|---|---|---|
| h120 | 135 / 135 | — | 134 / 134 |
| h130 | 56 / 56 | — | 56 / 56 |
| h140 | 15 / 50 | D0–D8（提前量 0.43–0.49 s，翻越开始时正好蹲到底）15 / 15 上去；D12 以后（接触墙时还在下蹲）35 / 35 没上 | 48 / 48 |
| h160 | 0 / 66（含 E12 / E24 / E36 早起跳的 23 次） | 升到 351–368 落回 | 66 / 66 |
| h200 | 0 / 50 | 升到 352–369 落回 | 50 / 50 |

- 服务器事件（h160）：站姿 `BEGIN_WALLRUN` @ 起跳后 0.260 s → `MANTLE` @ 0.524 s。蹲：`BEGIN_WALLRUN` @ 0.269–0.287 s，**下一条命令（+0.008 s）就 `END_WALLRUN`**；D36（起跳后 0.31 s 才按蹲，已经在爬墙）在 0.310 s 结束，正好是按下的时刻。
- 原生：`WallRun_TryStart` **0x140a4e220** 只在**下蹲键（按键位 `0x4000004`）没按着**、并且（没蹲 `+0x2a70 == 0`，或者能站起来 `FUN_140b135d0`）时才开始爬墙 / 跑墙；`WallClimb_Move` 0x140a4d4e0 每条命令也读同一个按键位。
- **规则**：按着蹲 → 不能开始、也不能继续爬墙；只能在接触墙时直接翻越（要台面够得着）。蹲着能翻的最高点在 h140 和 h160 之间（h140 要翻越开始时已经蹲到底才够得着）。
- 116 次（h160 + h200 蹲的全部）0 次例外，这条是稳定的。
