# R6U 对照：Unity Reference 斜坡改成 R5 前后（R6 的 133 次 R5 试验）

生成：`r6u_compare.py`（下面"复现"）。R5 列是实测；其他列是 `harness/` 用同样的 R5 输入驱动 Unity Reference 游戏身体：

- **before**：R6U 之前的 Reference（#67 的世界：每个平面段一个实体），= `SLOPE-SLIDE.md` 里的 Unity 列。
- **U1 / U1+U2 / U1+U2+U4**：逐条打开（U-3 关）。
- **after**：R6U 的 Reference（U-1–U-5 全开，U-3 = Props）。

R6U 起 harness 默认按 R5 的铺法建世界：每块 1023 u 的砖一个实体（道具），所以每条接缝都是换地面实体；`--segments` 回到 #67 的一段一个实体。`--pre-r6u` + `--segments` 和 #67 的 Unity 结果逐项相同（tables.md 无差别）。U-4 在实测坡度（≥ 5°）上没有影响，所以 U1+U2 和 U1+U2+U4 两列相同。

复现：

```
dotnet build harness -c Release -o <out>                       # 读 ../../../../../HSD-Unity
<out>/SlopeHarness.exe <trials> <u_before> --pre-r6u --segments
<out>/SlopeHarness.exe <trials> <u_U1> --off U2,U3,U4          # 同理 U1+U2: --off U3,U4；U1+U2+U4: --off U3
<out>/SlopeHarness.exe <trials> <u_after>
py -3 slope_analysis.py <trials> --unity <u_x> --json <res_x.json>   # 每个 Unity 输出一次
py -3 r6u_compare.py before=<res_before.json> U1=<...> U1+U2=<...> U1+U2+U4=<...> after=<res_after.json>
```
