# SYNTHETIC fixtures — not Apex measurements

Everything in this folder was generated by `tools/hsdtel/synth.py` (model "SYNTH-1", seed 1):

```
python3 research/phase2-prep/tools/hsd_tel.py synth -o research/phase2-prep/fixtures/synthetic
```

SYNTH-1 is a deliberately simple movement model with made-up parameters. The parameters are listed in `synth.py` (`P = {...}`). Its only purpose is to give the parser, validators, event detection and fitters known answers to recover.

**No number in these files describes Apex Legends or R5Flowstate.** Every file starts with a `# SYNTHETIC` line.

The files reproduce the real line formats and log layout:

- `platform/logs/{client,server}/<GUID>/message.log` holds `[MOVE-TRACE]` lines. The format is the printf in `s21-r5sdk/src/game/{client,server}/move_sim_trace.cpp`, with the `[YYYY-MM-DD HH:MM:SS.mmm] Native(C|S): ` file prefix (`core/logdef.cpp`, `public/tier0/dbg.h`).
- `.../script.log` holds `[HSD-MD] ver=2` lines in the HSD.MoveDiag v0.2 format (`research/phase2-prep/TELEMETRY-SCHEMA.md`).
- `faulty/` is a copy of the client logs with one injected defect of each kind. The expected validator codes are `E_MALFORMED_MT`, `E_NONFINITE`, `W_TELEPORT`, `W_SEQ_GAP`, `E_MISSING_FIELD`, `W_API_MISSING`, `W_SCRIPT_ERROR`.
- `console_copy_client.txt` mimics the in-game console: ANSI colour codes and no file timestamp.

Scenario (runs are set by `hsd_md_run`):

| run | content |
|---|---|
| r1 | rest 0.3 s → forward 2.0 s → release 2.0 s (E1 shape) |
| r2 | run up, then 3 jumps with air strafe while turning 180°/s (E2 shape) |
| r3 | bunny hops with 0/2/5 extra ground frames, then a slide, then release (E4/E5 shape) |

`tests/test_determinism.py` regenerates these files and checks that the output is byte-identical.
