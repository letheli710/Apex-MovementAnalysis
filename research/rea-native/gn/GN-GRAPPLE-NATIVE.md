# GN：钩爪脱钩全部按原生改（D-50）

日期 2026-10-28。依据 N13（[../n13/N13-GRAPPLE-DETACH.md](../n13/N13-GRAPPLE-DETACH.md) §2、§3、§5）。用户决定："对于'勾爪'这一块，我们全部按原生的去做"，现版本归档、可切回。

HSD-Unity 分支 `gn/grapple-native`；本仓库分支 `gn/grapple-native`（基于 `n13/grapple-detach`）。

## 1. 结论

- Reference（和 Fun）的钩爪脱钩规则全部换成原生：G-1 接近距离、G-2 斜坡 400、G-3 绳子方向、G-4 径向低速、#7 低速时限、G-5 远离规则只在世界钩点。每条一个开关，`GrappleS21Params.SetGnDetach(false)` 一次切回旧版（输出和改前逐字节相同）。
- **G-5 确认了，但和 N13 推断的相反**：钩子的"父实体"是钩到的那个道具，不是世界。钩在世界几何上时远离规则开着，钩在道具上时关着。R5 对照场景里的岩石都是道具，所以那些片段从没见过远离脱钩和撞上上抬。
- **G-6 新问题**：钩在地面（世界）上时，客户端原生代码确实做了撞上上抬（Frida：vz → 299），但录下来的轨迹没有跳。按任务不加，记为待定。
- **h = 22**：绳子方向从原点上方 23 量（N13 没认出来的 +0x1de8）。
- A-1：脱钩 241 / 241 / 199 / 199 → **245 / 245 / 202 / 202**（R5 244 / 243 / 201 / 201），最高点 145 / 145 / 111 / 112 → **155.7 / 155.7 / 116.3 / 116.6**（R5 155.3 / 154.9 / 117.3 / 116.8）。比 N13 预计的 244 / 244 / 201 / 201 晚 1 条命令；同一个新场景用旧规则就已经是 244 / 244 / 202 / 202，所以这 1 条出在场景 / 拉力近似，不在规则。没有一个片段离 R5 更远（hold 1702 前后都差 2 条，方向相反）。
- 视线离开、rodeo：脱钩时刻和横滚不变；F-1 把 R5 的参照换成"只有客户端"的模型后，横滚峰值一致（视线离开 Unity 12.8° 对 12.75–13.0°，rodeo 11.2–11.5° 对 11.0–11.9°）。
- N6 天花板：拉动 → 脱钩 1.200 → **1.500–1.508 s**（R5 1.508–1.517 s）。

## 2. G-5：钩子的父实体（Frida 实测）[native + meas]

原生"远离 > 500"脱钩（`0x14066f600`）和"撞上时上抬"（`0x14066fb60` 接近分支）都只在**钩子实体 +0x148 的句柄为空**时才做。N13 推断"钩在世界上时有父实体"[inf]。这次用 Frida 直接读（[frida_hook_parent.js](frida_hook_parent.js)，只读；会话 `20261028_111333_GN_hook_parent`，Pathfinder，`--geometry m3 --kit --m10-log`，120 fps）：

| 钩在哪 | +0x148 | +0x1560 | 接近脱钩那一条命令客户端的 vz |
|---|---|---|---|
| M3 岩石（`m10_g_d400` ×3，含热身） | 实体 8122（就是脚本创建的岩石 prop） | 空 | 211.1 / 211.0 / 212.4（只有重力，没上抬） |
| 地面（`m10_g_g400_spr` ×2，世界几何） | **空** | 空 | **299.2 / 299.2**（上抬到 300 的上限） |
| rodeo、视线离开（岩石） | 实体 8122 | 空 | 视线规则脱钩，没有上抬 |

- **N13 的推断要改**：父实体不是"世界"，而是**钩到的那个独立实体**（prop、绳子等）。钩在世界几何上时 +0x148 是空的。
- 所以原生的规则是：**钩在世界上**时"远离 > 500"脱钩和撞上上抬都开着；**钩在 prop 上**（我们所有 R5 对照场景的岩石都是脚本创建的 prop）时两项都关。N13 那 6 次接近脱钩都在岩石上，所以没有上抬。
- 这几次都没有触发"远离 > 500"（最大远离速度 0），这一项只确认了开关条件，没有直接看到它脱钩。
- 帧率：Frida 挂着时 3 个试验掉到 113 fps（超出 ±3 %）。这里只用 Frida 读到的指针和 vz，不用这些试验的轨迹做对照。

**撞上上抬（G-6）在轨迹上看不到**：地面钩的那两次，录下来的客户端轨迹在脱钩那一帧 vz = 0、ground = 1，之后沿地面减速，没有跳起来（22003：x −13615.5 脱钩，离钩点 45.5 u）。Frida 看到的是客户端 pull step 里把 vz 抬到 299；最终画面上没有。可能是本地 S3 dedi 没有这一项、把客户端纠正回来了（和视线离开一样的混合版本），也可能是地面上这一条命令的移动把 vz 清掉了。**世界上的墙**（空中撞上）这次没有场景能测。

所以 G-6 按任务**不加**（`impactBoost` 开关做了，所有配置都关），记为待定，见 §6。

## 3. 绳子方向的 h（玩家 +0x1de8）[native + Frida]

N13 没认出来的 h：Frida 读到 **h = 22**（整个会话不变，Pathfinder 站立）。所以原生绳子方向
d = (P + (0, 0, `grapple_lift` 25)) − (原点 + (0, 0, 22 + 1)) = P − 原点 + (0, 0, 2)，
几乎就是从原点指向钩点。`look_split.py` 加了 `nat_h22`：视线规则第一次触发的帧和 h = 0 / 36 相同或相邻（look180 1.067–1.075 s，rodeo 0.473–0.500 s）。

## 4. Unity 的改动（每条一个开关，`GrappleS21Params`）

| # | 开关 | 原生 | 旧版 |
|---|---|---|---|
| G-1 | `nativeProxDistance` | 接近距离 min(\|P − 原点\|, \|P − 眼睛\|)，当前眼高；wind-up 里也是这条 | 线段 [原点, 原点 + 72]（wind-up ≤ 45） |
| G-2 | `detachRampMax` | 400 | 800 |
| G-3 | `nativeRopeDir`、`ropeLift` 25、`ropeBase` 23 | 视线、接近斜坡、远离速度按 d = P + 25 − (原点 + 23)；往下看时 d 和眼睛 → 钩点的水平部分都在水平前方后面 | 视线从原点 + 70，速度朝原点 + 36 |
| G-4 | `nativeLowSpeed` | v·d̂ ≤ 250 计时 | \|v\| < 250 |
| #7 | `nativeLowSpeedTimer` | 拉动中一律 1.5 s | 碰墙 / 天花板 1.2、地面高度 0.7、其余 1.5 |
| G-5 | `awayOnlyWorldHooks` | 远离 > 500 只在世界钩点（`IGrappleHookEntity`：道具、绳子算实体） | 一直生效 |
| G-6 | `impactBoost`（都关） | 世界钩点接近脱钩时 vz = min(vz + 300, 300) | 没有 |

- **#7 是这次另外找出来的**（任务第 7 条）：原生按"有没有地面实体"选时限（`0x14066f600`：有地面实体时 0.7，沿墙跑时 1.2，否则 1.5），Unity 原来按"碰到墙"选 1.2。R5 拉动时一直 ground = 0（M10 地面拉、这次的地面钩、N6 天花板都是），所以拉动中实际一律 1.5。
- **查过、没改的**：绳子过长（距离 > 最大长度 + `grapple_detachExtraAllowedLength` 256）：钩爪射程 850，拉动中碰不到 1100 以上，不做；远离脱钩时的 +200 上抬（`detachVerticalBoost`）：只跟着远离规则，测过的片段没触发，Unity 不做；视线规则"向上而且同向更陡"的豁免（`0x142373684`）：那个向量没认出来，测过的片段没触发，不做；近战目标、钩到玩家 / NPC 的分支：Unity 没有这些目标。
- 演示 `m10a_look_away`：锚点仰角约 50°，原生规则从绳子方向量，一直仰着头转 180° 绳子方向还在前方（d·视角 > 0），不脱钩。演示改成边转边把视角放平到 R5 look180 的仰角 10°。
- 对照工具：`FeelReplay` 读 `feel_rock`（S-1 / S-2）和 `world.boxes`；`FeelBatch` / `CameraFeelBatch` 加 `-preGn`；`CameraFeelBatch` 多写 `body.csv`。
