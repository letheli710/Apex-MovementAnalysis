## 2. +30 u/s 什么时候出现 [native]

本次补读了"表面法线"`+0x3630` 是谁写的：
- `WalkMove`（0x140a4a7c0）和 `AirMove`（0x140a48f90）每一帧先把它清零；
- 这一帧的移动撞到表面时，写入那个表面的法线（`WalkMove` 只在撞击把移动挡掉超过一个阈值时写）；
- `TraversalMove`（mantle）不清它，所以 mantle 开始前最后一帧如果撞到了墙面，法线一直留到 mantle 结束。
- `Jump`（0x140a3b550）：移动方向和法线点积 < 0（朝着表面）时，速度加 −法线 × **30**（常量在 `.rdata`）。

所以：
- 只有"接近时碰到墙面"的那几次（M8：3 / 12、3 / 15）mantle 跳多 30；
- 普通地面跳朝着刚撞到的墙，也会多 30（多出的部分大多被墙挡掉）。

## 3. 升梯另外两个跳过条件 [native] + SDK

升梯处理 `0x140a39420` 的跳过顺序：相位 → `+0x4838` → `0x140a393b0`。

**`+0x4838` = `m_armoredLeapPhase`**：
- SDK 的升梯和黑洞都在 armoredleap 阶段不为 0 时跳过，日志名 `TG_SKIP_ARMOREDLEAP`；这个字段由 `armored_leap.cpp` 写（Newcastle 战术技能"城墙"的跳跃）。
- 原生里读写 `+0x4838` 的函数大多在 0x140b15690–0x140b18650 一段（城墙跳代码），另外跳跃、移动入口也读它。

**`0x140a393b0` = SDK 注释里的 `ShouldIgnoreGravityAbilities`**：
- 玩家发射状态 `+0x1d3c` == 2，并且发射速度向量（`+0x2cbc`）的平方 > 300²（常量 300.0 和 2.0）时返回真。
- SDK 说本地 dedi 没有玩家发射系统（没有 `m_playerLaunch*` 属性），所以这一项走不到。

两项都和单人练习无关。

## 5. 用户决定（2026-10-25）

> 完成 J-1 后 PR。

Unity 实现：HSD-Unity#33（分支 `j1/jump-surface-push`）。
- 电机 `jumpSurfacePush`：Reference 30，Fun 继承，回放电机 0。
- 记下的墙：每次世界扫掠后写入，运动学命令（攀爬、翻越、悬挂）不改。
- 加到普通地面跳、翻越跳和 superglide 上；没有加到二段跳、蹬墙。
- **和 R5 的频率对齐**：Unity 的攀爬在撞墙的下一条命令才开始，R5 的探测在撞墙之前就开始。所以攀爬 / 翻越 / 悬挂如果在接触的第一条命令开始、上一条命令又按着 W 朝着这面墙，就清掉记下的墙。
- Unity 结果：跳得离墙近（30 u）的接近会先贴着墙往上滑，得到 +30（R5 的少数情况：402 / 329）；从 60–170 u 起跳、翻越在第一次接触时开始的，结果和 R5 的多数情况一样（199.5 / 299，斜向出口 60°）。
