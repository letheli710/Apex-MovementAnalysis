# N9：Horizon 升梯、Valkyrie 喷气、重力炮的原生代码

日期 2026-10-24。用户定的范围（2026-10-24）：Horizon 的 Q（重力升梯）、Valkyrie 喷气、地图重力炮的剩余细节。

来源：
- 原生：`r5apex_dx12.exe` 的 Ghidra 反编译（只在 `local/`，不提交）；常量直接从 exe 的 `.rdata` 读出。
- SDK：R5Flowstate SDK 的服务器端移植 `trigger_gravity.cpp`、`jetpack.cpp`、`trigger_cannon.cpp`（本地 dedi 跑的就是它们）。
- 实测：M4、M6-B、M8 的已有数据。

**这里只记录规则和差别，不改 Unity**；修改建议在 §5，由用户决定。

## 1. 结论

| 机制 | 原生和 SDK | 和 Unity |
|---|---|---|
| Horizon 升梯 | **找到了原生代码**，常量和 SDK 一模一样 | 力的模型一致；只差"相位中不受升梯影响" |
| Valkyrie 喷气 | 原生常量和 SDK 的 `ApplyJetpack` 一模一样 | 一致（Unity 本来就是照 SDK 写的，又实测校过） |
| 重力炮 | 原生只做"替换速度 + 共享 1 s 冷却" | Unity 没有重力炮 |

## 2. Horizon 升梯 [native]

**原生位置**：
- 移动触发区分发 `0x140a37390`，按触发区类型分派：1 跳板、4 升梯、8 黑洞、0x20 重力炮。
- 类型 4 的处理是 `0x140a39420`。
  - N2-P2 §7 当时没找到它。
  - N8-C 在查相位时看到了这个函数，但没认出是升梯。
- SDK 把类型 4 叫 `TT_GRAVITY_LIFT`、类型 8 叫 `TT_BLACKHOLE`，和这里对上了。

**每帧的规则**（原生和 SDK 相同）：
1. **跳过的情况**（按顺序）：
   - 在相位窗口里（+0x19e0 ≤ 现在 ≤ +0x19e4），直接返回；
   - 玩家 +0x4838 不为 0；
   - 另一个检查函数 `0x140a393b0` 返回真（SDK 说这一项在本地 dedi 上走不到）。
2. **再进的门槛**：上次弹出后不到 **2.0 s**，不受力（常量 2.0）。
3. **进入时**：记下进入时间，悬停计时清零。
4. **弹出速度**：弹出速度先算好存着，等弹出时用。
   - 公式是"前向 × s、向上 × s"，s = min(停留时间 / maxEjectTime, 1)。
5. **竖直**：高度比例 f = 高度 / 升梯高度。
   - f < **0.9** 时：vz = clamp(vz + upAccel·dt, **5**, upSpeed)；
   - f ≥ 0.9 时：vz 按曲线取值，从 **0.5** 降到 **−0.5**，也就是悬停。
6. **悬停计时**：vz < 5 时累加；超过 maxHoverTime 就弹出。
7. **水平**：
   - 有方向键输入：目标速度 = 输入方向 × max(当前水平速度, 空中速度)，按 airAccel 逼近；
   - 没有输入：朝中心拉，速度按距离取，从 20 u 处的 **0.5** × toCenterSpeed 到半径处的 1 × toCenterSpeed；
   - 两种情况都把速度限制在 max(当前水平速度, 目标速度) 以内。
8. **结果**：速度 = 竖直分量 + 水平分量，并清掉地面。

**弹出方向**（SDK）：
- 默认用水平视线方向；
- 离中心超过 40 u 时，改用"从中心向外"的方向；
- 两者都没有时，用移动方向。

**从 exe 读出的常量**：2.0、0.9、5.0、0.5 / −0.5、20.0、0.5。和 SDK 的写法逐个相同。

**和 Unity 对照**（`Abilities/GravityLift`）：

| 规则 | Unity | 结论 |
|---|---|---|
| 竖直 clamp、0.9、悬停曲线、悬停 0.5 s 弹出 | 有（M4 实测 + 脚本） | 一致 |
| 弹出 400 / 450 × min(停留 / 0.5, 1)，方向规则 | 有（M8 拟合出约 2 帧的偏移） | 一致 |
| 有输入 / 无输入的水平规则 | 有 | 一致 |
| 弹出后 2.0 s 不能再进 | 有，标为 [src] 未测 | 现在有原生依据：[native] |
| **相位中不受升梯影响** | **没有** | 差别（L-1） |

## 3. Valkyrie 喷气 [native]

- 原生 `Jetpack_Thrust` 0x140aff150、`Jetpack_Vertical` 0x140afee50 用到的常量，都和 SDK `jetpack.cpp` 的 S21 `ApplyJetpack` 相同：
  - 紧度按半衰期算：−ln 2 / 紧度；
  - 超过极限时的紧度 0.4（预先算好的 −ln 2 / 0.4 = −1.7329 也在 exe 里）；
  - 超过极限的判断余量 0.01；
  - 切换开关的 0.25 s 窗口；
  - 输入阈值 1e-6 / 1e-4。
- 另一个常量 0.866（cos 30°）只用来设动画方向的标志，不影响移动。
- Unity 的 `JetpackParams.Measured()` 就是这个模型，又经过 M6-B 实测校准，所以**一致**。
- SDK 里有、Unity 没有的几项，S21 的设置值都让它们不起作用：
  - `jetpackVerticalVelocityScaleOnActivation` = 1（census）；
  - 加力（afterburner）、按俯仰飞（pitch movement）、副手武器推力都没开。

## 4. 重力炮 [native]

`GravityCannon_Launch` 0x140a3af30（由触发区分发里的类型 0x20 调用）：
1. **启用时间**：触发器的启用时间（+0xa18）必须 > 0，并且已经过了。
2. **冷却**：玩家 +0x350 必须已经过期。这个字段和跳板共用。
3. **发射**：速度**直接替换**为触发器方向（+0xa94）× 触发器速度（+0xa08），然后清掉地面。
4. **发射之后**：
   - 冷却设为现在 + **1.0 s**（和跳板一样）；
   - 给镜头加一个 punch；
   - 把最高点高度（vz² / 2g + z）记到玩家 +0x2078。
5. **没有相位检查**：分发函数和发射函数都没有。所以相位中的身体照样会被重力炮发射，这一点和跳板不同。
6. **空中控制锁不是 S21 原版**：飞行中去掉沿发射方向的输入、禁止 lurch，这是 SDK 自己加的 `bridge_trigger_cannon_lock`。说明里写的是"按受限空中控制发射器的样子"。原生代码里没有。

本地地图里，Storm Point（`mp_rr_tropic_island_mu2`）有重力炮，可以实测。
