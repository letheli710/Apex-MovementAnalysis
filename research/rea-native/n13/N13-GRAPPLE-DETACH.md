# N13：Unity 钩爪为什么比 R5 早脱钩

日期 2026-10-28。来源：F7（[../../feel/FEEL.md](../../feel/FEEL.md) §10）的"视线离开 Unity 约 1.05 s 脱钩、R5 到 1.5 s 还挂着"，和 A-1 剩下的部分（§9.1：往墙上拉最高点低 5–10 u，接近钩点早约 2 条命令，撞墙那一下 R5 竖直速度多约 12 u/s）。

**只做研究：没有改 HSD-Unity，没有改 DECISIONS.md。决定和日志由主控记。**

## 1. 结论

## 2. 原生脱钩规则：每条到底量什么 [native]

每条命令的调用链（S21 客户端 r5apex_dx12）：钩爪更新 `0x140670ff0` → 拉动这一步 `0x14066fb60`（返回 1 = 这条命令脱钩，**这条命令不再加拉力**）→ 脱钩规则 `0x14066f600`。结构体字段名来自 SDK 的 `GrappleData`（`research-src/s21-r5sdk/src/game/shared/r1/grapple.h`）：钩点数组在 +0x14（每个 12 字节）、点数 +0x44、`m_grapplePulling` +0x49、`m_grappleSwinging` +0x4a、`m_grappleMeleeTarget` +0x64、`m_grappleHasGoodVelocity` +0x6c、`m_grappleLastGoodVelocityTime` +0x70。

两个共用的量：
- **钩点 P** = 钩点数组里下标 min(点数 − 1, 2) 的点，也就是绳子末端；钩在会动的东西上时每条命令更新成那个东西的位置。实测（M10-GRC 的 hook）：地面钩点 z 正好是地面 294.920；墙上钩点就是岩石表面。
- **绳子方向 d**（`0x140672580` → `0x140674a90`）= (绳子第一个点 + (0, 0, `grapple_lift`)) − (原点 + (0, 0, h + 1))。`grapple_lift` 是 ConVar，注册默认值 "25"（字符串在 `0x14167887c`）；h 是玩家 +0x1de8 的一个浮点，**没认出来**。钩到玩家 / NPC 时改成对方的眼睛位置。

## 3. 逐条对照：同样的输入，哪条命令触发

时间都从按 Q（钩爪激活）算，120 Hz，一条命令 0.0083 s。

### 3.1 视线离开 ×4、rodeo ×8（N6 Frida 第二轮、N12 补测）

把每条规则放在 **R5 自己的逐帧状态**上跑（眼睛、原点、视角、M10-GRC 记下的钩点），看第一次满足的帧（[look_split.py](look_split.py)）：

| rodeo 20315–20317 | 0.32 | 0.458–0.467 | 0.458–0.462 | 0.483–0.488 / 0.471–0.475 / 0.462–0.467 | 0.542–0.546 | 0.30–1.21 / 0.50–1.21 |

- 客户端标志晚 0.025–0.08 s：这个标志跟着 dedi 的快照（20 Hz）走，所以是 0.05 s 一档，和 N6 的"越过 90° 后 0.025–0.084 s"是同一件事。
- **dedi 的拉动在视线离开里正好持续 1.500 s**（0.701 → 2.201、0.651 → 2.251）：dedi 没有视线规则，是被它自己的 1.5 s 低速超时放掉的 [hyb，推断]。客户端在这段时间里每 0.05–0.1 s 被重新挂上；20311、20312 里从 1.24 s 起干脆一直挂着到 2.1 s。这就是 F7 看到的"R5 到 1.5 s 还挂着"。
- Unity Reference 自己的运行（F7 镜头批）：峰值 1.05–1.09 s，对应脱钩约 1.03–1.06 s，比原生在 R5 状态上的 1.067–1.075 早 0–4 条命令。这一点差在 Unity 身体自己的轨迹上，不在规则上（镜头批不输出钩爪事件，所以 Unity 这一列只能从横滚曲线推，精度约 ±0.02 s）。

## 4. 撞墙那一下的 +12 u/s

### 4.1 是斜面，不是上抬 [meas]

d400 和 M4 hold 撞墙那条命令完全一样：vx 575 → **6.5**，vz 185.5 → **197.7**（只有重力时应该是 179.3）。按"速度贴着平面裁掉"v′ = v − (v·n)n、法线 n = (−cos a, 0, sin a)：
- 只用剩下的 vx 6.5 解出 sin a = **0.0324（1.86°，面朝上偏）**；
- 再用同一个 a 算 vz：预测 197.7 / 196.6，实测 **197.7 / 196.6**（两次都对上到 0.1）。

M4 hold：+12.1 / +12.2；near（vx 只有约 430）：+7.8 / +7.8，也符合"vz 增量 ≈ vx · sin a"。Unity 的方块墙是竖直的，所以撞墙后 vz 只减不加（Unity 168.8 → 162.6）。

### 4.2 `grapple_impactVerticalBoost` [native + meas]

- 值：`grapple_impactVerticalBoost` 300、`grapple_impactVerticalMaxSpeed` 300（Pathfinder，N4A 类变量实测 `20261023_203953_N4A_classvars_pathfinder`）。
- 代码（`0x14066fb60`，接近脱钩分支 `0x14066fe4c`）：脱钩那一条，如果正在拉、钩子实体的父实体句柄（钩子 +0x148）为空、vz < 300，则 vz = min(vz + 300, 300)。
- 实测：6 次接近脱钩的那条命令 dvz 都是 −6.25（d400 ×2、M4 ×4；vz 在 177–211，要是触发应该跳到 300）。
- **GN 更正（2026-10-28，Frida 实测，见 [../gn/GN-GRAPPLE-NATIVE.md](../gn/GN-GRAPPLE-NATIVE.md) §2）**：+0x148 是钩到的那个**道具**（M3 岩石 = prop 8122）；钩在地面（世界几何）上时为空，接近脱钩时客户端 vz 被抬到 299。下面这条推断只对道具成立。
- 推断 [inf]：钩在世界（岩石、地面）上时钩子有父实体，所以这一项不触发。脱钩规则里"远离 > 500"和它的 +200 上抬用的是**同一个**父实体判断，这也解释了为什么从没见过 AWAY 脱钩和 +200（P-09）。钩到玩家 / 会动的东西时可能不同，没测。

## 6. 没做到 / 没查的

- **h（玩家 +0x1de8）没认出来**：绳子方向的起点高度。换成 0 / 36 / 69 时视线规则只差 0–3 条命令，不影响结论；会影响 G-4 的径向速度（很小）。
- **视角向量 `0x142373600`、`0x142373684` 是什么**：只从用法推断（前者是水平前方），后者那条"向上且同向"的豁免在测过的片段里都没触发。
- **钩子父实体**（G-5、§4.2）：只有间接证据。确认要用 Frida 只读钩子实体 +0x148，这次没跑游戏。
- **Unity Reference 在视线离开 / rodeo 片段上的脱钩命令**：镜头批（`CameraFeelBatch`）只输出镜头，不输出钩爪事件；`FeelBatch` 不带 F7 的记录钩点。这一列用的是 F7 的横滚峰值时间推出来的（±0.02 s）。规则本身的对照（§3.1）是在 R5 的状态上做的。
- **G-2、G-4 没有片段能直接验证**（需要 267–533 u/s 的慢速贴近、绕钩点横飞的新场景）。
