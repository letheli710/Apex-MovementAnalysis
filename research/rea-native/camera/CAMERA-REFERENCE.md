## 0. 约定和单位

| 项 | 约定 |
|---|---|
| 长度 | Source 单位 u（1 u = 0.0254 m） |
| 角度 | 度。Source：pitch + = 向下，roll + = **向右倾**（右边低）；Unity `CameraPose.roll` + = 向左倾，所以 **Unity roll = −Source roll** |
| 偏航 | Source 向右转 = yaw 变小；Unity yaw = −Source yaw |
| 时间 | 秒；模拟每秒 120 条命令（dt = 1/120），镜头按命令更新，渲染帧在两条命令之间线性插值 |
| FOV | Unity `Camera.fieldOfView` 是**竖直** FOV；Apex 的 FOV 是 **4:3 画面的水平 FOV**（实测 89 → 97.9 正好 ×1.1）。换算见 §3.6 |
| 准星 | 两版都只动镜头，不动准星：physics aim = 鼠标原值（C3：26 次落地瞄准角变化 0.0；N6：所有镜头效果 `eang` 不变） |

## 3. 原版：每个通道怎么动（公式）

### 3.1 眼高（CAM-10）[native + meas + inf]

- 下蹲比例 d ∈ [0, 1]：
  - 下蹲 / 滑铲 / 蹲姿碰撞体时目标为 1，否则为 0；
  - 线性移动，每秒 1/0.4，滑铲中每秒 1/0.2。
- 眼高 = 64 + (32 − 64) × smoothstep(d)，smoothstep(x) = x²(3 − 2x)。

C3 滑铲样本：0.052 s 59.3、0.103 s 49.3、0.154 s 39.3、0.205 s 32.2，smoothstep 在 ±1.5 u 以内吻合。曲线形状（原生 0x1409d9750）没读，所以是 [inf]。

### 3.2 punch 弹簧和落地 kick（CAM-01 / CAM-02）[native + meas]

**弹簧**：θ'' = −k·θ − c·θ'，k = 65，c = 9，每个轴一个（俯仰、偏航、横滚），一共两组。

| 量 | 公式 | 值 |
|---|---|---|
| 固有频率 ω₀ | √k | 8.062 rad/s（1.28 Hz） |
| 阻尼比 ζ | c / (2√k) | 0.558 |
| 衰减率 α | c / 2 | 4.5 /s |
| 阻尼频率 ω_d | √(k − α²) | 6.690 rad/s |
| 冲量响应 | θ(t) = v₀ / ω_d · e^(−αt) · sin(ω_d t) | — |
| 峰值时间 | atan(ω_d / α) / ω_d | 0.146 s |
| 峰值 | 0.0642 × v₀ | — |
| 过零 | π / ω_d | 0.470 s |
| 反向峰 | 峰值 × −e^(−απ/ω_d)，在 0.616 s | −12 % |

Unity 按精确解推进（`PunchAxis.Step`），所以和帧率无关。

**落地 kick**（`Land_ViewKick` 0x140a35750），v = 落地前一条命令的下落速度：

- v_min = √(2g × 12 × 10) = 424.3 u/s，v_max = √(2g × 12 × 70) = 1122.5 u/s（g = 750；setfile `viewkickFallDistMin` 10、`Max` 70 英尺）。
- 强度 s：
  - v < v_min：s = v / v_min；
  - v_min ≤ v ≤ v_max：s = 1 + 11 × (v − v_min) / (v_max − v_min)；
  - v > v_max：s = 12（`viewkickFallDistMaxScale`）。
- 三个随机数 r ∈ [−0.5, 0.5]（种子是命令号；Unity 用命令号的确定性哈希）。
- 第一组弹簧：俯仰角速度 += s × (2 + 0.75·r₁) × 20，横滚角速度 += s × r₃ × 20。
- 第二组弹簧：同样的量 × 0.2。两组相加，所以俯仰峰值 ≈ 0.0771 × 俯仰冲量。
- 在水里落地：s × 0.2（玩家 +0x1c7，CAM-02b）。**Unity 没有水，没做。**

### 3.3 滑铲倾斜（CAM-05b，`SlideTilt_Update` 0x140afc040）[native + meas]

- 二维状态向量 S。目标 T：
  - 不在滑铲时为 0；
  - 在滑铲时 = 水平速度方向 × clamp((|v_h| − 125) / (400 − 125))。
- 每条命令 S 向 T 移动，最多 5·dt（|T| > |S| 时）或 2.5·dt（|T| ≤ |S| 时）。
- Source 横滚 = −15 × (S · r̂)，r̂ = (sin yaw, −cos yaw) 是视角的右方向。
- 速度在视角左边（视角向右转开）→ 横滚为正（向右倾）。C3 的 6.36° 就是这个符号。

### 3.4 冲刺转向倾斜（CAM-07）[native + meas]

- 归一化倾斜 n，目标 = 冲刺中 ? clamp(−yaw 速率 / 120, −1, 1) : 0（`sprinttilt_turnrange` 120 °/s）。
- n 的速度朝目标方向加速，加速度 35 /s²（`sprinttilt_accel`），速度上限 2 /s（`sprinttilt_maxvel`）。到达目标时停住。
- Source 横滚 = 2° × n（`sprinttiltMaxRoll`）。向右转，向右倾。
- 原版通过 PoseParameter 交给动画执行，镜头上的结果和这个公式一致（N6）。

### 3.5 钩爪横滚（CAM-11，`Grapple_CameraRoll`）[native + meas]

钩住（收绳准备和拉动）期间，d = 钩点 − 眼睛，f / r / u = 视线的前 / 右 / 上方向：

- 距离系数 = clamp(|d| / 150)；
- 视角系数 = clamp(θ / 65°)，θ = d 和 f 的夹角；
- d 在垂直于 f 的平面上的方向 p，φ = p 和 u 的夹角（用 p × u 和 f 的方向定符号）；
- k = clamp((|φ| − 90°) / 90°)；
- 项 = 距离系数 × 视角系数 × (1 − k) × 1（`grapple_rollStrength`）× clamp(φ, ±20°)（`grapple_rollMax`）；
- **Source 横滚 = −项**（N6 实测：取反后 rms 3.2–3.4°，不取反约 21°），再以 6.667 /s 指数平滑。

### 3.6 滑铲 FOV（CAM-09）[native + meas]

- 比例 m 线性地朝目标走，目标是滑铲中 1.1、否则 1.0；进出各 0.25 s（每秒 0.4）。
- 竖直 → 4:3 水平 → 乘 m → 回到竖直：
  - h = 2·atan(tan(v/2) × 4/3)；
  - v′ = 2·atan(tan(m·h/2) × 3/4)。

### 3.7 墙跑项（CAM-05）[native + inf]

- 目标：墙跑中 ±10°，向离开墙的方向倾。
- 以 6 /s 指数逼近（`wallrun_maxViewTilt` 10、`wallrun_viewTiltSpeed` 6）。
- S21 墙跑是关闭的，没有实测。"6" 是速率还是别的意思没读清楚，所以是 [inf]。

### 3.8 view drift（CAM-20）和 cockpit sway（CAM-18）[meas + inf]

- **drift**：
  - 俯仰 = 0.195° × sin(2πt / 5.2)，偏航 = 0.084° × sin(2πt / 3.2)；
  - 只在站着不动时（地面上、水平速度 < 10），权重以每秒 2 淡入淡出；
  - 原版有 40 个 drift 参数，我们只测了站着不动这一种情况，所以只用了拟合的两条正弦。
- **sway**：
  - 俯仰 = −0.155° + 0.335° × sin(2πt / 0.27)，也就是 −0.49 … +0.18°；
  - 只在地面冲刺、速度 > 200 时，权重以每秒 4 淡入淡出；
  - 原版的 sway 跟着步伐和转向走（20 个 `cockpitSway*` 参数）。这里只是冲刺直跑实测的近似，所以是 [inf]。

### 3.9 合成

- Source 横滚 = 滑铲 + 冲刺 + 钩爪 + 墙跑 + punch 横滚，限制在 ±40°。
- 乘横滚强度，然后 Unity roll = −Source 横滚。
- 俯仰 kick = (punch 俯仰 + drift + sway) × 高度强度。
- 偏航 kick = drift 偏航 × 高度强度。
- FOV = 竖直(基础 FOV, 1 + (m − 1) × FOV 强度)。
- 镜头位置 = 插值后的身体位置 + 眼高。没有任何位置 kick。

## 4. M5.5：每个通道怎么动（保留版）

**平滑器**（`CriticalSmoother`）是临界阻尼的二阶低通，两级一阶串联，速率 ω：

- 阶跃响应 90 % 用时 = 3.8897 / ω，所以 ω = 3.8897 / 设定的 90 % 时间；
- kick 只推第一级，输出是 K·ω·t·e^(−ωt)，在 t = 1/ω 时到峰值 K/e，不回弹。`KickPeak(p)` 让峰值正好是 p；
- 所有响应时间乘设置里的 "Response time ×"。

| 通道 | 目标 / kick | 值 [design] | 时间 |
|---|---|---|---|
| 眼高 | 站 60、蹲 38、滑铲 32、攀爬 56、悬挂 54 | — | 下降 0.10 s、上升 0.24 s（90 %） |
| 横滚 | 墙跑 ±10、滑铲 3、侧移 1.5 × min(1, v/300) | — | 进 0.16 s、出 0.30 s |
| 横滚 kick | 墙跳 2.5（离开墙） | — | 峰 0.08 s |
| lift（u） | 起跳 1.0、滑铲跳 2.5、墙跳 1.5、弹射 2.0、攀爬上跳 1.5、superglide 1.5、mantle jump 1.5、滑索跳 1.5 / 超级跳 3.0、悬挂跳 1.5、空中跳 1.5、喷气 1.0、重力 ±1.5 | — | 峰 0.07 s |
| dip（u） | 落地 4·k（硬 8）、攀爬抓墙 1.2、mantle 落地 1.5、上滑索 2.0、抓边 1.5、Phase Breach 出口 1.5 | k = clamp((\|vz\| − 150)/622) | 峰 0.06 s |
| pitch（°，+ 向下） | 落地 0.8·k（硬 2.0）、起跳 −0.4、mantle 1.2、取消 mantle −0.8 | — | 峰 0.06 s |
| FOV 目标（°） | 速度 8 × clamp((v − 200)/500)、滑铲 3 × clamp((v − 125)/335)、钩爪拉 4、兴奋剂 3、喷气 2、飞行 3、升降 2、Breach 6、墙跑 2，总和上限 22 | — | 0.35 s |
| FOV kick（°） | 滑铲开始 4（续滑 2）、滑铲跳 2、弹射 7、墙跳 2、墙跑 1.5、钩爪 2、superglide 5、上滑索 1、超级跳 3、出滑索 2、Breach 3、空中跳 1.5 | — | 峰 0.09 s |
| 惯性滞后 | 眼睛位置 += (平滑速度 − 速度) × 0.006，最多 1.5 u | — | 速度 0.12 s、滞后 0.06 s |
| 速度线 | 0 → 1，三维速度 330 → 650 | — | 0.25 s |

关闭（"Off preset"）时是 M5 的老镜头：眼高 60 / 38 以每秒 12 指数逼近，墙跑 ±10° 以每秒 8 逼近，FOV 固定。这个在两版里都一样。

## 6. 以后调整或新建时

- **改原版的值**：都在 `NativeCameraParams`（每个字段注释写了出处）。改了以后，`NativeCameraTests` 里钉住实测的断言会失败。这是故意的：要么有新的实测，要么在这里写明为什么偏离原版。
- **给新动作设计镜头**：按 HSD-Unity 的 `fps-camera-design` 技能走（简报 → 通道 → 曲线 → 打断表 → 实现 → 验证）。原版数值是参照物：
  - 落地类反馈先看 §2.1 的 s 曲线和弹簧形状；
  - 倾斜类先看 §3.3 / §3.4 的"按相对方向 / 转向速率"做法。
- **两版对比着调**：游戏菜单 "Camera model" 随时切换。诊断 HUD（F3）的第二行分别显示两版的通道。
- **规则 3 的例外**：原版的回弹一次、drift、sway 违反 `fps-camera-design` 的"不回弹、不持续摆动"。这是用户要求的例外，上限钉在 `NativeCameraTests.ContinuousTermsStayInsideTheirMeasuredBounds`。
