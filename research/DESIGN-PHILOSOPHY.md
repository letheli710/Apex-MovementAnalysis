# R5 手感的设计哲学和技术理念（设计规范）

HSD 是研究项目，最后要做自己的枪和镜头。这份文档把过去全部测量整理成做新东西时照着用的规范。用户的验收标准："哪怕我们有些新加的东西，也得让它的手感和设计方法符合 R5。"

- **状态**：活文档，2026-11-02 第一版。全枪械实测（会话 `r5`）还在跑，结果补进第 11 节列的位置。
- **读法**：只想做东西，读 §1、§5–§7 和 §9。想知道为什么，读 §3–§4。用之前看一眼 §10。
- **全枪字段**：[design-philosophy/WEAPON-FIELDS.md](design-philosophy/WEAPON-FIELDS.md)（29 把枪，脚本生成）。

## 1. 一页总结

**解读，不是 Respawn 的说法。** 我们手里只有数据和代码，没有设计文档。下面每条都是从数据读出来的规律，证据和反例在 §4。

| # | 解读 | 一句话证据 |
|---|---|---|
| P1 | 瞄准是真值，画面诚实地显示它 | 所有镜头效果都不改瞄准角；R-301 开镜准星和子弹完全重合 |
| P2 | 镜头只转不移；持续状态克制，离散事件响亮 | 跑多快 FOV 都不变，但 900 u 落地俯仰 30–44° |
| P3 | 动量是玩家的资产，只有明确规则才能收走 | 空气摩擦 0；连跳不吃摩擦；每条削减都写得出条件 |
| P4 | 技巧窗口按时间算，地板低、天花板高 | lurch、翻越、滑铲退还都是时间窗；第一发没有后坐 |
| P5 | 枪的重量是一条贯穿字段的轴 | 开镜时间、切枪、开镜移速一起变（相关 0.84、−0.72） |
| P6 | 动起来可以打，但价格写清楚 | 扩散按姿态查表，冲刺、空中贵；霰弹免费 |
| P7 | 后坐可以学：固定表 + 小随机 + 总能回家 | 图案逐发固定，随机小，弹簧最后归零 |
| P8 | 一套物理反复用，没有优先级 | 所有 kick 进同两组弹簧，相加，没有上限 |
| P9 | 技能：威力换预告，夺控很少而且很短 | 炮击 2 s 预告；黑洞夺键只有 0.8 s |

做新东西最常用的五条技术规矩（§5）：

1. **时间底座线性，曲线加在读取方**。`zf` 线性，FOV 读它时才 smoothstep。
2. **事件 = 往弹簧加冲量**。不写专门的动画，不写优先级。
3. **瞄准角、画面角、子弹角分开存**。画面只读，绝不写回瞄准。
4. **行为写成字段，一把枪一行数据**。配件和模式都是字段覆盖。
5. **回落 = 等一段 + 线性走完**。这个形状到处都是。

## 3. 为什么只拟合单项数值会漏规律

这些是这个项目自己犯过的错。设计新东西前先记住，否则会把假规律当成 R5。

| 例子 | 当时怎么得的 | 真相 | 教训 |
|---|---|---|---|
| **后坐不动镜头**（D-86） | 脚本读 `EyeAngles`、`CameraAngles` 开枪不变（IP2） | 画面跟 `m_vecPunchWeapon` 走，瞄准角本来就不含它 [实测，RV §1]。用户试玩说"像 CS:GO"，用户对 | **读到的接口不等于屏幕**。要读最终输出 |
| **开镜是线性的** | 量 `zf`，一条直线（LOG `leader-ads-curve`） | `zf` 线性，FOV smoothstep，枪余弦 + 动画 [实测，ADS] | 先分清**进度**和**读进度的东西** |
| **回落是一个常数** | 猜 0.2 s 后 T = 0.12 s | 弹簧，腰射和开镜差 3 倍；R-301 腰射 T 0.46、开镜 0.14 [实测，RV §2] | 常数拟合不出来时，说明结构错了 |
| **"幅度 = 表"** | IP2 只看到命中点跟表走 | 幅度 = kick × (hard + soft × 20 / d)，开镜 R-301 约 1.2 倍，腰射约 2 倍 [实测，RV §1.2] | 同一现象在不同模式下比，再下结论 |
| **斜坡滑铲 147 + 342·sinθ**（M8） | 拟合 29–41° | 750·sinθ·cosθ，5° 时旧拟合差近 3 倍 [实测 + 反编译，SL] | 拟合只在测过的范围成立 |
| **跑步晃动 0.335°、站立眼高 64** | N6、C3 带转向、冲刺中量的 | 直跑 0.25°；站 70、冲刺才 64 [实测，DIFF K-3、K-4] | 分开状态再量 |
| **滑铲落地 kick 大 1.5 倍** | 镜头日志撞墙的片段 | 没差 [实测，DEC D-71] | 对不上时先查测量 |

**规矩**：看到一个新现象，按这个顺序问：

1. 底下有没有一个线性进度？
2. 谁在读它，读的时候加了什么曲线？
3. 它是在往某个共用的弹簧或数值上加东西吗？
4. 腰射 / 开镜、站 / 跑 / 空中是不是查不同的表？

问完才谈拟合。

## 4. 哲学

每条都是**解读**。支持它的是测量，测量本身不等于设计意图。

### P1 瞄准是真值，画面诚实地显示它

**解读**：玩家要能信任"我瞄的地方"。镜头可以跳，但瞄准角不跟着跳；画面动的时候，要告诉玩家子弹实际去哪。

| 测量 | 标注 | 出处 |
|---|---|---|
| 落地 26 次，瞄准角变化 0.0；所有镜头效果 `eang` 不变 | [实测] | CR §0 |
| 起跳、翻越只动 punch 和翻越阶段，眼睛角度全程 0 | [实测] | CAM2 §2.2 |
| 子弹 = 瞄准 + 完整 punch，取这一发 kick 之前；第一发落在瞄准点（4 次） | [实测] | RV §1.3 |
| 准星 = 瞄准 + (1 − fraction) × punch，腰射残差 0.000° | [实测] | RV §1.1 |
| 29 把枪里 16 把开镜 fraction 为 0，瞄具和子弹一体 | [数据] | FIELDS §2 |
| 每发 punch 回落后回到 0，不累积进瞄准；`viewkick_perm_*` 字段基本全是 0（只有 Mozambique 的 random 不是） | [实测] / [数据] | RV §2.2、FIELDS 脚本 |
| 〔11-13 加〕鼠标和 punch 反向时，输入先一比一减 punch，减到 0 才进瞄准角，不越过 0；同向的输入全部进瞄准角。子弹和画面照样跟着鼠标走，只是账记在 punch 上 | [实测] | [E-MOUSE](combat/gun-measure/E-MOUSE.md) §1 |
| 〔11-13 加〕**子弹 = 瞄准 + punch1 + punch2 + 开镜 drift**：落地后马上开枪，移动 punch 整组进子弹（400 u 落地 0.1 s 后低 16–17°），差 ≤ 0.28°；Wingman 第 3、4 发偏高就是开镜 drift。也就是说开镜（fraction 0）时子弹永远打在屏幕中心 | [实测]（客户端和服务端 `attackDir` 一致） | [F-GAPS](combat/gun-measure/F-GAPS.md) §1、§5 |

**反例**：
- **开镜 fraction 大的枪，准星和子弹不一致**：Kraber 0.75、Charge Rifle 0.6、EVA-8 0.35、Bocek 0.35、Wingman 0.3 [数据，FIELDS §2]。Wingman 开镜子弹比准星高 30 % punch [实测，RV]。fraction ≥ 0.2 的 7 把全是没有图案的单发枪，它们下一枪之前 punch 已经回落了不少，所以这个差距影响小。这个解释是 [推断]。
- **腰射不诚实**：29 把里 22 把腰射 fraction 比开镜大。腰射靠扩散圆告诉你，不靠准星。
- ~~**鼠标下压可能会抵消 punch**（反编译：抵消部分不进瞄准角），还没测（§10.2）。~~ 〔11-13 [实测]，[E-MOUSE](combat/gun-measure/E-MOUSE.md)〕成立：R-301 连射时下压 3.3°/s，瞄准角在射击中只动 0–0.06°（输入 4.3–8.1°），punch 被压小；停火后下压 1.98°，瞄准角只动 0.09–0.44°。这**不算反例**：子弹 = 瞄准 + 完整 punch，所以鼠标对子弹仍是一比一；画面在腰射时随鼠标走 (1 − fraction)，R-301 是 0.95。变的只是"停火后回到哪里"：压枪压掉的 punch 不会再弹回来，弹簧也不会把画面拉到比起点更低。

**对设计的要求**：画面效果一律不写瞄准。如果画面中心偏离子弹，要决定谁承担差距（fraction），并且写明。

### P2 镜头只转不移；持续状态克制，离散事件响亮

**解读**：画面位置来自身体，所以位移始终可信。持续状态几乎不动镜头，让玩家能长时间看清楚；一次性事件可以很大，因为它很快结束，还能告诉你"这一下有多重"。

| 测量 | 标注 | 出处 |
|---|---|---|
| 没有速度 FOV、没有速度线、没有身体惯性；镜头位置始终 = 眼睛位置 | [实测] | CR §1、N6 |
| 移动里 FOV 只有滑铲 ×1.1，线性 0.25 s（4:3 水平 FOV 89 → 97.9） | [实测 + 反编译] | CR §3.6 |
| 走路侧移横滚 0（`sv_rollangle` 0） | [实测 + 反编译] | CR §1 |
| 倾斜只按**相对量**：滑铲 15 × \|S\| × sin(视角和滑向夹角)，正着滑是 0；冲刺转向按转速最多 2° | [实测 + 反编译] | CR §2.2、§2.3 |
| 落地 kick 2°（原地跳）→ 约 20°（400 u）→ 30–44°（900 u） | [实测] | CR §2.1 |
| 下滑索俯仰峰 14–18°，二段跳约 6–8°（公式，没有录像） | [实测] / [反编译] | DIFF FND |

**反例**：
- **眼睛确实会移**：下蹲、滑铲、冲刺 −6 u，滑索上最多约 −9 u，这些都对应身体姿态，不是 kick [实测，CR §3、DIFF K-4]。
- **持续的小摆动存在**：站立 drift ±0.195°、冲刺 sway ±0.25° [实测，DIFF K-3、CR §3.8]。很小，而且是原版，用户要求保留。
- **翻越动画镜头约 5°，持续 0.5 s** [实测，CAM2 §3]，来自动画，不是 kick。

**对比 M5.5**（用户喜欢过，10-24 改成默认原生，代码保留）：速度 FOV +8°、位置 kick、身体惯性都是 R5 没有的；落地俯仰最多 2°，R5 是 37°。**M5.5 是另一种好语言，不是 R5。**

### P3 动量是玩家的资产，只有明确规则才能收走

**解读**：速度是玩家赚来的。系统不会偷偷磨掉它，每次削减都是一条有条件、有数字的规则。

| 测量 | 标注 | 出处 |
|---|---|---|
| 空气摩擦、空气阻力 0，水平 0.0000 u/s 每命令 | [实测] | M2 |
| 空中加速只朝 69 u/s 的意图上限补，已有的速度不被削 | [实测] | M2 |
| 连跳那条命令跳过摩擦；超速连跳 max(v − 100, 299) | [实测 + 反编译] | M2、NR §4.1 |
| lurch 只换方向，速度大小不变；Δv 上限 209.3 | [实测 + 反编译] | NL §2.4 |
| 滑铲：落地续滑没有损失；换地面实体、2 s 以后再加速一次 | [实测 + 反编译] | M2、SL §5 |
| 爆炸击退：直接相加，上限 max(1000, 推之前的 \|v\|)；击退后一小段时间没有减速 | [实测 + 反编译] | RJ §0 |
| 坡度变化处滑铲不离地，133 次 0 次 | [实测] | SL §4 |

**反例**：
- 明确的削减本身：无输入减速 1250 u/s²、落地减速 (t / 1.0)² [实测 / 反编译，M2、NJ §3]。这些有条件，不违背。
- 减速区里空中 / 滑铲进入，水平速度一次 ÷2 [数据，`research/combat/_shared/B-move-slow.md`]。**这是最接近"偷"的一条**，只有技能才这么做。
- 反滥用：连跳高度惩罚（0.75 s 内恢复）、滑铲早跳退还加成、加成冷却 2 s。解读成"动量不能白拿"。

### P4 技巧窗口按时间算，地板低、天花板高

**解读**：不做操作也能玩，会操作多拿一点。窗口是时间，不是帧，所以和帧率无关，能练。

| 窗口 | 数值 | 标注 | 出处 |
|---|---|---|---|
| lurch 强度 | 0.2 s 满，0.5 s 线性到 0，按时间，±1 ms | [实测 + 反编译] | M3、NL §3 |
| 翻越加速 | 最后 133 ms，×1.3 出口；本地跑的是 SDK 的状态机，不是原版 | [实测] | M3 §3.3 |
| 原生 superglide | 分界是结束前约 0.1 s 的时间 | [反编译] | NR §4.1 |
| 滑铲早跳退还 | 200 ms 下蹲过渡内（0.201 退、0.215 不退） | [实测] | DIFF RPS |
| 落地后高度恢复 | 0.15 s 平台，到 0.75 s 恢复 | [实测 + 反编译] | M2、NR §4.1 |
| 后坐重置 | 第一发没有偏移；delay + 发数 / rate，R-301 0.11–0.51 s | [实测] | RV §1.3、§3 |

**反例**：
- 钩爪、翻越大部分是自动的，窗口少。
- 随机：落地 kick 有 r，同样的落地每次不同，这部分练不了 [实测，DIFF K-1]。
- `jump_grace` 有一组默认不生效的衰减（`max_decay` 0）[反编译，NL §2.3]，说明"多次 tap 衰减"做了又关了。关的原因我们不知道。

### P5 枪的重量是一条贯穿字段的轴

**解读**：玩家不用读数字就能感到枪的轻重，因为所有和"操作这把枪"有关的时间一起变，再配上开镜时走路多慢。

| 类 | zoom in / out | deploy | ADS 移速 | 换弹 | 标注 |
|---|---|---|---|---|---|
| 手枪 | 0.18 / 0.16 | 0.225–0.4 | 1.0 | 1.25–2.1 | [数据] |
| 霰弹 | 0.20–0.22 / 0.18–0.20 | 0.25–0.5 | 0.9–1.0 | 0.9–2.5 | [数据] |
| SMG | 0.20–0.22 / 0.20 | 0.35–0.4 | 0.75 | 1.7–2.0 | [数据] |
| 步枪 | 0.27 / 0.23 | 0.6 | 0.5 | 2.4–3.2 | [数据] |
| 精确 | 0.30–0.50 / 0.25–0.50 | 0.6–1.0 | 0.425–0.85 | 0.33–2.6 | [数据] |
| 机枪 | 0.34 / 0.30 | 0.8 | 0.4 | 3.1–3.4 | [数据] |
| 狙击 | 0.20–0.58 / 0.15–0.55 | 0.7–1.2 | 0.35 | 2.66–3.5 | [数据] |

29 把枪的秩相关：zoom in 和 deploy 0.84，zoom in 和 ADS 移速 −0.72，deploy 和 holster 0.87，deploy 和 raise 0.93 [算，FIELDS 脚本]。步枪、机枪、SMG 这几个类内部几乎是同一组值。关镜从不比开镜慢（29 把里 26 把更快，3 把相等）[数据]。

**反例**：

## 5. 技术理念

### T1 线性进度 + 读取方加曲线

R5 几乎所有过渡都是这个结构：一个按 dt 走的 0..1 数，再由每个读者查自己的曲线。

```
进度：f += dt / T（目标 1），f −= dt / T（目标 0）。反向从当前值接着走，不重新开始。
读者：y = a + (b − a) × C(clamp01((f − start) / (end − start)))
```

| 进度 | T | 读者 | 曲线 C | 窗口 | 标注 / 出处 |
|---|---|---|---|---|---|
| 开镜 `zf` | 进 0.18–0.58 s，出 0.15–0.55 s | 镜头 FOV | smoothstep `3t² − 2t³` | 0–1（瞄具可改） | [实测] ADS §1，残差 0.001° |
| | | 枪程序偏移 | 余弦 `(1 − cos πt) / 2` | 0–0.5 | [实测] ADS §2.2 |
| | | 枪动画 | 每把枪自己的动画，播放进度 = `zf` | | [实测] ADS §2 |
| | | 灵敏度 | `tan(FOV / 2) / tan(基础 / 2)`，随 FOV（用上一帧的 FOV）；**关镜那一帧直接回 ×1，不随 FOV 回** | | ~~[反编译] ADS §3~~ 〔11-13〕[实测] [E-MOUSE](combat/gun-measure/E-MOUSE.md) §2 |
| | | 武器 fraction、枪屏幕震动 | 线性 | | [实测] RV §1.1；[反编译] ADS §3 |
| | | 走路晃动 | 线性淡出 | | [反编译] ADS §3 |
| 下蹲比例 | 0.4 s（滑铲 0.2 s） | 眼高 | smoothstep | 0–1 | [实测 + 推断] CR §3.1 |
| 冲刺比例 | 等 0.16 s，每秒 1.25；停 0.11 s，每秒 6.67 | 眼高 −6 | `sin(fπ / 2)` | | [反编译 + 实测] DIFF K-4 |
| 滑铲 FOV | 每秒 0.4 | FOV | 线性（反例） | | [实测] CR §3.6 |
| 翻越进度 | 按高度档 | 翻越镜头淡入 0.15 s | SimpleSpline | | [实测] DIFF D-75 |
| 热度 | 每发 +heatpershot | 弹簧 k、d | 线性插值 | | [实测] RV §2.1 |
| 蓄力 | `charge_time` | Bocek 弹速 | `charge_curve_coefficients` | | [数据] 枪族 charge-spinup |

**为什么这样**（解读）：所有东西同步、可中断、可反向，加新读者不用改时间。枪在 `zf` 0.5 就位，FOV 走到 1：所以"先快后稳"不是一条缓动曲线，是**多个读者窗口叠出来的**。R-301 共 0.27 s，枪约 135 ms 到位 [实测，ADS §2.3]。

**做法**：不要给进度本身加缓动。曲线写在读者那边，每个读者选窗口和曲线。

### T2 kick = 往弹簧加冲量，线性相加

```
每轴独立：x'' = −k·x − d·v，按帧时间精确求解
kick：x += hard × K（角度），v += soft × 20 × K（角速度）
|x|² + |v|² < 0.001 时直接归零
```

两组弹簧 [反编译 + 实测，CAM2 §5、RV §2.1]：

| 弹簧 | 参数 | 进画面 | 进子弹 |
|---|---|---|---|
| 第一组（移动 punch） | k 65、c 9（ζ 0.558），峰值 0.146 s，0.47 s 过零，回弹 12 % | 1 × | ~~未测，推断不进~~ 〔11-13 [实测] [F-GAPS](combat/gun-measure/F-GAPS.md) §1〕**1 ×**，进子弹 |
| 第二组 `m_vecPunchWeapon`（武器 kick） | 字段 / `springs.txt`，按热度和 `zf` 插值；〔11-13 [实测] [F-GAPS](combat/gun-measure/F-GAPS.md) §1.3〕空手时是 k 65、c 9 | (1 − fraction) × | 1 × |

移动事件写第一组，同时给第二组写 0.2 × [实测，CAM2 §2.2]。~~这组常数在拿枪时听谁的，没有验证（§10.2）。~~ 〔11-13 [实测] [F-GAPS](combat/gun-measure/F-GAPS.md) §1.3〕第二组**拿枪时用这把枪当时的武器弹簧**（R-301 腰射 k 40 d 20、开镜 115 / 20，P2020 80 / 20，和 Frida 读到的武器弹簧一致），**空手时是 65 / 9**；第一组永远 65 / 9。所以拿枪时移动事件在第二组的峰值比空手小（R-301 腰射是第一组的 0.13 倍，空手 0.20）。

两种冲量的差别 [实测，RV §4；分布 算，FIELDS §2]：

- **hard 一帧到位**，**soft 在约 1/d 秒内到**。
- **连发枪几乎全靠 soft**：有图案的 17 把 soft / hard 2.1–12，中位 6.6。上抬是被推上去的。
- **单发枪接近一半一半甚至 hard 为主**：没有图案的 12 把 0.15–2.8，Charge Rifle 0.15、EVA 0.3、P2020 1。枪一下就在那。

每发最终抬高（k热 = 0 时）[实测，RV §1.2]：

```
抬高 ≈ K × (hard + soft × 20 / d热)
R-301 开镜公式 1.125，实测 1.17–1.28；Spitfire 开镜公式 1.589，实测 1.45–1.59
```

**移动事件的峰值** [算，SIM；公式实测过]：两组合计峰值 = 0.0771 × 俯仰冲量。

### T3 瞄准角、画面角、子弹角分开存

```
眼睛角度 eang   = 只来自鼠标（这就是"瞄准"）
画面角度        = eang + 翻越动画 + punch1 + (1 − fraction) × punch2 + drift / sway；横滚另算
子弹方向        = eang + 完整 punch2（这一发 kick 之前）+ 扩散
〔11-13 更正，[实测] F-GAPS §1、§5〕子弹方向 = eang + punch1 + 完整 punch2 + 开镜 drift + 扩散
```

全部 [实测 + 反编译]：CAM2 §5、RV §1。腰射子弹那一项是 [推断]（RV §7）。没有任何路径把画面写回 `eang`。

〔11-13 更正，[实测] [F-GAPS](combat/gun-measure/F-GAPS.md) §1、§5〕原来的子弹那一行漏了两项：**punch1（移动 punch）和开镜 drift 也进子弹**。落地 0.1 s 后开枪，子弹 = punch1 + punch2，差 ≤ 0.28°；Wingman 开镜扣掉 punch2 剩下的就是 drift。三种角还是分开存，`eang` 仍然只来自鼠标；只是“子弹角”= 画面角里除了 fraction 以外的全部。

〔11-13 补，[实测] [E-MOUSE](combat/gun-measure/E-MOUSE.md) §1〕"只来自鼠标"要加一句：**鼠标输入先抵消反向的 punch2，剩下的才进 `eang`**（`0x140a33ff0`）。抵消只减到 0，不越过；和 punch 同向的输入全部进 `eang`。所以 `eang` 仍然只来自鼠标，但不是鼠标的全部。子弹 = eang + punch2，鼠标对子弹的作用仍是一比一。

### T4 数据字段驱动，mod 覆盖

- 大部分枪没有自己的逻辑：脚本一句 `FireWeapon_Default`，有些 `.txt` 连回调都不绑 [数据，W1 §2.1]。
- 配件、模式、增益都是字段覆盖：`x`（替换）、`*x`（乘，约 1.4 万条）、`++x`、`--x` [数据，W-MOD]。
- 同名 mod 每把枪自己写数值 [数据，枪族 attachments]。枪管 L1 / L2 / L3：`viewkick_pitch_base` ×0.95 / 0.9 / 0.85，`pitch_random` ×0.8 / 0.75 / 0.7。枪托 L1：`zoom_time` ×0.85，`deploy` ×0.85，`raise` ×0.9，drift ×0.85 [数据，`mp_weapon_rspn101.txt`]。
- **开火模式也是 mod**：Prowler 全自动 = `fire_rate 13.25`、`burst 0`、换 `viewkick_pattern` [数据，W-MOD]。
- 脚本只负责字段说不了的事：门槛（回调返回 0 = 不开火）、状态机（Bocek、Sheila）、槽位（W-FR §3.1）。

**反例**：Charge Rifle、Sheila、Bocek 有不少脚本。**读 `.nut` 前先看 `.txt` 绑了什么**：Havoc 的 `CanFire_EnergyAR` 是死代码 [数据，W1 §2.1]。

### T6 状态选表、状态乘系数，而不是写分支

- **移动倍率 msc 一个数**：速度上限、加速度、lurch 上限都乘它（空手 1.15，兴奋剂下 lurch 上限 294.67）[实测，M2、NL L-05]。**例外**：无输入减速和滑铲减速不乘 msc [实测，M2]。
- **按姿态查表**：扩散 `stand / crouch / air` × `hip / ads`；`viewheight` 按姿态 [数据]。
- **按 `zf` 插值腰射和开镜**：弹簧、fraction、扩散 [实测，RV §2.1、§5]。

**怎么影响武器**：见 §7.8。

### T7 确定性随机，有范围

- 随机种子来自命令号：MD5 → 种子混合 → 线性同余，Frida 逐个对上，Unity 重放逐次一致 [实测，DIFF K-1]。
- 随机项总是 `基础 + 幅度 × r`，r ∈ [−0.5, 0.5]。形状是固定的，随机只改大小 [反编译，CR §3.2]。

### T8 精确积分、帧率无关、最后归零

- 弹簧按帧时间解析解，所以和帧率无关 [反编译，RV §2.1]。
- 窗口按时间不按帧 [实测，NL §3]。
- 接近 0 时直接归零，不留尾巴（弹簧，SmoothCD 也是，目标和当前都小于 0.001）[实测 + 反编译，RV §2.2、DIFF C-12]。

### T9 需要切换的东西共用一个平滑状态

- 绳子横滚三选一，切换时不跳，因为共用 SmoothCD 的值和速度（ω 6.667）[反编译 + 实测，DIFF C-12、CAM2 §5]。
- 滑索视角偏移同样用 SmoothCD（ω 4）[反编译，CAM2 §4]。
- SmoothCD = 临界阻尼。R5 **既有**临界阻尼（用于追目标）**也有**欠阻尼（用于 kick）：追目标不回弹，被打可以回弹。

## 6. 镜头规范

做新镜头效果照这个来。

### 6.1 每帧的拼接顺序 [反编译 + 实测，CAM2 §5]

```
位置 = 身体原点 + 视角高度（下蹲比例）+ 冲刺偏移 + 滑索偏移
俯仰、偏航 = 瞄准 + 翻越动画 + rodeo + punch1 + (1 − f) × punch2 + drift / sway
横滚 = 滑铲 + 冲刺 + 绳子（三选一）+ 墙跑 + 闪避 + punch 横滚，折回 ±180°
FOV = 基础 + 开镜（smoothstep）；滑铲 × 1.1
```

新效果只能**加**进这几行之一，不能改前面的值。

### 6.2 kick 表（事件 → 往第一组写多少俯仰角速度）

r ∈ [−0.5, 0.5]；第二组 × 0.2；峰值 = 0.0771 × 俯仰冲量，约 0.146 s [反编译 + 实测]。

| 事件 | 俯仰 | 偏航 | 横滚 | 俯仰峰值 | 出处 |
|---|---|---|---|---|---|
| 起跳 / 滑铲跳 | (2 + r)·20 | r·20 | (0.9 + 0.5r)·20 | 2.3–3.9° | CAM2 §2 |
| 二段跳 | (4.5 + r)·20 | r·20 | 2r·20 | 6.2–7.7° [算] | CAM2 §2.1，**没有录像** |
| 落地 | s(2 + 0.75r)·20 | 0 | s·r·20 | 0.89–44° | CR §3.2 |
| 下滑索 | (10 + 3r)·20 | 10r·20 | 10r·20 | 14–18° | DIFF FND |
| 〔11-13〕被子弹打中 | 0 | 0 | 0 | 0 | [实测，hyb] [F-GAPS](combat/gun-measure/F-GAPS.md) §3：bot 玩家真开枪，27 发，两组 punch、画面、FOV 全 0 |
| 〔11-13〕自己开枪（震屏） | — | — | — | 0 | [实测] [F-GAPS](combat/gun-measure/F-GAPS.md) §2：只有第二组 kick，没有别的偏移 |

### 6.4 开镜（最完整的例子）

全部 [实测]，公式 ADS §4。**先写这段再做任何开镜相关的东西。**

1. `zf` 线性，反向接着走。
2. FOV：`R = 基础 + (zoom_fov × S − 基础) × (3 − 2t)t²`。S 是本地 `cl_fovScale`（1.272），基础 89。**度数是用户设置，真正要学的是比例**：R-301 tan 比 0.712。
3. 枪的程序偏移：余弦，窗口 0–0.5。量很小（R-301 前向 0.72 u，上下 0.4 u）。
4. 枪的动画：可见运动的主体。R-301：先朝中间甩，下沉 1.37 u，枪口下压 3.5°，横向过冲 15 %，抬起到位，`zf` 约 0.5 结束。
5. **关镜不是倒放**：枪留在瞄准位置，`zf` 降到约 0.83 才动，到 0.19 才回腰射。
6. ~~灵敏度随 FOV 走 [反编译，没跑]。~~ 〔11-13 [实测]，[E-MOUSE](combat/gun-measure/E-MOUSE.md) §2〕开镜过程中每帧乘 `tan(FOV/2) / tan(89/2)`，用上一帧的 FOV，中位误差 0（R-301 机瞄到位 0.711，3x HCOG 0.305）。**关镜第一帧就回 ×1**：这时 `zf` 0.97、FOV 还是开镜值；开镜到一半松开也一样。开镜慢慢变慢，关镜一下变快。

## 7. 枪械规范

### 7.1 一发的流程 [实测 + 反编译，RV]

```
按键 → 过 1 / fire_rate → 子弹方向 = eang + punch2 + 扩散
〔11-13 更正，F-GAPS §1〕子弹方向 = eang + punch1 + punch2 + 开镜 drift + 扩散
→ 飞行（弹道）→ 伤害
→ value += valuePerShot，取 floor(value / valuePerShot) 这一行
→ K = 行 × base + 随机；x += hard·K·缩放；v += soft·20·K·缩放
→ 热度 + heatpershot；扩散 kick += spread_kick，不超过上限
```

**次序很重要**：子弹在 kick 之前取值，所以第一发偏移 0，第二发才有第 0 行。

### 7.2 后坐数值范围 [算，FIELDS §2；实测列 RV]

**怎么读这张表**：
- **开镜连射 k = 0**：打的时候弹簧不往回拉，所以一直爬。R-301 开镜爬到约 5.7° [实测]。回落要等 hold + fade。
- **腰射 k ≠ 0**：边打边回。R-301 腰射第 5 发 5.1°，第 20 发 2.7° [实测]。
- **所以连发枪大多开镜回得快（T 0.10–0.17 s）、腰射回得慢（T 0.2–0.46 s）** [实测 4 把 / 算 FIT]。例外：Prowler、Volt 反过来。

### 7.4 扩散

```
扩散 = 姿态基础（站 / 蹲 / 走 / 冲刺 / 空中 × 腰射 / 开镜）+ 累计 kick
kick 每发 + spread_kick_on_fire，不超过 spread_max_kick
停火 spread_decay_delay 后按 spread_decay_rate 回落
走动 spread_moving_increase_rate / decay_rate 在静止和跑动之间过渡
```

单位度 [实测，IP2 §2.3]。回落速率单位和走动过渡 [数据，语义推断]（W-SR §5）。

范围 [数据，FIELDS §3]（霰弹除外）：站腰 2–5.6（狙击 8），每发 kick 0.15–2.5，kick 上限 1.5–12，开镜 0（步枪、手枪）/ 0.35（SMG）。

### 7.10 枪模 FOV [反编译 + 实测，IRON-SIGHTS "枪模 FOV"；D-120；Unity D-122]

枪有自己的 FOV，和世界 FOV 分开。**新枪、新瞄具都按这条，不要按 `zoom_fov` 直接换算。**

```
t = clamp01((zf − ads_fov_zoomfrac_start) / (ads_fov_zoomfrac_end − ads_fov_zoomfrac_start))

写了 zoom_fov_viewmodel（> 0）：  V = 70 + (字段 − 70) × (3 − 2t)t²     不看 cl_fovScale
没写：                            tan(V/2) = tan(35°) × tan(R/2) / tan(R基础/2)
腰射（zf = 0）：                  两条都等于 70
```

`V` 是 R5 度数，4:3 水平。换成 Unity 垂直 FOV：`2 × atan(tan(V/2) × 3/4)`。1600×900 下每单位正切 `600 / tan(V/2)` 像素。

| 状态（本地 `cl_fovScale` 1.27217，基础 89） | V | px/tan | 垂直 FOV | 实测 px/tan |
|---|---:|---:|---:|---:|
| 腰射 | 70 | 857 | 55.4° | R-301 833–863 |
| 机瞄，`zoom_fov` 60 | 58.5 | 1071 | 45.6° | 没量 |
| 机瞄，`zoom_fov` 55 | 53.0 | 1203 | 41.0° | R-301 1187，Sentinel 1221 |
| 3x，字段 14 | 14 | 4887 | 10.5° | R-301 4914 |

- 实测是看图，精度约 3 %，只测了 R-301 和 Sentinel。其余枪是公式。
- 过渡曲线和世界 FOV 相同是 [推断]，只量了两端。
- **瞄具的 FOV 和开镜位置要一起改**：瞄具把枪往前推，同时收窄枪模 FOV。只改 FOV 不改位置，3x 和 2–4x 会大 2 倍（IRON-SIGHTS "装瞄具时的枪"）。
- **全屏瞄准镜**（Kraber 默认镜、`optic_sniper*`）：代码里到位后 V = 70，开镜看不到枪，没实测。
- **枪口和曳光起点的屏幕位置都跟着枪模 FOV 变**。比枪口坐标查不出这种变化，要比屏幕位置。

**Unity 怎么对应（D-122）：** Unity 没有 `cl_fovScale`。R 和 R基础用 `AdsCurves.FovRatio`（常数 1.27217、89），和世界相机同一个比例，不看 Unity 自己的基础 FOV。滑铲和兴奋剂的 FOV 不进这个比例，R5 的分母会加这类增量，没测。开关 `arsenal.gunFovWorldRule`，关 = 按 `zoom_fov`。Kraber 是例外，保持 `zoom_fov`，因为 Unity 没有全屏瞄准镜画面，环是模型画的，等用户定。

### 7.11 腰射枪身角度 [实测，HOLD-POSE；Unity D-123]

**通用规则（用户 11-05 定）：以后新增或重做的枪，腰射枪身角度都用 R5 实测，不平着拿；没有实测的要标明。** 目前范围是腰射。

- R5 的枪身不是平行视线的：多数枪横滚 2–10°，俯仰 0–3°，Bocek 横滚 42°。R-301 俯仰 0.84°、偏航 0.11°、横滚 6.14°。
- **绕枪口转**，枪口点不动，所以枪口、曳光起点和开火都不受影响。验证时要比枪口差，并且分开比枪身。
- **其他姿态是相对站立的差值**：走路、冲刺、蹲、滑铲、跳在同一次旋转里和站立角度相加，这样和 R5 的绝对角度一致。不要把站立角度和差值分成两次旋转。
- 开镜的过程 R5 读不到横滚，Unity 按开镜进度线性退掉，是 [推断]。
- 建模时不要为了平着拿的画面去挪瞄具。Bocek 就是例子：瞄具应该在弓的中线上，开镜靠转角落到准星。开镜也转的枪要单独写明角度从哪来；Bocek 的横滚 18.92° 是反算，偏航 4.22° 沿用腰射，都不是读出来的。
- 没有实测的枪：Vantage，平着拿，已标明。

## 9. 新东西怎么做

### 9.1 流程

1. **写一句目标**：玩家感到什么。
2. **找锚点**：R5 里最接近的两个东西（枪：同一重量类；镜头：同一强度的事件）。没有锚点就先去找；真的没有，在 TF2 里找（只有 Apex 没有原型或 R5 测不了才用，LOG / `tf2/`）。
3. **选结构**：用 §5 的 T1–T9，不新发明结构。
4. **填数**：范围取 §6 / §7 / FIELDS。不写范围外的值，除非写明为什么。
5. **判定**：过 §9.2。
6. **做进 Unity**：开关，默认值，切回。
7. **对照**：用同样的输入比（`research/feel/`），能比的比 R5，不能比的比锚点。
8. **留档**：选中和没选中都写（`CLAUDE.md`）。**没试玩前，新值都是 [设计]。**

### 9.2 判定标准

每条过了打勾。**结论分三档**：

- **R5 规律内**：结构和范围都在 R5 里。
- **有锚点的延伸**：结构在，数值超范围，或者加了 R5 没有的机制，但能指出最接近的锚点。
- **明确偏离**：结构不在 R5 里。可以做，但是要写成偏离，并留开关（M5.5 就是这样保留的）。

**通用**

- [ ] 能不能指出两个 R5 锚点？
- [ ] 有线性进度吗？曲线是不是在读者那边？
- [ ] 回落是 hold + 线性，还是弹簧？
- [ ] 中途反向或被打断，从当前值接着走，不跳？
- [ ] 和帧率无关？
- [ ] 随机有界，种子可复现？
- [ ] 同时发生多个时，相加能得到对的结果？（不需要新写优先级）
- [ ] 是字段，不是逐个写代码？
- [ ] 能关（开关）并且能切回？

**枪**

- [ ] 属于哪个重量类？开镜、切枪、抬枪、开镜移速都按这类选了吗？（表 P5）
- [ ] 连发：有图案？soft / hard ≥ 2？开镜热弹簧 k = 0？
- [ ] 单发：base 给俯仰？hard 占比大？
- [ ] 第一发有没有偏移？（应该没有）
- [ ] 子弹在 kick 之前取值？
- [ ] 开镜 fraction 多少？如果 > 0，为什么准星和子弹可以不一致？
- [ ] 扩散：各姿态都填了？顺序 蹲 ≤ 站 ≤ 走 ≤ 冲刺 ≈ 空中？如果全部相同，它是不是近距离枪？
- [ ] 停火回得对吗：开镜快、腰射慢？回到原位？
- [ ] 图案能重开：value 倒数？
- [ ] DPS 落在 170–220？不是的话换弹或弹匣有没有配平？
- [ ] 枪的**开镜动画**不是线性？关镜不是倒放？
- [ ] 特殊机制走"进度 → 改字段"？

**镜头**

- [ ] 只动画面？瞄准角逐位相同？
- [ ] 事件走 kick（弹簧），持续状态走目标（SmoothCD）？
- [ ] 有位置 kick、速度 FOV、自己的震屏吗？有的话写成偏离
- [ ] 倾斜是相对量（速度对视角、转速），不是状态？
- [ ] 量级对得上：平常 2–4°，主动大动作 5–8°，退出大动作 14–18°，硬落地可以到 30–44°？
- [ ] 多个同时发生：相加后不会不可接受吗？

**技能**

- [ ] 控制走状态效果（有淡出，同类取最大）？
- [ ] 威力大的有预告吗？
- [ ] 夺控短吗（R5 锚点 0.8 s）？
- [ ] 玩家和 NPC 数值分开了吗？
- [ ] 进入高速状态的处理（空中 / 滑铲进入是否砍一半）想过吗？
