# 火箭跳 A：原生爆炸击退规格（D-77）

日期 2026-10-31。用户 10-31 定了 D-56 选 **A：EPG 式物理击退**（理由："更原生，上限更高，也更有技巧"）；B（Fuse Knuckle Jumper 式跳跃加成）没选，留档见 `DECISIONS.md` D-77。

这份规格把 R5 #64（[EPG-ROCKET-JUMP.md](EPG-ROCKET-JUMP.md)，下称"#64"）、TF2 T-1 / T-7（[../../tf2/epg/T1-T7-REPORT.md](../../tf2/epg/T1-T7-REPORT.md)，下称"T-1"）和这次补的原生查证合在一起，写成 Unity 照着做的规则。Unity 实现在 HSD-Unity 分支 `rj/knockback-a`（PR letheli710/HSD-Unity#52，§10）。

## 1. 数据从哪来

- #64：本地 R5 S21 服务端模拟开火（沿视线追踪 + 按弹速等待 + 原生 `RadiusDamage`），真手雷对照，29 个条件、每个 ≥5 次；另有单次推力扫描（`data/probe-force-sweep.csv`）。
- T-1：TF2 EPG 真实开火；诊断模组每次受伤打印伤害、**伤害力向量**和伤害点相对脚的位置（`tf2/runtime/data/20261029_020710_t1_epg/diag.tsv` 的 `HSDDIAG DMG` 行）。这次用这些力向量反推方向和衰减。
- 原生查证（这次做的，§7）：Ghidra 12.1.4 读本地 `r5apex.exe`（项目 `ghidra-projects/r5apex.gpr`，sha256 3f44bf9a…）和 `r5apex_dx12.exe`（函数地址对上 `research/rea-native/map/functions.csv`）。只记地址、偏移和常数，反编译原文不进仓库。

## 2. 衰减和方向

### 2.1 方向：指向身体中心，没有竖直加成

TF2 T-1 站着朝脚下打（jump_kit）：伤害点在脚前 10.2 u、高 1.0 u，力向量 (0, −18241.7, 62387.8)，|F| = 65000.0。

- 力的竖直 / 水平比 = 3.42。从伤害点指向"脚 + h"的方向比是 (h − 1) / 10.2，解出 h = 35.9，就是 72 高碰撞体的中心（36）。所以力**只沿爆点 → 中心**，没有额外往上的分量。[TF2 meas]
- R5 滑铲中朝脚下打：Δv 竖直 576、水平 317，比值 1.82；爆点在脚前 12.1 u、高 2 u，解出中心高 24.0，正好是蹲姿碰撞体（48）的一半。站着时比值 3.65 对中心 36 的 3.26 略高，是因为测 Δv 那一帧地面摩擦已经吃掉一点水平速度。[R5 meas]

**规格**：方向 = 单位向量（身体中心 − 爆点），身体中心 = 脚 + 当前碰撞体高度 / 2（站 72 → 36，蹲 / 滑 48 → 24）。

### 2.2 衰减距离：沿连线走到身体表面的长度

#64 当时写"离身体中心约 70 u 内是满额"，那是按到中心的距离看的，不准。把所有数据重新对一遍：

| 数据 | 爆点相对脚 | 到中心 | 按"到中心"算的衰减 | 按"到最近点"算 | **按"沿连线到表面"算** | 实测衰减 |
|---|---|---|---|---|---|---|
| R5 站着 45° | 前 76.5，高 2 | 83.7 | 0.75 | 0.94 | **0.880** | 0.889（伤害 0.891） |
| R5 站着 30° | 前 125.9，高 2 | 130.4 | 0.39 | 0.55 | **0.521** | 0.519（伤害 0.509） |
| TF2 脚下 37.6 u | 前 6.0，下 37.6 | 73.8 | 0.62 | 0.94 | **0.936** | 0.937（伤害 0.926） |
| TF2 脚下 49.3 u | 前 7.4，下 49.3 | 85.6 | 0.54 | 0.84 | **0.838** | 0.840（伤害 0.838） |
| TF2 脚下 71.1 u | 前 10.2，下 71.1 | 107.6 | 0.35 | 0.66 | **0.655** | 0.658（伤害 0.647） |

（R5 内径 52、外径 180；TF2 内径 30、外径 150；身体按半径 16、高 72 的柱体。）

- 侧面和脚下两种几何都只有"沿连线到表面"这一种算法对得上：侧面差 ≤ 0.01（约 1–2 u），脚下差 ≤ 0.003。这和 Source 引擎 `RadiusDamage` 的做法一致（从爆点向目标中心追踪，用碰到目标处的距离）。[R5 meas][TF2 meas]
- 曲线是**线性**：R5 侧面两点之间斜率 (0.889 − 0.519) / (113.6 − 66.2) = 1 / 128 = 1 / (180 − 52)。不是平方。[R5 meas]
- 推力和伤害用同一个衰减（两边都对得上）。

例外（已知、不追）：
- TF2 在脚**侧面**、贴地的三个点（31 / 69 / 113 u），按柱体表面算偏大，按中心算偏小；它们像是打到了腿的命中盒（比 16 u 细）。R5 侧面三点按 16 u 柱体就对得上，所以规格用柱体。[推断]
- R5 跳起后 24 / 48 帧开火（爆点在脚正下方 45–54 u）：实测衰减 0.95 / 0.93，按柱体底面算应该满额。这两组的爆点位置是服务端分帧结算记下的，有 0.05–0.25 s 的偏差，位置本身不可靠；也可能是两腿中间打空、打到了骨盆。规格不为它们改。[推断]

**规格**：d = 从爆点沿"爆点 → 身体中心"走到碰到身体柱体（半径 16，高 = 碰撞体高度）的长度，爆点在身体里面时 d = 0；衰减 = clamp(1 − (d − 内径) / (外径 − 内径), 0, 1)。

## 3. 大小

- Δv = 推力 × 衰减 ÷ 100。[R5 meas] jump_kit 地面 659、空中 653，比 650 大 1.4 % / 0.5 %；真手雷 50000 → 488（低 2.4 %）。[TF2 meas] 力向量的模正好 = 推力 × 衰减，Δv 655。这 ±2 % 来自"单条命令速度跳变"的测量方式（同一帧里还有重力和摩擦），规格用 100，差别记进 `R5-DIFF-ARCHIVE.md`。
- 和现有速度相加：跳的同一帧开火，竖直方向 = 跳的速度 + 推力，所以 486 > 270。[R5 meas]

## 4. 上限

- setfile `damageImpulseSpeedBoostLimit` = 1000（所有传奇相同）。[R5 native]
- 推力扫描：站着推力 100000 和 200000 都是 948（服务端 0.1 s 后采样，减掉重力 75 后约 1000）；TF2 997。[R5 meas][TF2 meas]
- 已经比 1000 快时的规则没有测过。规格：推完的 \|v\| 不超过 max(1000, 推之前的 \|v\|)，即推力不能把速度加到 1000 以上，但也不会把已经超过 1000 的速度砍下来。[推断]
- `damageImpulseSpeedLossLimit` = 50：#64 冲刺跳打在前面时水平速度掉了 171，但总速度是上升的，看不出这条限制在管什么。**不做**，留作未测。[R5 native][未测]

## 5. 地面门槛（做，偏离 #64 的建议）

**R5 的门槛是什么**（这次重新解读 #64 的数据）：
- 推力扫描（爆点在脚边 30 u，满额）：31000 → 完全不动；31500 → 0.1 s 后 vx −210、vz 163。换成初速：31500 ÷ 100 = 315，沿爆点 → 中心是 (−209, 236)，0.1 s 后竖直减掉重力 75 = 161，水平不变（正好在 §7 的无减速窗口里）。所以 31500 是**全额推**，没有"一下跳到 266"的台阶，266 只是 0.1 s 后的采样值。[R5 meas]
- 31000（Δv 310）整个不动，连水平分量都没有。站着 30° 那组 Δv 342 推得动（竖直分量只有 99）。所以判断看的是 **\|Δv\| 总大小**，不是竖直分量：站在地上时 \|Δv\| ≤ 310 不起作用，≥ 315 全额。[R5 meas]
- EPG 原版 30000 在空中能推出 287，所以空中没有门槛。[R5 meas]
- TF2 不一样（门槛在 17500–25000 之间，30° 时竖直分量被吃掉、水平保留）。规格跟 R5。[TF2 meas]
- 判断写在服务端，`r5apex_ds.exe` 没有分析，精确值只能取 310 和 315 中间的 **312.5**。[R5 meas]

**为什么做**：#64 §7 建议"先不做，玩了再定"。这次改成做，理由：
1. 用户选 A 的理由是"更原生"，D-70 拟合原则是尽量贴合 R5 native；门槛有直接数据，实现只是一个比较。
2. 对 EPG 火箭跳本身没有影响：脚下开火 Δv 650，远高于 312.5；只影响远处（d > 约 118 u，衰减 < 0.48）爆炸的小推力，以及手雷（50000）在 d > 约 132 u 时的推力。
3. 有开关（`KnockbackParams.groundMinSpeed = 0` 关掉）。

## 6. 护盾规则（不做）

R5：伤害全被护盾吃掉就完全不推，只要 1 点进血就全额推（EPG 和真手雷都一样）。[R5 meas]
HSD 的战斗层没有护盾（只有血量），所以这条规则没有对象，**不做**。以后加护盾时照这条做。

## 7. 击退后的减速规则（新发现，做）

在 R5 客户端里找到一个随网络同步的玩家字段 `m_damageImpulseNoDecelEndTime`（r5apex.exe 偏移 0x2a50），读它的地方：

| r5apex_dx12.exe 函数 | 地图里的名字 | 做什么 |
|---|---|---|
| 0x140a36580 | Ground_GetDecel | 地面减速（含 slideDecel / slideWantToStopDecel / sprintDeceleration）乘一个系数 k |
| 0x140a48f90 | AirMove | 水平空中阻力（setfile 阻力项）乘 k |
| 0x140a4a7c0 | WalkMove | 贴墙时沿法线的减速乘 k |
| 0x14092ab70 | Pred_RunCommand? | 收到伤害冲量事件时写这个字段 |

- 写入：结束时间 = 当前时间 + \|冲量速度\| × `impulse_low_decel_duration_scalar`。这个 ConVar 的默认值是 **0.003**（r5apex.exe 静态初始化 0x1401c5fb0，字符串 "0.003"，ConVar 对象 0x1422f65b0，值在 +0x60）。[R5 native]
- 系数 k：当前时间 ≥ 结束时间时 k = 1；否则 k = clamp(1 − 2 ×（结束时间 − 当前时间）, 0, 1)，即前段为 0，**最后 0.5 s 线性恢复到 1**（常数 0.5 在 .rdata 0x14157ce0c）。[R5 native]
- jump_kit 脚下开火 Δv 650 → 窗口 1.95 s：前 1.45 s 落地也没有地面摩擦，之后 0.5 s 逐渐恢复。这解释了 #64 推力扫描里 0.1 s 后水平速度一点没掉（−210）。[R5 native][R5 meas]
- 服务端用的值没有在运行时核对过（客户端和服务端 ConVar 一般相同；之前核对过的 movement ConVar 都一致）。[未测]
- 对玩法的影响：火箭跳落地后有 1–2 s 保持速度，接滑铲 / 再跳都不会被摩擦吃掉；横向小推力（贴地打）也能把速度保持一段时间。

**规格**：每次击退（被地面门槛忽略的不算）把结束时间设成 now + \|Δv\| × 0.003（覆盖旧值）；每条命令按上面的 k 缩放地面减速（deceleration / sprintDeceleration / crouchDeceleration / slideDecel / slideWantToStopDecel）和能力给的水平阻力。slideVelocityDecay（滑铲的指数衰减）不在 Ground_GetDecel 里，不缩放。

## 8. 自伤

- EPG：`explosion_damages_owner 1`，伤害 65；带 jump_kit 的弹体对自己 ×0.75 = 48.75。[R5 native]（TF2 同一行脚本，TF2 基础伤害 90 → 68。）
- Gibraltar 再 ×0.85 是传奇被动，HSD 不做。
- HSD 玩家 100 血、6 s 后每秒回 12：连续火箭跳两次剩 2.5 血，第三次会倒地。按原生做，**菜单里给"EPG 自伤"开关**（默认开）。要不要默认关等试玩。[design]

## 9. 和移动状态的交互

| 状态 | R5 | Unity（`rj/knockback-a`） |
|---|---|---|
| 地面站着 / 走 | 门槛以上全额推，离地 [R5 meas] | 同；向上的推力让身体离地（抬 1 u，沿用 TF2X） |
| 空中 | 推力不变（damageImpulseScaleAir 1），没有门槛 [R5 native][R5 meas] | 同 |
| 跳的同一帧 / 刚跳 | 叠加在跳的速度上：486 / 492 u [R5 meas] | 同（结果见 §10） |
| 冲刺 | 推力相同；打在前面刹车、打在后面加速 [R5 meas] | 同 |
| 蹲 / 滑铲 | 身体中心变低（24），同样朝下打水平分量更大：363 → 680；被推离地后滑铲结束 [R5 meas] | 同（碰撞体蹲着按 48 算中心） |
| 蹬墙跑 | [未测] | 速度加到身体上，蹬墙跑能力下一条命令按自己的规则处理（只在 Fun 里有，HSD 设计） |
| 钩爪 | [未测] | 速度加到身体上，钩爪拉力继续叠加（不脱钩） |
| 滑索 / 翻越 / 爬墙 | [未测] | 这几个状态每条命令自己设位置 / 速度，击退相当于被忽略，状态不会被打断 |
| 击退后落地 | 无减速窗口（§7）[R5 native] | 同 |

原生里击退会不会打断钩爪、滑索、翻越，本地 R5 拿不到能开火的 EPG，模拟开火也没测这些状态，**未测**；Unity 现在的处理是按现有能力代码推出来的，没有单独测试。

## 10. Unity 实现和对照

对照表在 `R5-DIFF-ARCHIVE.md` "RJA 火箭跳 A"一节。要点：

- 站着朝脚下：R5 270 u，Unity 282 u（+4 %）。
- 跳 + 开火：R5 486 u。R5 这组是服务端模拟开火，爆炸在起跳后约 0.13 s；Unity 同一爆炸时刻（开火晚 12 条命令）487 u。Unity 真正"同一帧"开火是 563 u，因为弹体几乎不晚、跳的竖直速度还没掉。
- 俯视角小时 Unity 推得更多（30°：444 对 342），原因是 Unity 战斗层的眼睛 60 u 在原点正上方，R5 70 u、在原点前 9 u，同样角度落点更近。规则本身一致。

开关：

- `MovementConfig.knockback`（`KnockbackParams`，Reference / Fun 都开）：null 或 `enabled = false` = TF2X 的推力（推力 ÷ 103、最近点衰减、没有上限 / 门槛 / 窗口），逐字节不变。
- 游戏 Esc → 战斗页 "R5 原生击退" 开关（PlayerPrefs `hsd.tf2.x.rjnative`，默认开）；"EPG 自伤"（`hsd.tf2.x.epgself`，默认开）。
- FeelBatch / CameraFeelBatch `-preRJA`（试验数据里没有爆炸，输出不变）。
- 新武器 EPG（jump_kit）：Y 键切武器或战斗页选择；战斗页"火箭跳测试点（EPG）"把人放到测试点，旁边的柱子标出 R5 的 55 / 270 / 486 u。

## 11. 没测 / 没做

1. 地面门槛的精确值（310–315 之间）和判断方式：服务端 `r5apex_ds.exe` 没分析。
2. `damageImpulseSpeedLossLimit` 50 的意义。
3. 速度已经超过 1000 时被推的规则。
4. 蹬墙跑 / 钩爪 / 滑索 / 翻越中被炸的原生行为。
5. `impulse_low_decel_duration_scalar` 服务端运行时的值。
6. 弹体直接命中的 `impulse_force`（jump_kit 17500）：Unity 没做直接命中推力（只有爆炸推力）。
7. 正式服 EPG-1（S23）的数值：本地 S21 只有泰坦陨落版的武器文件。
