# 枪械补测 B 批（不占鼠标和焦点）

会话 `r5gap-b`，2026-11-13。本地 R5Flowstate（S21 客户端 + S3 dedi + SDK 混合构建），火力训练场，离线，1600×900 窗口。游戏一直在后台跑，没有拿过焦点，没有发过真实鼠标和按键：开火、开镜、跳、冲刺都用客户端 `ClientCommand`，截图用引擎的 `screenshot` 命令。Frida 挂着时约 140 fps。游戏跑了约 50 分钟（21:28–22:20 UTC）。

清单在 `workspace/R5-GAP-TESTS-1113.md` 的 B 批。B5 由读代码的会话做，这里没有做。

## 先说结论

1. **落地后马上开枪，子弹会偏，而且偏很多（B1）。** 子弹方向 = 瞄准 + 第一组 punch（移动）+ 第二组 punch（武器）+ 开镜 drift。从 400 u 落下（落地 770 u/s），落地 0.1 s 后开枪，子弹比瞄准点低 16–17°；900 u 落下低 24–28°；96 u 落下低 2°。以前文档推断"移动 punch 不进子弹"，**这是错的**。换句话说，R5 的子弹总是打在屏幕中心（开镜、fraction 0 时）。
2. **拿枪时第二组弹簧用武器字段，空手才是 k 65 c 9（B1）。** 两份文档都对，只是说的情况不一样：第一组（移动 punch）永远是 k 65 c 9；第二组空手时也是 65 / 9，拿着 R-301 腰射是 40 / 20、开镜 115 / 20，P2020 是 80 / 20。
3. **开枪没有震屏（B2）。** 射击那一刻画面只有 punch，别的偏移是 0.000°。但单发枪**拉栓、泵动、换弹的动画带着镜头动**：Peacekeeper 腰射泵动时俯仰 5.2°、横滚 1.8°，Kraber 拉栓 4.9°，Longbow 腰射 0.4°。
4. **真实中弹也没有镜头抖动（B4）。** 让 bot 玩家真的开枪打我们，27 发命中，瞄准、两组 punch、画面、眼睛位置、FOV 全是 0。
5. **Wingman 第 3、4 发偏高不是混合构建的问题（B6）。** 服务端和客户端的子弹方向完全一样；偏高的那 0.35–0.5° 是开镜 drift，drift 也进子弹。后坐表走到最后一行就停住，Flatline、R-99 也是。
6. **射速和蓄力（B7）**：Kraber 每发 2.235 s，Sentinel 1.597 s，Charge Rifle 按住 0.856 s 出一发。蓄力全是**线性进度**（Charge Rifle 0.85 s、Havoc 0.39 s、Bocek 约 0.4 s、L-STAR 2.2 s）。
7. **远距离（B8）**：50–300 m 下坠约是公式的 0.85 倍，**没有归零**。只代表 S3 dedi。
8. **枪口焰（B3）**：粒子系统寿命量到了（步枪 0.5–0.6 s，手枪 0.13–0.3 s，狙击 1.6–1.8 s），亮度和"亮的那一下有多长"本地没测成。
9. **移动中的几项（B9）**：钩爪拉动中**完全不能开枪**，开镜被取消，拉完 0.44–0.48 s 才能开枪；爬墙（翻越前那一段）同样收枪，翻过墙顶那 0.5 s 里第 0.15–0.19 s 就能开枪；Marksman's Tempo 把 Sentinel 间隔从 1.60 s 降到 1.43 s。Kinetic Loader 滑铲装填没测成。
10. **准星和 HUD 截图（B10）**：30 把枪腰射 / 开镜各一张，加 4 张命中后的画面。命中标记在截图里没有认出来。

标注：[实测] 是这次量的；[hyb] 是涉及服务端、只代表混合构建的；[推断] 是解读。

## 1. 落地后开枪，和第二组弹簧（B1）

### 1.1 方法

- 场地：出生点头上 390 u 有屋顶，所以换到一块平的屋顶（`-9949, -1488, 3856`），上方 1100 u 没有遮挡。
- 每次运行：服务端把玩家放到屋顶上方 96 / 400 / 900 u，速度清零；客户端脚本一直等，等到"离地 → 再着地"的那一帧，再等 0 / 0.05 / 0.1 / 0.2 / 0.3 s，然后 `+attack` 一帧（R-301 单发），一直开着镜。每格 2 次。
- 子弹方向：注册了 `AddCallback_OnWeaponAttack`（服务端和客户端各一个），这是代码在开火时给脚本的 `attackOrigin` 和 `attackDir`，记下它的俯仰。
- punch：Frida 每帧读玩家 `+0x2430`（第一组）和 `+0x2448`（第二组），每发 kick 时再记一次。探针 `f-gaps/frida_fgaps.js`。
- 弹簧：不开枪，只是落地，然后对落地后 1.2 s 的轨迹逐帧拟合 `x'' = −k·x − d·v`。腰射、开镜、空手（收掉主武器）、P2020 各 2 次，400 和 900 u 两种高度。

### 1.2 子弹偏不偏

全部 26 发在 [B1-SHOTS.tsv](f-gaps/B1-SHOTS.tsv)。俯仰正数是向下。

| 高度（落地速度） | 落地后多久开枪 | 子弹俯仰 | punch1 | punch2 | 子弹 − (punch1 + punch2) |
|---|---|---|---|---|---|
| 96 u（375 u/s） | 0.02–0.03 s | 0.28–0.31° | 0.24–0.26 | 0.05 | 0.00 |
| | 0.06–0.12 s | 1.86–2.32° | 1.62–2.08 | 0.22–0.26 | 0.00 |
| | 0.24 / 0.31 s | 1.99 / 1.13° | 1.85 / 1.08 | 0.15 / 0.07 | −0.01 / −0.03 |
| 400 u（770 u/s） | 0.03–0.05 s | 1.77–2.27° | 1.56–1.98 | 0.30–0.38 | −0.08 ~ −0.10 |
| | 0.08–0.14 s | 15.5–17.2° | 13.6–15.5 | 1.71–1.97 | −0.10 ~ −0.12 |
| | 0.22 s | 15.5° | 14.5 | 1.17 | −0.16 |
| | 0.32 s | 8.4–8.6° | 8.05–8.24 | 0.54–0.55 | −0.19 |
| 900 u（1160 u/s） | 0.09 s（d = 0） | 3.67° | 3.27 | 0.63 | −0.23 |
| | 0.06–0.15 s | 23.6–28.3° | 20.8–25.6 | 2.96–3.45 | −0.25 |

- **子弹 = 瞄准 + punch1 + punch2**，差 0.00–0.28°。差值是负的（偏上），落得越高越大，和下面第 5 节的开镜 drift 同一个来源（drift 也进子弹），这里没有单独扣。
- 服务端和客户端报的 `attackDir` 一样（差 ≤ 0.016°）。
- 落地头 0.05 s 内开枪，扩散还是空中的值（开镜 2.6–4.2°），之后才回到 0。
- "落地后多久"用的是客户端脚本看到着地的时刻，和落地 kick 生效的那一帧差一两帧，所以 d = 0 的几发 punch 还很小（900 u 那发 0.09 s 才 3.7°，而 0.06 s 的另一发已经 23.6°）。看大小以 punch 列为准。
- 400 u 和 900 u 落地，punch1 峰值 15–19° 和 27–34°，在 0.1–0.2 s。

**怎么理解**：R5 的子弹从来都跟着"开镜时的屏幕中心"走。腰射时屏幕 = 瞄准 + punch1 + (1 − fraction) × punch2，子弹 = 瞄准 + punch1 + punch2；差别只在第二组的 fraction。落地这一下画面往下砸多少，子弹就往下偏多少。高处落下后立刻开枪等于打地上。

## 2. 开枪时的屏幕震动（B2）

7 把枪（R-99、R-301、Spitfire、Wingman、Peacekeeper、Longbow、Kraber）× 腰射 / 开镜 × 2 次，站着不动。每帧算"画面 − 瞄准 − punch 函数的输出"（震屏只能在这里），以及眼睛位置。对照：客户端 `ClientScreenShake(5, 10, 1)`，同一个探针量到 0.90–0.96° 和 4.7–4.8 u，所以探针看得见震屏。[B2-SHAKE.tsv](f-gaps/B2-SHAKE.tsv)、[B2-CYCLE.tsv](f-gaps/B2-CYCLE.tsv)。

| 枪 | 射击时（每发之后 0.26 s 内） | 之后的动作动画 |
|---|---|---|
| R-99、R-301、Spitfire（连射 14–21 发） | 0.000°，位置 0 | 打空后的换弹有，不属于开枪 |
| Wingman（3 发） | 0.000° | 无 |
| Longbow | 0.000° | 腰射拉栓：射后 0.32 s 起，0.6 s，俯仰 0.43°、横滚 0.70°、眼睛 0.1 u；开镜 0 |
| Peacekeeper | 0.000° | 泵动：腰射射后 0.27 s 起，1.09 s，俯仰 5.15°、偏航 −0.31°、横滚 −1.84°；开镜 0.39 s 起，0.41° / 0.75° |
| Kraber | 0.000° | 拉栓：腰射 0.85 s、开镜 1.08 s 起，1.6–2.3 s，俯仰 4.9°、偏航 −0.87°、横滚 −1.46° |

- **R5 开枪没有自己的震屏**：射击那一刻，画面只有两组 punch（加站立 / 开镜 drift）。
- **镜头会跟着武器动作动画动**：拉栓、泵动、换弹时，相机挂点随动画走，量级可以到 5°。它不是噪声，是一条平滑曲线，从开枪后零点几秒开始（这是 [推断]：来自动画相机挂点；曲线形状在 `B2-CYCLE` 只有峰值和时长）。
- 开镜时这部分大多被压掉（Longbow 0，Peacekeeper 0.4°），Kraber 开镜仍有 4.9°（它的开镜是瞄具界面，镜头还在动）。

## 4. 枪口焰（B3）

### 4.1 粒子系统寿命 [实测]

客户端脚本在枪模的 `muzzle_flash` 挂点上把武器自己的 `fx_muzzle_flash_view`（和 `_world`）放一次，逐帧 `EffectDoesExist`，各 2 次。[B3-FXLIFE.tsv](f-gaps/B3-FXLIFE.tsv)。

| 枪（粒子） | 第一人称 | 第三人称 |
|---|---|---|
| R-301 / Flatline / G7（`assault`） | 0.50–0.60 s | 0.53–0.62 s |
| R-301 消音（`assault_sup`） | 0.44–0.48 s | |
| R-99（`smg`） | 0.55–0.61 s | 0.42–0.47 s |
| Spitfire（`lmg`） | 0.43–0.55 s | 0.57–0.61 s |
| Wingman | 0.13–0.29 s | 0.30–0.35 s（`pistol`） |
| P2020（`pistol`） | 0.26–0.28 s | |
| Peacekeeper | 0.72–0.92 s | |
| EVA-8 | 0.80–0.91 s | |
| Longbow、Kraber（`snp_hmn`） | 1.57–1.81 s | 1.03 s |
| Charge Rifle | 0.17 s | |

两次之间差到 0.1–0.3 s，说明粒子寿命带随机。**这是整个系统（含烟、火星）的寿命，不是亮的那一下**。R-301 每 0.074 s 一发，所以连射时几十个系统叠在一起。

### 4.2 亮度：没测成

试了单发后第 0–26 帧各截一张（R-301 9+9 发、Wingman 18 发，[B3-FLASH.tsv](f-gaps/B3-FLASH.tsv)，截图在私有仓库）。白天场景里，射后 0–50 ms 截图上最显眼的是**曳光**（从枪口斜着飞出去的亮条），枪口本身的亮核分不出来；Mastiff 射后 3 帧有一团很大的焰（B10 截图里看到）。`B3-FLASH` 的像素计数被枪模后坐的移动淹没了，**不能当亮度用**。要量亮度得在暗处、固定枪模，或者读粒子定义，这次没做。

## 5. 表尾和 Wingman 第 3、4 发（B6）

### 5.1 表尾 [实测]

Flatline（`corrupted_mag`，35 发）、R-99（33 发），腰射和开镜各 2 次，按住打空。[B6-TABLE-END.tsv](f-gaps/B6-TABLE-END.tsv)。

|---|---|---|---|---|

和 R-301 一样：**停在最后一行，不循环**。第一批用服务端补弹匣的办法没成（客户端预测的弹匣没跟着变，打到原弹匣就停了），改用大弹匣 mod。

### 5.2 Wingman 第 3、4 发 [实测]

开镜单发，间隔 0.4 s 和 0.8 s 各 2 次，[B6-WINGMAN.tsv](f-gaps/B6-WINGMAN.tsv)。

- 服务端和客户端的 `attackDir` 完全一样（4 位小数）。**不是 dedi 和客户端的差别。**
- 子弹 − 瞄准 = punch2 + 开镜 drift。间隔 0.4 s 时第 3、4 发比 punch2 高 0.35–0.52°，正是那时的 drift；间隔 0.8 s 时第 4、5 发反而低 0.2–0.5°（drift 摆到另一边）。按 Wingman 开镜 fraction 约 0.27 扣掉以后，和前一帧的"画面 − 瞄准"差 ≤ 0.02°。
- 所以 D-EXT §7"子弹比客户端 punch 高、越积越多"（R-301、P2020、G7 也有）也应该是开镜 drift 进子弹，**不是混合构建造成的**。这是 [推断]：那批没有 drift 数据，没有逐发核对。

## 7. 远距离弹道和归零（B8）

出生点朝 yaw 0 的长通道，假人放在 50 / 100 / 200 / 300 m，服务端每帧把视线对准"胸口 + 公式下坠"，开镜单发 3 次。用开火回调给的发射方向画直线，下坠 = 直线在命中距离上的高度 − 命中点高度。[B8-DROP.tsv](f-gaps/B8-DROP.tsv)。[hyb]：子弹由 S3 dedi 算。

| 枪 | 50 m | 100 m | 200 m | 300 m |
|---|---|---|---|---|
| Longbow（公式） | 1.70（1.96） | 5.8–6.7（7.9） | 25.6–26.2（31.3） | 60.5–61.7（70.6） |
| R-301 | 1.95（2.23） | — | 37.0（35.9） | — |
| Wingman | 4.29（5.38） | 18.8（21.5） | — | — |

- 实测 / 公式 0.74–1.03，多数 0.80–0.87。公式 = ½ × 750 × 重力倍率 × (距离 / 弹速)²，不含阻力。
- **没有归零**：50 m 正好是 `bolt_zero_distance`（1968.5 u），如果归零生效，那里的下坠应接近 0，实测仍是公式的 0.8–0.9。
- 命中只有 11 发：R-99、Kraber 和其余格子没打中（假人太小、R-99 下坠大），**样本少**。比 1 小的原因没查（可能是命中点在假人前表面、或者重力不是 750）。

## 8. 移动中的几项（B9）

[B9-STATES.tsv](f-gaps/B9-STATES.tsv)。

### 8.1 钩爪中开枪 [实测]

Pathfinder，用 G6 那面能拉动的世界墙（玩家 `-12321.5, 7400, 294.92`，朝 x+）。按钩爪后按住开火 0.9 s 或 3.2 s，R-301，腰射和开镜各 2+2 次；不按钩爪的对照 13 发。

- **拉动中一发都打不出**（拉 1.21–1.22 s，8 次全是 0 发）。主武器还在手上，但开火被挡住。
- **开镜被取消**：按钩爪后、拉动开始前 `zf` 已经回到 0；拉动中最多 0.15–0.18。
- **拉完 0.44–0.48 s 才出第一发**；按着开镜的话，`zf` 在拉完后 0.35 s 回到 1。

### 8.2 真实翻越开镜、翻越出来的抬枪 [实测]

用 B-STATES 那块墙。冲刺、跳、在空中按开镜，一直按住开火 4 s。这块墙要先**爬**（贴墙后向上约 1.6 s，`IsMantling` 还是 0），再翻过墙顶（`IsMantling` 1，0.52 s）。

| | R-301 腰射 2 次 | R-301 开镜 2 次 |
|---|---|---|
| 贴墙前 | 照常开火（5–6 发） | 照常，空中能开镜 |
| 爬墙那 1.6 s | **不能开火**（贴墙后最多 1 发） | 开镜 0.14 s 内被取消，不能开火 |
| 翻墙顶（0.52 s） | 进入后 **0.15–0.19 s** 恢复开火，翻越中打 5–6 发 | 同样 0.16–0.19 s；`zf` 保持 0 |
| 翻完 | 继续 | 按着开镜的话，翻完 0.28 s 回到 1 |

上一轮"翻越打断开枪，R-301 只打 4 发"实际是**爬墙**打断的；翻墙顶的那一段反而能开枪。B-STATES 说的"开镜时没触发翻越"这次用"空中再按开镜"解决了：开镜不会阻止爬墙和翻越，只是被取消。2 s 那批（按 2 s 就松前进键）翻越只有 0.1 s，没用。

### 8.3 Marksman's Tempo [实测，脚本在服务端 hyb]

Sentinel + `hopup_marksmans_tempo`，每 0.1 s 点一次：间隔 1.595 → 1.435–1.482 → 1.434 s（2 次）。不带时 1.597 s（B7）。字段 `marksmans_tempo_active` 把 rechamber 改成 1.25，实测没到 1.25 + 0，弹匣只有 4 发，只看到 3 个间隔。

### 8.4 Kinetic Loader：没测成

Peacekeeper + `hopup_kinetic_loader`，打 3 发后冲刺 0.6 s 再按蹲 1.4 s（速度到 369，说明滑起来了）。弹匣 2 → 2，没有装填；站着也是 2 → 2。装填是服务端脚本线程（`KineticLoaderFunctionality_ServerThink`，要 `IsSliding && IsOnGround`），[推断] 这里用脚本给枪时线程没起来，或者 S3 dedi 没认出滑铲。**本地测不了，不能说明正版没有。**

## 10. 局限

- **混合构建**：服务端的东西（子弹、伤害、弹道、hop-up 脚本）标了 [hyb]。B1 子弹方向客户端和服务端一致；B4 受击、B8 弹道、B9 Tempo / Kinetic 只代表 S3 dedi。
- 每格多为 2 次。B1 落地开枪 26 发，另外 6 次没打出（原因没查）。
- 帧率约 140 fps；B1 弹簧拟合用帧时间，和帧率无关。B2 的数值是 0 或动画峰值，不受帧率影响。
- B1 的高度是"传送到空中再掉下"，不是跑跳落地；落地速度和真实跳下同一个公式。
- 时间零点：B7 / B9 里按键时间是墙钟换成游戏时间（用 Frida 帧对齐），误差约 ±0.05 s；开枪时间本身是游戏时间，精确到帧。
