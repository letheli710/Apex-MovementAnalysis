# 技能系统记录模板

用户 2026-10-31 定：每项技能研究，除了研究结果、数据和实现，还要带一份 Markdown，把这个技能的整个系统完整记录下来。目的是以后改参数、改实现、把它和别的技能融合、拆分、组合时，照着这份记录就能动手。

文件位置：`research/combat/<传奇>-<能力>/SYSTEM.md`（英文小写，例如 `lifeline-heal-drone/SYSTEM.md`）。同一个文件夹放分析脚本、静态值表、实测数据说明。

写法：中文，短句。每条事实标来源（`文件:行号`、武器 `.txt` 字段、ConVar、实测会话文件夹）。脚本里没写、靠推断的，写"推断"。

---

## 0. 概要

- **技能**：传奇 / 槽位 / 名字 / 主脚本。
- **一句话**：它在游戏里做什么。
- **分类**（可多选，见 C0-ABILITY-FILTER 第 1 节）：
  - 好技能：效果本身值得在 HSD 里做；
  - 可视化：表现（动画、特效、跟随运动、绳子、屏幕效果、HUD）值得借；
  - 系统：背后的机制（指派目标、跟随、瞬移、伙伴 AI、仇恨、载具……）值得借。
- **可拆出的部件**：列出能单独拿给别的技能用的部件，每个一行，指向第 3 节对应位置。例：`跟随运动 → 3.2 FollowMedic_MoveThread`。

## 1. 它用什么实现各种效果

逐个效果写：这个效果靠引擎里的什么东西实现。

| 效果 | 实现手段 | 说明 |
|---|---|---|
| 例：持续回血 | 状态效果 / 每帧线程加血 | |
| 例：治疗绳 | 绳索实体（10 节点） | |

常见手段：投射物、触发器（trigger）、状态效果（status effect）、伤害类型和 damageSourceId、脚本线程、实体（prop / npc / vehicle）、粒子特效、绳索、屏幕调色、HUD（RUI）、声音、高亮。

客户端和服务端分开写。注意本地是 S21 客户端 + S3 dedi + SDK 的混合构建，服务端脚本有可能是 SDK 社区重写的，怀疑时标出来，第 5 节列为要实测。

## 2. 流程

从按键到结束，按时间顺序写。能画状态机就画（Mermaid 或文字都行）。

- 触发条件（按键方式、充能、前置条件、不能用的情况）；
- 每一步：发生什么、持续多久、谁触发下一步；
- 打断和取消（被打、倒地、换武器、死亡、超距）；
- 结束和冷却；
- 升级 / 天赋分支怎么改流程。
