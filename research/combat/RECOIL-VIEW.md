# 武器后坐对画面的作用 · R5 实测（RECOIL-VIEW）

会话 `recoil-view`，2026-11-02。本地 R5Flowstate（S21 客户端 + S3 dedi + SDK 混合构建），火力训练场，离线，1600×900 窗口，约 140 fps（Frida 挂着）。

工具在 [recoil-view/](recoil-view/)。原始记录在私有仓库 `HSD-RawData` 的 `apex/research/combat/recoil-view/`：`frida/frames.csv`（每帧）、`frida/shots.csv`（每发）、`runs/`（113 次运行）、`ghidra/`（反编译片段）。

**标注**：**[实测]** = 这次在 R5 本地混合构建上读到的。**[反编译]** = 从 `r5apex_dx12.exe` 读的代码，没有单独跑。**[算]** = 用实测验证过的弹簧公式和 `.txt` 字段算的。**[推断]** = 没有直接证据。S21 正版和 Unity 都没有在这次运行。

样本：R-301、Spitfire 腰射 / 开镜各 4 种连射长度，各 3 次；Wingman、P2020 腰射 / 开镜各 2 种打法，各 3 次；间隔测试 R-301、Spitfire 各 7 个间隔，各 1 次；子弹对比 4 把枪开镜，各 4 次。

## 结论先说

| # | 结果 | 依据 |

## 1. 画面和子弹（问题 1）

### 1.1 读到了什么

`m_vecPunchWeapon_Angle` 能读：客户端玩家 `+0x2448`（角度）、`+0x2454`（角速度）。没有用截屏。证据：镜头输出角度减去瞄准角，正好等于 `0x140af1ed0` 返回的 punch；腰射时它和 `+0x2448` 的比值精确等于 `1 − fraction`，最大残差 0.000°。**[实测]**

| 枪 | 模式 | `weaponFraction` | punch → 画面的斜率 | 期望 |
|---|---|---|---|---|
| R-301 | 腰射 | 0.05 | 0.950 | 0.95 |
| Spitfire | 腰射 | 0.2 | 0.800 | 0.80 |
| Wingman | 腰射 | 0.4 | 0.600 | 0.60 |
| P2020 | 腰射 | 0 | 1.000 | 1.00 |
| R-301 | 开镜 | 0 | 1.016 | 1.00 |
| Spitfire | 开镜 | 0 | 1.051 | 1.00 |
| Wingman | 开镜 | 0.3 | 0.693 | 0.70 |
| P2020 | 开镜 | 0.2 | 0.648 | 0.80 |

开镜几行不准，因为开镜时还叠着 **view drift**：不开枪也有，俯仰最大 0.29°，偏航 0.21°（`look_ctl`）。P2020 开镜的 0.648 只能算受 drift 干扰，不能拿来否定 0.80；样本少、punch 小，这一格**没有定下来**。

CAM2 §5 第 6 条写的"第二组 × (1 − 开镜比例)"不准确，应该是 × (1 − fraction)，fraction 按开镜比例在腰射和开镜两个值之间插值（`0x140af0c90`）。这次已改。**[反编译 + 实测]**

### 1.2 幅度和表

每发 punch 的增量 = `hard × kick`（角度）+ `soft × 20 × kick`（角速度）。开火时热弹簧 `k = 0`，角速度按阻尼 d 衰减，于是：

```
每发最终抬高 ≈ kick × (hardScale + softScale × 20 / d热)
```

| 枪 | 模式 | d热 | k热 | 公式 | 实测 punch / 表累计 | 说明 |
|---|---|---|---|---|---|---|
| R-301 | 开镜 | 60 | 0 | 1.125 | 1.17–1.28 | 高出的部分**推断**来自第一发那一帧还是冷弹簧（d = 20），外加下文的服务端纠正 |
| R-301 | 腰射 | 20 | 40 | 不适用 | 2.10（第 1 发）→ 1.86（第 5 发）→ 0.57（第 20 发） | 热弹簧 k 不是 0，边打边回落 |
| Spitfire | 开镜 | 45 | 0 | 1.589 | 1.45–1.59 | |
| Spitfire | 腰射 | 35 | 0 | 1.957 | 1.97–2.21 | |

连射时 R-301（13.5 发/s）腰射峰值约 5.1°（第 5–6 发），第 20 发落到约 2.7°；开镜一直爬到约 5.7°。**[实测]**

### 1.3 子弹

假人 150 u，开镜（扩散 0），每帧把瞄准按回原位，比命中点和当时的 punch：

| 枪 | 发数（不含第一发） | 偏航：\|命中 − punch\| 平均 | 俯仰：命中 / punch（打在躯干的） |
|---|---|---|---|
| R-301 | 40 | 0.05° | 0.96 |
| Spitfire | 35 | 0.04° | 0.98 |
| P2020（fraction 0.2） | 16 | 0.03° | 1.03 |
| Wingman（fraction 0.3） | 12 | 0.07° | 1.21 |

- **第一发落在瞄准点上**：高度 1639.1，眼睛 1639.0，横向 512.0（4 次都是）。**[实测]**
- **子弹用完整 punch，不乘 (1 − fraction)**：P2020 第 3 发 1.37–1.41° 对 punch 1.32–1.43°，乘 0.8 就只有约 1.1°。Wingman 第 2 发 0.73–0.84° 对 0.70–0.80°，乘 0.7 只有约 0.5°。**[实测]**
- **腰射子弹没有单独验证**：腰射扩散 3–5°，这个样本量分不出来。**[推断]** 和开镜同一规则。
- **Wingman 没有完全对上**：第 3、4 发子弹比客户端 punch 高 0.1–0.4°，每次都这样。子弹是服务端算的，**推断**是 S3 dedi 和 S21 客户端的差别，没有查。其他三把枪俯仰低 2–4 %，含命中点在碰撞盒表面（实际距离约 148 u）带来的误差。

IP2 §2.2 说"子弹跟着表走、`EyeAngles` 不变"：`EyeAngles` 确实不变（punch 不进瞄准角），但这不说明视角不动。D-86 据此让后坐只作用在子弹上，这个推论是错的；用户 11-02 的判断对。

### 1.4 水平方向

表第 1 列负数 = 视角偏航减小 = **向右**。R-301 `rspn101_2` 第一行 −0.30，`s2Y` 变负，命中点 `y` 变小；面朝 +x 时 −y 是右边。这个方向和 punch 对上了（1.3 节）。IP2 §2.2 的"左偏 0.4–2.2 u"方向写反了，Unity 的注释照抄了它。**[实测]**

## 2. 停火后的回落（问题 2）

### 2.1 规律

`m_vecPunchWeapon` 每帧按弹簧走，`x'' = −k·x − d·v`，按帧时间精确求解（`0x140a33ee0` / `0x140521af0`）。三轴独立。k、d 取当前的冷热混合：

```
热度：每发 +heatpershot（上限 1）
最后一发后 holdtime 内不变，之后在 fadetime 内线性降到 0
k, d = 热弹簧和冷弹簧按热度插值，再按开镜比例在 hipfire / ADS 之间插值
|x|² + |v|² < 0.001 时直接归零
```

**验证 [实测]**：从最后一发的状态出发，用这个公式和实测的 k、d、帧时间往后算，和实测曲线比。腰射 R-301、Wingman、P2020 的 RMS 是 0.001–0.021°。R-301 开镜实测热度：0.084 s 开始降，0.132 s 到 0（字段 0.08 + 0.05）；Spitfire 0.125、0.174 s（0.12 + 0.05）。

**服务端纠正**：连发枪的 RMS 大（0.1–0.3°），因为客户端 punch 会被纠正一下：每次连射 1–2 次跳变，幅度 0.2–1.07°，大约在停火后 0.17 s（Spitfire 腰射最大）。腰射 R-301、Wingman、P2020 几乎没有。**推断**是混合构建 S3 dedi 和 S21 客户端的预测差，**不要照做**。

### 2.2 实测曲线

时间从回落峰值算起（秒）。"D + T" = 用 `先停 D，再 exp(−(t − D) / T)` 拟合实测，RMS 是相对峰值的比例。

| 枪 | 模式 | 峰值在最后一发后 | 到 50 % | 到 10 % | D | T | RMS | 过冲 |
|---|---|---|---|---|---|---|---|---|
| R-301 | 腰射 | 0.017 | 0.365 | 1.081 | 0.04 | 0.46 | 0.007 | 0 |
| R-301 | 开镜 | 0.067 | 0.244 | 0.424 | 0.13 | 0.14 | 0.035 | 0.002° |
| Spitfire | 腰射 | 0.059 | 0.341 | 0.643 | 0.18 | 0.22 | 0.041 | 0 |
| Spitfire | 开镜 | 0.039 | 0.304 | 0.449 | 0.21 | 0.12 | 0.056 | 0.03–0.13° |
| Wingman | 腰射 | 0.056 | 0.194 | 0.535 | 0.04 | 0.22 | 0.006 | 0 |
| Wingman | 开镜 | 0.070 | 0.194 | 0.523 | 0.04 | 0.21 | 0.006 | 0 |
| P2020 | 腰射 | 0.068 | 0.201 | 0.500 | 0.05 | 0.20 | 0.010 | 0 |
| P2020 | 开镜 | 0.111 | 0.194 | 0.349 | 0.09 | 0.12 | 0.032 | 约 0.05° |

**曲线形状**：冷弹簧过阻尼的（R-301 腰射 k40 d20、Spitfire 腰射 k80 d20）是单调回落，尾部指数；欠阻尼的（R-301 开镜 k115 d20、Spitfire 开镜 k95 d15、P2020 开镜 k55 d10）开始慢、中段快、略微过冲。

**能否回到原位**：能。`x` 最后被归零，不残留。归零时间（从最后一发）：R-301 腰射 2.4–2.7 s，开镜 0.8–1.0 s；Spitfire 腰射 1.3–1.6 s，开镜 1.0–1.2 s；Wingman 1.7–2.0 s；P2020 约 1.1 s。**[实测]**

**偏航**：同一规律，用偏航自己的 k、d。到 50 %：R-301 腰射 0.32 s、开镜 0.21 s，Spitfire 0.25、0.21 s，Wingman 0.36、0.34 s（比俯仰慢，偏航 k 小），P2020 0.26、0.21 s。**横滚**也有：R-301 最大 0.45°，Spitfire 0.58°，Wingman 0.08°，同样进画面。**[实测]**

## 3. 图案什么时候重新开始（问题 3）

```
行号 = floor(value / viewkick_scale_valuePerShot)，不超过最后一行
每发 value += valuePerShot（这些枪都是 1）
value 当前值 = 上次记录值 − (现在 − 上次开火 − valueDecayDelay) × valueDecayRate，只在等待过后减，不小于 0
```

**[反编译]** `0x140712c80`，**[实测]** 下表。

| 枪 | 打了几发 | 间隔（s） | 下一发的 value | 公式 | 行号 |
|---|---|---|---|---|---|
| R-301（delay 0.09，rate 50） | 11 | 0.131 | 8.93 | 8.95 | 8 |
| | 11 | 0.231 | 3.92 | 3.95 | 3 |
| | 11 | 0.280 | 1.25 | 1.50 | 1 |
| | 11 | 0.388 及以上 | 0 | 0 | 0 |
| Spitfire（delay 0.15，rate 80） | 8 | 0.110–0.139 | 8.00 | 8 | 8 |
| | 8 | 0.248 | 0 | 0.16 | 0 |
| | 8 | 0.348 及以上 | 0 | 0 | 0 |

所以"回到第一发"的时间 = `delay + 发数 × valuePerShot / rate`：R-301 打 1 发 0.11 s，打满 21 发 0.51 s。而且间隔更短时**不是从头开始**，是接着中间某一行。

## 4. `viewkick_spring` 和 soft / hard（问题 4）

**数值位置**：`scripts/weapons/springs.txt`（`research-src/s21-platform/`，本地安装 `platform/scripts/weapons/`）。R-301、Spitfire、Wingman、P2020 这 7 个条目两边逐字相同。**[实测]** 运行时读回的 k、d 也等于文件值。

| 条目 | hip k / d（pitch） | ADS k / d（pitch） |
|---|---|---|
| `rspn101_vkp` | 40 / 20 | 115 / 20 |
| `rspn101_vkp_hot` | 40 / 20 | **0** / 60 |
| `lmg_vkp` | 80 / 20 | 95 / 15 |
| `lmg_vkp_hot` | **0** / 35 | **0** / 45 |
| `wingman`（没有 hot） | 120 / 30 | 100 / 25 |
| `pistol` | 80 / 20 | 55 / 10 |
| `pistol_hot` | 80 / 20 | 45 / 10 |

全部枪的值见 [recoil-view/FIT-TABLE.tsv](recoil-view/FIT-TABLE.tsv)（只取武器默认值，没有计算配件 mod）。

**soft / hard**（`0x140711ce0`）：

```
kick = 表的这一行 × viewkick_pitch_base + 随机（|r| 在 inner..1 之间 × 第 4 列 × viewkick_pitch_random × 0.5，符号随机）
x += hardScale × kick × 缩放
v += softScale × kick × 缩放 × 20
```

每发的 Δv / Δx **[实测]** 都精确等于 `soft × 20 / hard`：

| 枪 | 俯仰实测 | 公式 | 偏航实测 | 公式 |
|---|---|---|---|---|
| R-301 | 132.86 | 132.86 | 41.43 | 41.43 |
| Spitfire | 193.33 | 193.33 | 153.33 | 153.33 |
| Wingman | 37.14 | 37.14 | 40.00 | 40.00 |
| P2020 | 20.00 | 20.00 | 30.00 | 30.00 |

所以 W-SPREAD-RECOIL 的推断（hard 即时、soft 平滑）对了。hard 那部分一帧就到，soft 那部分在 1/d 秒内到。

随机 **[实测]**：R-301 每发 `Δx / hard − 表` 平均 −0.002 到 −0.022（0 均值），标准差约 0.10，和第 4 列 ±0.15–0.225 相符。这肯定了 IP2 的推断：第 3、4 列是随机范围。Wingman、P2020 没有图案（`row = −1`），kick 直接是 `base ± random`。

**[反编译]** 没有跑到的缩放（`0x140712e80`）：按开镜比例的 `viewkick_air_scale_ads`、`viewkick_duck_scale`、`viewkick_move_scale`，按 value 在 `scale_min`、`scale_max` 之间插值，第一发 `scale_firstshot`。这次的枪这些都是 1，站着测的，都没走到。**〔11-04 更正：站着也走，见第 10 节。〕**

## 6. Unity 该改什么

**这次没有改 Unity。** Unity 的现状读自工作树 `wp3-weapon-unity`（未提交）。

### 6.1 三个常数

**建议（A）：用弹簧取代这三个常数。** 一个全局常数无法同时描述腰射和开镜（差 3 倍），也无法描述不同枪。数值都在现成的 `.txt` 里，不是拟合来的。

| 常数 | 现在（猜的） | 方案 A：弹簧 | 方案 B：还用一阶衰减，但只能取一组 |
|---|---|---|---|
| `RecoilReturnDelay` | 0.2 | 删掉，换成 `viewkick_spring_cooldown_holdtime` + `fadetime` 控制的热度（R-301 0.08 + 0.05） | **0.13** |
| `RecoilReturnTime` | 0.12 | 删掉，换成 `springs.txt` 的 k、d（R-301 开镜 115 / 20，腰射 40 / 20） | **0.14** |
| `RecoilViewSmooth` | 0.025 | **0**（删掉）：hard 是即时的，soft 的上升已经由弹簧产生，再平滑就重复了 | **0.017**（R-301 开镜：1 / 60） |

方案 B 按 R-301 开镜取值。代价 **[实测]**：腰射 R-301 应当 T 0.46 s，这组值回得快 3 倍多。要用 B 就按枪和模式分开：

| 枪 | 腰射 D / T / Smooth | 开镜 D / T / Smooth | 来源 |
|---|---|---|---|
| R-301 | 0.04 / 0.46 / 0.038 | 0.13 / 0.14 / 0.017 | D、T [实测]，Smooth [算] |
| Spitfire | 0.18 / 0.22 / 0.029 | 0.21 / 0.12 / 0.023 | 同上 |
| Wingman | 0.04 / 0.22 / 0.020 | 0.04 / 0.21 / 0.024 | 同上 |
| P2020 | 0.05 / 0.20 / 0.025 | 0.09 / 0.12 / 0.044 | 同上 |
| 其他枪 | `FIT-TABLE.tsv` 的 `D`、`T`、`Smooth` 列 | 同左 | [算]，R-301 的算值和实测差 0.01–0.03 |

现在猜的 0.2 / 0.12 比较接近开镜（开镜本来就回得快），腰射差得最远。

## 10. 每发的缩放、累计值、表尾、横滚（2026-11-04 补）

前面第 4 节写"这次的枪这些都是 1，都没走到"，这句话**不对**：站着开枪也走缩放。Mastiff、Longbow、Sentinel、Wingman 这些枪第一发就不是 1。下面的规则来自反编译（`r5apex_dx12.exe`：kick `0x140711ce0`，缩放 `0x140712e80` + `0x140712d10`，累计值 `0x1406fea80`），再和 R5 记录的逐发 Δpunch 对比。字段缺省值取自运行时读回的 `vars.jsonl`。

### 10.1 规则

```
俯仰 Δangle = hardScale × kick × 缩放(俯仰)，Δspeed = softScale × 20 × kick × 缩放(俯仰)；偏航同样
缩放 = 按开镜比例插值(腰射值, 开镜值) × 蹲 × 空中 × 移动
腰射值 = 第一发且 firstshot_hipfire ≠ 0 时用 firstshot，否则 min + (max − min) × t；开镜值同样
t = clamp((累计值 − LerpStart) / (LerpEnd − LerpStart))；Start = End 时 t = 1，直接是 max
蹲 = 1 + 下蹲比例 × (duck_scale − 1)
空中 = 1 + 开镜比例 × (air_scale_ads − 1)：不在地面时；hover 时另用 viewkick_hover_scale
移动 = move_scale：水平速度超过当前姿态速度的一半时
```

- **有三个累计值**，不是一个：俯仰 `+0x1604`、偏航 `+0x1608`（每发加 `scale_valuePerShot`，封顶 `LerpEnd`），图案 `+0x160c`（每发加 `pattern_valuePerShot`）。衰减用同一组 delay、rate。kick 读的是**这一发加之前**的值。
- **表尾**：图案值到 `行数 × 每行` 时减 `loop_offset` 行。所以 Spitfire（30 行，loop 23）从第 7 行接着走，不是第 23 行；loop 0（R-301）一直停在末行。
- **`start_max`**：第一发（`+0x1700` = 0）时图案值不超过 `start_max` 行。`-1` 没有上限（R-301 主表就是）。只有 8 张表设了。
- **连发**：一组的第一发，图案值向上取整到整组。**[反编译，没有单独验证]**
- **`velocityScalePerShot`**：每发开始时速度先乘它。基础枪都是 1。
- **随机**：`|r|` 在 `inner` 到 `random` 之间 × 该行随机列 × 0.5，符号抛硬币。**没有图案的枪也 ×0.5**，随机列当 1。
- **横滚**：`base + 硬币 × (randomMin..randomMax)`，不走缩放，有自己的弹簧（R-301 k 20000，d 22）。

## 11. 枪模每发的跳动（2026-11-04 补）

第 5 节和 `gun-measure` 里的结论是"换算没查"。这次查了。**开镜是 R5 的规则，已对上；腰射的源头没追到，用的是拟合。**

### 11.1 开镜：有规则

来自反编译：kick `0x140711ce0`，弹簧 `0x140a34170`，枪模 `0x14085c3e0`。

枪模有自己的三个弹簧（玩家 `+0x3514` 角度、`+0x3520` 速度），参数是 `viewmodel_spring_jolt` 按开镜比例插值，不走热度。每发：

```
后退  x：Δ角度 = 后退量 × 俯仰 hard × jolt_scale    Δ速度 = 后退量 × 俯仰 soft × 20 × jolt_scale    （不乘这发的 kick，每发一样）
偏航  y：Δ角度 = 这发 punch 的偏航 Δ角度 × jolt_scale    Δ速度 = 这发 punch 的偏航 Δ速度 × jolt_scale
横滚  z：Δ角度 = 这发 punch 的横滚 Δ角度 × jolt_scale    Δ速度 = 这发 punch 的横滚 Δ速度 × jolt_scale
```

进枪模（**全部 × 开镜比例**，所以腰射没有）：

```
向前 = x × 开镜比例
向右 = viewmodel_jolt_side · (x, y, z) × 开镜比例
横滚 = viewmodel_jolt_roll · (x, y, z) × 开镜比例 − punch 横滚
```

最后那个 `− punch 横滚` 不乘开镜比例：镜头跟着 punch 横滚，枪再转回去，所以枪相对世界基本不滚。所有枪的 `jolt_side`、`jolt_roll` 都只有中间一项，所以实际只有 y 起作用：**枪的横滚来自这发的偏航后坐**。

字段偏移：`viewmodel_jolt_scale` 0x730、`backwardPerShot` 0x734、`side` 0x738、`roll` 0x744，加武器 `+0x19d0`。

### 11.3 腰射：不是规则，是拟合

腰射时上面的公式全是 0，但枪明显在动（R-301 俯仰约 −0.8°）。查到的：

- **不是动画序列**：`seq` 和 `cycle` 全程不变。
- **不是 `weaponFraction`**：那一项 `f × vmScale × punch`，R-301 只有 0.0475 倍，实测 0.5 倍以上。
- **不是屏幕抖动**：`0x140965a30` 也加到枪上，但它不动偏航，实测偏航也在动。
- 枪的角度**跟着镜头走，然后回落，而这时 punch 还没回落**。Wingman 甚至回落到反方向（−0.70° 到 +0.37°）。
- 枪模 `0x14085b1f0` 用 `+0x1de0` 的矩阵转了一次角度，这是最后一个没排除的来源，这个偏移的写入方太多，**没追下去**。

所以这里写的是**测量的拟合，不是 R5 的规则**：

```
枪的俯仰 = g × (镜头俯仰 − L)，L 用弹簧 (k, d) 追镜头俯仰；偏航同样；横滚另加一项
枪的前、上 = 固定比例 × 枪的俯仰；右 = 固定比例 × 枪的偏航
全部 × (1 − 开镜比例)
```

每把枪每个通道一组 (k, d, g)，在这把枪的腰射连按和按住两次记录上一起拟合，见 [gun-measure/D-GUNKICK.tsv](gun-measure/D-GUNKICK.tsv)。`1 − 开镜比例` 是**推断**：开镜时实测接近 0，中间过程没测。

拟合的好坏差很多，残差 RMS / 幅度 RMS：

| 枪 | 俯仰 | 偏航 | 枪 | 俯仰 | 偏航 |
|---|---:|---:|---|---:|---:|
| R-99 | 0.25 / 3.74 | 0.07 / 0.49 | Longbow | 0.13 / 0.57 | 0.05 / 0.30 |
| R-301 | 0.14 / 0.87 | 0.08 / 0.23 | P2020 | 0.10 / 0.28 | 0.03 / 0.08 |
| Spitfire | 0.25 / 1.58 | 0.11 / 0.42 | Wingman | 0.18 / 0.37 | 0.08 / 0.18 |
| Devotion | 0.21 / 2.08 | 0.13 / 0.46 | EVA-8 | 0.30 / 0.42 | 0.17 / 0.29 |
| Kraber | 0.14 / 1.24 | 0.09 / 0.97 | **Mastiff** | **0.83 / 1.08** | 0.19 / 0.59 |

连射枪的俯仰残差大多是幅度的 10–30 %。**单发和霰弹枪解释得差**（Mastiff、Peacekeeper、Mozambique、EVA-8、Bocek）。角度通道残差超过幅度 60 % 或者增益超过 2 的，生成数据时**直接置 0**（共 9 个通道），位移比例残差超过 60 % 的也置 0：不动比动错好。

和 HOLD-POSE 第 7 节的转视角也对不上：这里的 (k, d, g) 换算到 233°/s 是几度到几百度，实测转视角只超前 2.44°。所以我把它们当成两回事，Unity 里也是分开的两项。

### 11.5 没做

- **单发枪开镜的跳动**：Mastiff、Kraber、Sentinel 这些 `jolt_scale` 是 0，但开镜也跳（Mastiff 前 +0.49 u，俯仰 −1.52°），这部分既不走 11.1 也没进拟合（拟合只有腰射）。这是这次最明显的缺口。

- **屏幕抖动 `0x140965a30`**：加到枪上，来源没追。
- **+0x1de0 矩阵的写入方**：见 11.3。
