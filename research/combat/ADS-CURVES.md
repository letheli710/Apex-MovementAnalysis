# 开镜过程的曲线 · R5 实测（ADS-CURVES）

会话 `recoil-view`，2026-11-02。本地 R5Flowstate 混合构建，火力训练场，离线，约 140 fps（Frida 挂着）。站立不动，不开枪。

工具在 [recoil-view/](recoil-view/)（`frida_ads.js`、`ads_client.txt`、`ads_run.py`、`batch_ads.sh`、`analyze_ads.py`、`ads_curves.py`）。枪的曲线表：[recoil-view/ADS-CURVES.tsv](recoil-view/ADS-CURVES.tsv)。原始记录在私有仓库 `HSD-RawData` 的 `apex/research/combat/recoil-view/`（`frida-ads/`、`runs/`、`ghidra/`）。

**标注**：**[实测]** = 这次在 R5 本地混合构建上读到的。**[反编译]** = 从 `r5apex_dx12.exe` 读的代码，没有单独跑。**[推断]** = 没有直接证据。S21 正版和 Unity 都没有在这次运行。地址都是 Ghidra 基址 `0x140000000`。

样本：R-301、Wingman、Spitfire 完整开镜 / 关镜各 4 次；R-301、Spitfire 中途反向各 2 次。

## 结论先说

用户说开镜应该有加速，这是对的：`zf` 本身是线性的，但画面上的东西都不直接用它。

| 东西 | 随 `zf` 的曲线 | 依据 |
|---|---|---|
| `zf` | **线性**，开镜 1 / `zoom_time_in`，关镜 1 / `zoom_time_out` | [实测] R-301 0.270 / 0.230，Wingman 0.180 / 0.160，Spitfire 0.340 / 0.300 s |
| 镜头 FOV | **smoothstep** `3t² − 2t³` | [实测] 最大残差 0.001° |
| 枪的程序偏移 | **余弦** `(1 − cos πt) / 2`，窗口 0 到 0.5 | [实测] RMS 0.0006–0.0027 u |
| 枪的动画 | **每把枪自己的动画**，由 `zf` 驱动播放进度，开镜和关镜是两段不同动画，有下沉和过冲 | [实测] 只读到两个点的位置，见第 2.3 节 |
| 鼠标灵敏度 | 跟着当前 FOV 走：`tan(FOV / 2) / tan(基础 FOV / 2)` | [反编译] 没有测：不能占用鼠标 |

枪的可见运动**大部分来自动画**，不是程序偏移。R-301 视线中心从腰射到开镜横向移 3.15 u，而程序偏移（`viewmodel_offset_hip` → `ads`）只有前向 0.72 u、上下 0.4 u，横向是 0。

## 1. 镜头 FOV

**[反编译]** `0x140af16a0`，由 `0x140af1720`（`GetFOV` 路径 `0x140afd8a0`）调用：

```
t = clamp01((zf − ads_fov_zoomfrac_start) / (ads_fov_zoomfrac_end − ads_fov_zoomfrac_start))
FOV = 基础 + (开镜 − 基础) × (3 − 2t) × t × t
基础 = floor(70 × cl_fovScale + 0.5)，这里是 89
开镜 = zoom_fov × cl_fovScale
```

**[实测]** `cl_fovScale` 这里约 1.27217（由 69.97 / 55、76.33 / 60 反推）。全部 16 次、三把枪：

| 枪 | `zoom_fov` | 基础 | 开镜 FOV 实测 | 公式 | 最大残差 |
|---|---|---|---|---|---|
| R-301 | 55 | 89 | 69.97 | 69.97 | 0.001° |
| Spitfire | 55 | 89 | 69.97 | 69.97 | 0.001° |
| Wingman | 60 | 89 | 76.33 | 76.33 | 0.001° |

这三把枪没有配瞄具，窗口是默认 0 到 1。瞄具 mod 会改窗口（`mp_weapon_rspn101.txt` 里有 0.1–0.8、0–0.65 等），**[反编译]** 同一条公式，**没有跑**。

**中途反向 [实测]**：`zf` 从当前值接着走，没有跳变。R-301 在 0.598 松开，下一帧 0.567，FOV 也连续；一帧内最大的 FOV 变化 1.92° 只出现在 20 ms 的长帧上。

## 2. 枪

### 2.1 三层

**[反编译]** `0x14085c3e0`（`CalcViewModelView`，读 `viewmodel_offset_*`）和 `0x14085ab80`、`0x14085a3c0`（动画）：

1. **程序偏移**：见 2.2。
2. **动画**：序列的播放进度直接等于 `zf`（开镜）或 `1 − zf`（关镜）。**[实测]** 视图模型 `+0xf4` 逐帧相等，R-301 开镜序列 32、关镜序列 34。曲线写在每把枪的动画资源里，代码里没有，只能实测。
3. **射击抖动**、后坐（RECOIL-VIEW）在这之上叠加，和这里无关。

### 2.2 程序偏移

```
t = clamp01((zf − viewmodel_offset_zoom_frac_start) / (viewmodel_offset_zoom_frac_end − viewmodel_offset_zoom_frac_start))
偏移 = hip + (ads − hip) × (1 − cos(π t)) / 2
```

**[实测]** 三把枪拟合出的窗口都是 0 到 0.50（`.txt` 顶层没有写这两个字段，0.50 是默认值；**推断**，默认值本身没有从代码确认），枪位于 `zf` = 0.5 之后不再变。

| 枪 | 前向、上 腰射（u） | 前向、上 开镜（u） | RMS |
|---|---|---|---|
| R-301 | −0.90, 0.40 | −1.62, 0 | 0.0006 |
| Wingman | −2.00, 0 | −1.00, 0 | 0.0027 |
| Spitfire | −0.60, 0.40 | −0.70, 0 | 0.0010 |

前向比字段值少 2 u，是代码固定减的（`0x14085c3e0`）。

### 2.3 看到的枪（动画 + 偏移）

**能读到的只有这一部分**：两个挂点（`ADS_CENTER_SIGHT_*` 和 `muzzle_flash`）的世界坐标，减去镜头位置。由此得到视线中心的平移，以及视线中心到枪口连线的俯仰、偏航。**横滚读不到；动画的每根骨头读不到；**挂点相对 `zf` 可能差 ±1 帧（R-301 开镜约 ±0.03 `zf`）。

**检验 [实测]**：三把枪开镜结束时视线中心的横向、上下都是 0.00–0.02 u，正好在镜头轴线上，说明读的点是对的。

视线中心相对腰射的总移动 [实测]：

| 枪 | 前向 | 向准星中心（横向） | 向上 | 枪身俯仰 | 枪身偏航 |
|---|---|---|---|---|---|
| R-301 | −0.54 | 3.15 | +0.90 | +0.29° | +2.21° |
| Spitfire | +0.36 | 3.97 | −0.13 | +0.66° | +1.52° |
| Wingman | +0.30 | 2.69 | +0.74 | +0.49° | +5.20° |

R-301 开镜，每 0.05 `zf`（约 13.5 ms）的值 [实测]。`横向归一` 是 0 到 1 的主曲线，`进度` 是到开镜位置的距离比例：

| `zf` | 横向归一 | 进度 | 上下（u，相对腰射） | 俯仰（°） | 偏航（°） |
|---|---|---|---|---|---|
| 0.05 | 0.03 | 0.02 | −0.06 | −0.17 | 0.09 |
| 0.10 | 0.13 | 0.10 | −0.21 | −0.59 | 0.33 |
| 0.15 | 0.37 | 0.23 | −0.57 | −1.61 | 1.02 |
| 0.20 | 0.70 | 0.30 | −1.14 | −2.97 | 2.23 |
| 0.25 | 0.98 | 0.30 | −1.37 | −3.52 | 2.96 |
| 0.30 | 1.14 | 0.39 | −1.07 | −3.12 | 2.88 |
| 0.35 | 1.15 | 0.57 | −0.42 | −2.01 | 2.24 |
| 0.40 | 1.09 | 0.76 | +0.17 | −0.82 | 1.77 |
| 0.45 | 1.04 | 0.91 | +0.64 | +0.20 | 1.70 |
| 0.50 | 0.99 | 0.97 | +0.81 | +0.38 | 1.79 |
| 0.65 | 1.00 | 0.99 | +0.93 | +0.35 | 2.29 |
| 1.00 | 1.00 | 1.00 | +0.90 | +0.29 | 2.21 |

**怎么读**：枪先朝中间甩，同时下沉 1.37 u、枪口下压 3.5°，横向冲过头 15 %，然后抬起到位，`zf` 约 0.5 时基本结束。R-301 开镜共 0.27 s，所以枪在约 135 ms 内就位，FOV 还要继续走到 270 ms。这就是"先快后稳"的来源。

关镜不是开镜的倒放 [实测]：R-301 枪留在瞄准位置，等 `zf` 降到约 0.83 才开始动，横向一直走到 0.19 才回到腰射。全部数值在 `ADS-CURVES.tsv`。

各把枪横向归一曲线的拟合（`S(clamp01((zf − a) / (b − a)))`，S = smoothstep）[实测]：

| 枪 | 开镜 a..b | RMS | 过冲 | 下沉最多（u） | 关镜 a..b | RMS |
|---|---|---|---|---|---|---|
| R-301 | 0.05..0.28 | 0.052 | 15 % | 1.37 | 0.19..0.83 | 0.007 |
| Spitfire | 0.03..0.23 | 0.068 | 18 % | 2.08 | 0.26..0.80 | 0.053 |
| Wingman | 0.05..0.53 | 0.013 | 无 | 1.06 | 0.00..0.32 | 0.061 |

枪和枪差很多（这是动画资源决定的），所以不要用一条曲线代表所有枪。没有测的枪**只能按类型借用**，这是**推断**。

## 3. 其他有曲线的

全部 **[反编译]**，这次**没有单独跑**。

| 东西 | 曲线 | 位置 |
|---|---|---|
| 鼠标灵敏度 | 乘 `tan(当前 FOV / 2) / tan(基础 FOV / 2)`，当前 FOV 就是第 1 节的 smoothstep。R-301 开镜到位约 ×0.712（用实测 FOV 算）。只在按住开镜时生效；松开时条件变了，看代码是直接回到 ×1（另一个条件 `0x1407f9510` 没查，**不确定**） | `0x1408372b0`、`0x140906d10` |
| 分镜灵敏度 | `mouse_use_per_scope_sensitivity_scalars` 这里是 0，所以没有走这条；开了的话也是同一个 smoothstep。`mouse_zoomed_sensitivity_scalar_0` 这里是 1 [实测读值] | `0x140906d10` |
| 视图模型 FOV | 只有写了 `zoom_fov_viewmodel` 的（瞄具 mod）才变，同一个 smoothstep。这三把枪没有写 | `0x140838830` |
| 视图模型屏幕震动 | `shake_viewmodelFactor_human` 0.1 → `_ads_human` 0.01，**线性** `zf` [实测读值] | `0x14085c3e0` |
| 走路晃动 | 在 `zoom_scope_frac_start` 之前线性淡出 | `0x14085bdb0` |
| 武器 punch 分配 | fraction 线性 `zf`（RECOIL-VIEW §1.1） | `0x140af0c90` |

## 4. Unity 该用的曲线

**这次没有改 Unity。** 下面是建议。

### 4.1 时间

```
按住：zf += dt / zoom_time_in
松开：zf −= dt / zoom_time_out
clamp 到 0..1，反向时从当前值接着走，不重新开始
```

这部分 **[实测]**，所有东西都由这个 `zf` 驱动。

### 4.2 镜头 FOV

```
t = clamp01((zf − ads_fov_zoomfrac_start) / (ads_fov_zoomfrac_end − ads_fov_zoomfrac_start))   // 默认 0, 1
R = R基础 + (zoom_fov × S − R基础) × (3 − 2t) × t × t
```

R5 里 `S` = `cl_fovScale`，`R基础` = `floor(70 × S + 0.5)`。**[实测]**，残差 0.001°。

Unity 换算：`cam.fieldOfView` 是垂直 FOV，而 `baseFov` 和 R5 的度数不一定是同一个定义。按比例换算就不用管定义 **[推断，换算本身没有在 R5 验证]**：

```
S = 1.27217，R基础 = 89（要贴合本地 R5）
cam.fieldOfView = 2 × atan( tan(baseFov / 2) × tan(R / 2) / tan(R基础 / 2) )
```

R-301 开镜到位时 `tan(R / 2) / tan(R基础 / 2)` = 0.712。

### 4.3 枪

一共两层，都用同一个 `zf`。

1. **程序偏移** [实测]：`hip + (ads − hip) × (1 − cos(π × clamp01(zf / 0.5))) / 2`，读 `viewmodel_offset_hip`、`viewmodel_offset_ads`。
2. **占位枪的动画** [实测]：Unity 没有动画资源，用表代替。**首选**按枪查 `ADS-CURVES.tsv`（`dF`、`dR`、`dU`、`dPitch`、`dYaw`），开镜和关镜分开，按 `zf` 线性插值。这张表**已经含第 1 层**，用表时第 1 层不要再加一次。

没有表的枪，用这个代替 [推断]：

```
横向 = 总横向 × S(clamp01((zf − a) / (b − a)))，S(t) = 3t² − 2t³
              步枪、机枪类：开镜 a, b = 0.05, 0.25    关镜 a, b = 0.20, 0.80
              手枪类：      开镜 a, b = 0.05, 0.53    关镜 a, b = 0.00, 0.32
其余轴同样插值。过冲和下沉要的话另加：
下沉 = −h × sin(π × clamp01(zf / 0.45))²，只在开镜，h 约 1.4 u（步枪）
```

下沉这一行是我按形状写的近似，不是拟合结果。要准确就查表。

第 4.1、4.2 节和 4.3 第 1 层可以直接抄公式。4.3 第 2 层只对这三把枪是实测。

### 4.4 灵敏度

**[反编译]** 乘 `tan(R / 2) / tan(R基础 / 2)`，随 FOV 连续变化。关镜那一刻的行为没有确认（第 3 节），要在 R5 用真实鼠标测，这和 RECOIL-VIEW §7 第 1 项可以一起做。

## 5. 没有定下来的

1. **枪的横滚**和动画的每根骨头：读不到，只有两个挂点。
2. **`viewmodel_offset_zoom_frac` 默认 0.5**：从三把枪拟合得到，没有在代码里确认。
3. **鼠标灵敏度**：只有反编译，要真实鼠标。
4. **瞄具 mod**：窗口不同，公式 [反编译] 相同，没有跑。
5. **其他枪的动画**：只测了三把，差别很大。
6. **移动、蹲下时**的枪：只测了站立。
7. **R5 FOV 度数的定义**（4:3 水平还是别的）：4.2 的比例换算回避了这个问题，换算本身是推断。
8. **S21 正版**：这次是混合构建。动画和 FOV 公式都在客户端，**推断**和正版相同。
