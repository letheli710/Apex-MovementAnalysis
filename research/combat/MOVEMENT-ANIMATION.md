# 移动和枪的动画怎么叠在一起（R5）

2026-11-03，会话 `drive-docs`。用户要一份"移动和动画融合"的设计理念和技术整理，先查数据再写。这份文档回答：人在动的时候，手里的枪和正在播的动作（换弹、开镜、开火）是怎么合成一个画面的。

**没有进游戏。** 全部来自已有记录的重新分析和这次的反编译：私有仓库 `HSD-RawData` 的 `apex/research/combat/gun-measure/`（逐帧的枪位置、序列号、播放进度）、`research-src` 的武器文件、`r5apex_dx12.exe` 的 Ghidra 工程。工具和输出在 [movement-anim/](movement-anim/)。

**标注**：**[实测]** R5 本地混合构建的逐帧记录（S21 客户端 + S3 dedi，约 140 fps）。**[字段]** 武器文件的值。**[反编译]** 读代码，没有单独跑。**[推断]** 没有直接证据。动画在客户端，**推断**和正版相同。

**样本很少**：运动状态是 R-301 和 Wingman 各 1 次，开火切断是 6 把枪各 1 次。序列号是每把枪自己的编号，不能跨枪用。

## 1. 结论

| # | 结果 | 依据 |
|---|---|---|
| 1 | **移动不是靠播走路动画做的。** 走、蹲走、跳、下落、落地时，枪的主序列完全不变，晃动全是代码按武器字段算的 | [实测] |
| 2 | **只有冲刺换主序列。** 冲刺有自己的循环动画，周期 0.556 s，约等于两步 | [实测] |
| 3 | **换弹时走路的晃动直接叠在换弹动画上**：换弹序列照常播，程序层继续加。换弹中没有"走路换弹"这种专门的动画 | [实测] |
| 4 | **换弹压过冲刺动画，但只到解锁为止。** 解锁一到，冲刺、开火、开镜都能立刻切掉剩下的换弹动画 | [实测] |
| 5 | **开镜把程序层关掉。** 开镜走路时枪几乎不动，R-301 只剩约 ±0.22° 横滚 | [实测] |
| 6 | **切序列时枪不跳。** 序列号一换，播放进度从 0 开始，枪的位置仍然连续 | [实测] |
| 7 | **镜头和枪是两条线。** 枪的晃动不进镜头，镜头的晃动也不是枪带的 | [反编译 + 实测]，N10 |

一句话：**一层慢慢换的主动作，加一层一直在算的程序运动。移动主要改第二层，所以任何动作都能和任何移动自由组合，不需要做组合动画。**

## 2. 枪是怎么合成的

```text
枪的最终位置和角度
  = 主序列的当前帧                 换弹、开镜、冲刺循环、翻越……
  + pose parameter                 每帧写入，第一个是开镜比例 zf
  + 程序偏移                       腰射到开镜的位置，余弦（ADS-CURVES §2.2）
  + 走路晃动 bob                   按 bob_* 字段，开镜时淡出
  + 移动和转向偏移 sway            按 sway_* 字段，有弹性地跟上
  + 射击抖动 jolt、屏幕震动的一部分  按 viewmodel_jolt_*、shake_viewmodelFactor_*
```

这个顺序是从各层的作用整理的，**代码里相加的先后没有逐行核对**。

| 层 | 负责什么 | 谁驱动 | 依据 |
|---|---|---|---|
| 主序列 | 大动作 | 武器状态、冲刺状态 | [实测] |
| pose parameter | 同一动作的连续变化 | 每帧写 12 个槽，第一个 = zf，其余有的来自玩家状态，**没有全部对上名字** | [反编译] `0x14085a3c0` |
| 程序层 | 持续的小运动 | 速度、转向、zf | [字段 + 实测] |
| 动画叠加层 | 代码里存在（`m_AnimOverlay*`，带权重、淡入淡出、顺序；`AE_VM_EVENT_LAYER_ENABLE`） | **这次读不到枪上有没有用** | [反编译，只有名字] |

开火时主序列也不变（R-301 走路和站立，Wingman 滑铲 [实测]）。开火动作是叠加层还是程序层，**不知道**。

## 3. 每种移动时，主序列在干什么

R-301 的编号（Wingman 同样的结构，编号不同）。名字是**按出现时机推断**的，模型资源读不到。

| 状态 | 序列 | 时长 | 说明 |
|---|---|---|---|
| 站、走、蹲、蹲走、跳、下落、落地 | 34 | 一直 | 进度停在 1。就是关镜动画（ADS-CURVES：进度 = 1 − zf）的最后一帧，**腰射站姿就是关镜的终点** |
| 开镜 | 32 | 跟 zf | 进度 = zf |
| 冲刺 | 63 | 循环 0.556 s | Wingman 也是 0.557 s。没有单独的进入动画，从进度 0 开始 |
| 冲刺结束 | 28 | 0.30 s | Wingman 0.33 s |
| 冲刺中按滑铲 | 30 | 0.43 s | 两把枪相同。之后回到 34，**滑铲没有自己的枪动画** |
| 冲刺中起跳 | 28 | 0.30 s | Wingman 用另一段 0.57 s。空中回到 34，落地继续冲刺时循环从 0 开始 |
| 战术换弹 | 15 | 2.40 s | 等于 `reload_time` |
| 翻越 | 7 → 13 | 1.43 s，0.50 s | 13 的长度等于 `raise_time` 0.5（1 次，可能是巧合） |
| 上滑索 | 11 → 14 → 35 | 0.49、约 0.35 s，之后停住 | 下滑索 68 |
| 兴奋剂 | 6 → 12 | 0.14 s，之后持续 | 走路开火时 12 一直在 |

冲刺循环 0.556 s 和脚步对得上：N10 量到冲刺一步约 0.276 s，两步 0.552 s。**只在满速 260 下量过**，速度变化时循环是否跟着变，没测。`sprintcycle_time` 字段是 0，所以长度不来自这里。

**设计含义**：只有"手的姿势明显不同"才值得一段主序列。走路和滑铲都没有，只有冲刺有，因为冲刺时枪是放下来的。

## 4. 程序层：字段和实测对得上

### 4.1 走路晃动 bob

R-301 和 Wingman 字段相同。下表是走路满速（173.5）时的正弦拟合 [实测]。

| 量 | 字段 | 实测周期 | 实测幅度 |
|---|---|---|---|
| 上下摆动周期 | `bob_cycle_time` 0.4 | 俯仰 0.394–0.398 s | |
| 左右摆动周期 | | 横向、偏航、横滚 0.794–0.800 s，**正好两倍** | |
| 俯仰 | `bob_pitch` 0.75 | | ±0.44° |
| 偏航 | `bob_yaw` −1.7 | | ±1.48–1.51° |
| 横滚 | `bob_roll` 1.2 | | ±1.10° |
| 横向 | `bob_horz_dist` 0.1 | | R-301 ±0.22 u，Wingman ±0.35 u |

周期和字段一致。**幅度和字段同一量级，但不相等**（偏航 0.88 倍，横滚 0.92 倍，俯仰 0.58 倍），换算关系没有读出来。横向两把枪不同而字段相同，原因没查。

路径是"上下走两趟，左右走一趟"，也就是横放的 8 字。一步一次上下，两步一次左右。

**蹲走没有拟合成功**：速度只有 80，但摆幅和走路差不多（俯仰 ±1.47°，偏航 ±1.3°，横滚 ±1.15°），也不是干净的正弦。这和"按 `bob_max_speed` 缩放"的想法不符，**原因没查**。

### 4.2 移动和转向偏移 sway

一直按住前进时，枪整体往下、往后挪一点，这是 sway，不是 bob：

| 量 | 字段 | R-301 实测 | Wingman 实测 |
|---|---|---|---|
| 前进时向上 | `sway_move_forward_translate_z` −0.5 | −0.57 u | −0.56 u |
| 前进时向前 | `sway_move_forward_translate_x` −0.1 | −0.11 u | −0.10 u |

冲刺时这个偏移也几乎一样（R-301 −0.56 u，Wingman −0.57 u）。**所以它不随速度变大**，至少走和冲刺之间不变。

**有弹性**：停下后回到原位的时间常数 0.49–0.54 s，从 `sway_translate_gain` 2.5 算是 0.40 s。同一量级，公式**没有核对**（1 次）。角度回得快得多，约 0.1 s，`sway_rotate_gain` 是 7。

跳起时也走这一层，序列不变 [实测，R-301 1 次]：枪口先抬 1.5°（0.1 s），过顶后压到 −0.8°（0.5 s），落地后再抬 1.0° 回弹。枪的高度和垂直速度反向，滞后约 0.3 s：上升时往下沉，下落时往上抬，和字段 `sway_move_up_translate_z` −1、`sway_move_down_translate_z` +1 的方向一致。

所有枪字段里的这些数大多相同（看了 7 把：周期、距离、两个 gain 都一样）。**枪和枪的差别主要来自主序列和停放位置，不是这一层。**

### 4.3 开镜时

走路开镜，zf = 1 [实测]：

| | R-301 | Wingman | 字段（R-301） |
|---|---|---|---|
| 横滚 | ±0.22° | ±0.007° | `bob_roll_zoomed` 0.25 |
| 俯仰、偏航 | ≤ 0.01° | ≤ 0.001° | |
| 位置 | ≤ 0.02 u | ≤ 0.01 u | |

Wingman 的武器文件没有 `bob_roll_zoomed`，实测也接近 0，两者相符。代码上走路晃动在 `zoom_scope_frac_start` 之前线性淡出 [反编译，`0x14085bdb0`]。开镜后准星区域稳定，这是"开镜就准"的手感来源之一。

## 5. 换弹和移动同时发生

### 5.1 走路：直接相加

走路换弹和站着换弹，按同一播放进度相减 [实测，R-301 各 1 次]：

| 差 | 走路 | 冲刺中换弹 |
|---|---|---|
| 向上 | 平均 −0.48 u | 平均 −0.58 u |
| 向前 | 平均 −0.10 u | 平均 −0.17 u |
| 横向 | ±0.2 u | ±0.2 u |
| 偏航 | −2.0 到 +1.0° | ±1.5° |
| 横滚 | ±1.2° | ±1.3° |

差值就是 4.1、4.2 节的 bob 和 sway。**换弹序列本身没变，程序层原样加上去。**

冲刺中换弹时，冲刺循环不播，但差值和走路基本一样。所以**枪放下的姿势来自序列，一旦换弹占了序列，人跑得再快，手也是换弹的姿势**。

### 5.2 谁能切掉谁

序列记录 [实测，R-301，各 1 次]。这是对 C-MOTIONS §3 的补充，那里写"冲刺打断不了换弹"：

| 换弹中按的键 | 解锁前（0.5 s） | 解锁后（1.9、2.3 s） |
|---|---|---|
| 冲刺 | 不切。**解锁那一刻**（进度 0.65–0.68）切到冲刺循环 | **立刻切** |
| 开镜 | 不切，解锁后才开镜 | **立刻切**到开镜序列 |
| 开火 | 等解锁 | **立刻切**（C-MOTIONS） |
| 跳 | 不切 | 不切，播完 |
| 换枪、近战 | 切，没加弹 | 切，弹药保留（C-MOTIONS） |

换弹开始时正在冲刺，也是立刻进入换弹序列。C-MOTIONS 的结论没有错：冲刺不会让换弹失败。这张表说的是**动画**：解锁之后手就自由了，后面那段只是"没人要手的时候才播完"。

**规律**：解锁前，换弹占着手；解锁后，换弹动画优先级最低。跳不用手，所以从不切。

### 5.3 从冲刺到开火

| 枪 | 按开火到第一发 | 这时冲刺结束序列播到 |
|---|---|---|
| R-301 | 0.246 s | 0.76 |
| Flatline | 0.245 s | 0.69 |
| Spitfire | 0.247 s | 0.69 |
| Wingman | 0.184 s | 0.50 |
| P2020 | 0.141 s | 0.50 |
| Mastiff | 0.149 s | 0.40 |

结束序列**不会播完**，第一发一出就被切掉。这说明抬枪延迟和结束动画的长度是两回事：R-301 动画 0.30 s，能开火在约 0.23 s。比例也不统一，所以不能用"动画播到某个比例"来算。延迟的来源仍然没查清（C-MOTIONS §7）。客户端里有 `weapon_sprint_raise_delay` 这个名字，是候选，**值和用法都没读**。

## 6. 切序列为什么不跳

序列号换的那一帧，进度从 0 开始，但枪的位置连续 [实测]：冲刺进出全程，每帧最大位移 R-301 0.03 u，Wingman 0.07 u（约 7 ms 一帧）。说明序列之间有过渡。**过渡时长没有直接读到**。

进入冲刺时能看到形状，R-301 [实测]：0.2 s 内枪口压到 −1.3°、横滚到 −1.2°，约 0.5 s 接上循环。没有进入动画，却有一段自然的甩动，来自过渡和循环开头。

## 7. 镜头和枪分开

这部分已经在别的报告里，放在这里是因为它是同一条设计规则的另一半：

| 东西 | 动镜头 | 动枪 | 依据 |
|---|---|---|---|
| 走路 bob、sway | 不 | 动 | 本文，N10 |
| 冲刺的跑步晃动 | 动，俯仰约 ±0.3°，偏航 ±0.4° | 枪有自己的循环 | N10、CAMERA-REFERENCE |
| 翻越 | 动，镜头跟动画挂点，约 5° | 翻越序列 | CAM2 §3 |
| 开火 punch | 动 | 枪是另一套 jolt | RECOIL-VIEW |
| 冲刺倾斜、滑索倾斜 | 算一个比例，交给 pose parameter | | N2-C |

**同一个脚步节奏，镜头和枪各走各的幅度**：冲刺时镜头只晃零点几度，枪的角度变化有几度。玩家看世界很稳，只有手在动。

TF2 的泰坦也是这个思路：骨盆起伏 15.5 u，第一人称镜头只晃约 0.4 u（TITAN-POSE-CAMERA §4.1，TF2 数据，不是 R5）。

## 8. 从数据读出的设计理念

**这是我们的解读，不是 Respawn 的说法。**

1. **动作和移动分两层，组合就不用做了。** 换弹 × 走、蹲、跳、滑铲，全靠相加得到。动画量只和"手的动作数"有关，不和"动作 × 移动"的组合数有关。
2. **主序列只给手的姿势明显变化的情况。** 走路、跳和滑铲都不换，只有冲刺换。
3. **手是一种资源。** 换弹占手到解锁为止，之后一切要手的动作都能立刻抢走。跳不用手，从不打断。
4. **玩家的操作优先于动画播完。** 尾巴上那段只在没人要手时才播。
5. **小运动全用少量字段控制。** 多数枪的 bob 和 sway 一样，手感靠一组值统一，枪的个性放在主序列和停放位置。
6. **越需要瞄准，程序运动越少。** 开镜几乎归零。
7. **世界稳，手动。** 镜头只拿很小一部分运动。

## 9. Unity 现在的样子

看的是 `wp3-weapon-unity` 工作树（`combat/wp4-reload-swap`，2026-11-03），**另一个会话还没提交的改动**，以后可能变。这次没有改 Unity。

| 项 | R5 | Unity 现在 |
|---|---|---|
| 换弹动作 | 动画 + 程序层 | `HeldMotion`：枪走实测枪口路径，加上 [guess] 的展示姿势和弹匣动作。时间点用 C-MOTIONS |
| 冲刺、抬枪 | 循环序列 + 结束序列 | `lowered` 一个比例，枪放下，[guess] |
| 走路 bob | 按字段 | **没有** |
| sway | 按字段，有弹性 | **没有** |
| 开镜时收掉程序层 | 淡出 | 换弹动作按 `1 − zoom` 收，其他没有 |

这些差别**还没有写进 `R5-DIFF-ARCHIVE.md`**，要等这部分代码提交时一起写，也要用户决定做不做。

### 新动作照这个做

做新的枪或动作时，可以照着这几条检查，和 DESIGN-PHILOSOPHY §9 一起用：

- [ ] 手的姿势有明显变化吗？没有就不要加主序列，用程序层。
- [ ] 它和走、跳、滑铲同时发生时，能靠相加得到吗？不要做组合动画。
- [ ] 它什么时候开始不再需要手？那一刻之后，开火、开镜、冲刺都要能立刻切掉它。
- [ ] 不用手的动作（跳）不打断它。
- [ ] 开镜时它的程序运动收掉了吗？
- [ ] 镜头是不是只拿了很小一部分？
- [ ] 切换时位置连续吗？

如果 Unity 要补程序层，最值得先做的是 bob 和 sway：周期和偏移都有 [实测]，代价小。幅度的换算没读出来，先用第 4 节的实测值，并标明。

## 11. 复现

```bash
py -3 -I an_sequences.py <HSD-RawData>/apex/research/combat/gun-measure > OUT-sequences.txt
py -3 -I an_fits.py <HSD-RawData>/apex/research/combat/gun-measure > OUT-fits.txt
```

两个脚本在 [movement-anim/](movement-anim/)，输出也在那里。数据来自 `combat/gun-measure`（PR #95）的 `s3`、`s4` 两个会话。反编译的函数：`0x14085a3c0`（pose parameter）、`0x14085ab80`（序列进度 = zf）、`0x14085bdb0`（走路晃动淡出）、`0x1405fc020`（sway），基址 `0x140000000`，反编译结果留在本地，不进仓库。
