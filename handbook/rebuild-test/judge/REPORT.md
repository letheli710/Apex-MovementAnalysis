## 2. 唯一的手册错误：07 §1.4 的随机种子

**现象**：L1_50 / L1_200 / L1_400 落地命令（tick 42 / 87 / 123）的俯仰随机数，重建方和 Unity 只差一个符号：

| 命令 | 混合后的种子最高位 | Unity r | 重建 r |
|---|---|---|---|
| 42（L1_50 落地） | 1 | −0.4159 | +0.4159 |
| 61（L1_100 落地） | 0 | −0.1466 | −0.1466 |
| 87（L1_200 落地） | 1 | −0.0040 | +0.0040 |
| 123（L1_400 落地） | 1 | −0.2723 | +0.2724 |
| 30（L2 起跳，'vpJX'） | 1 | −0.1636 | +0.1636 |

**原因**：`R5SharedRandom.RandomFloat` 把 Jenkins 混合的结果当**有符号 32 位整数**，< 1 时先取反（−seed），还 < 1 就用 0xbc8f，然后用 Schrage 方法算 48271·seed mod (2³¹ − 1)。重建方照手册把它当无符号数直接取模。最高位是 1 时 −seed ≡ 2³² − seed，48271·(−seed) mod (2³¹−1) 正好和无符号算法的结果关于 2³¹ 对称，所以 r 变号。随机数取 0 时镜头完全一致，所以除了这一处，07 章的 kick 公式、弹簧、落地速度定义全对。

**要改的句子**（07 §1.4"规则和公式"第 3 步）：

> 3. next = 48271 · seed mod (2³¹ − 1)（Park–Miller），r = −0.5 + min(next / 2³¹, 0.99999988)（单精度）。

改成：

> 3. 把 seed 当**有符号** 32 位整数 s：s < 1 时 s ← −s；如果还 < 1（s = 0 或 −2³¹），next = 0xbc8f；否则 next = 48271·(s mod 44488) − 3399·⌊s / 44488⌋，< 0 时加 2³¹ − 1（Schrage，等于 48271·s mod (2³¹ − 1)）。r = −0.5 + min(next · 2⁻³¹, 0.99999988)，乘法和加法用单精度。例：命令 42、盐 0x76704c58 → r = −0.4159；命令 61 → −0.1466。

同一节顺带补三句（重建方 GAP-19 猜对了，但都是猜的）：第 1 步"第 6–9 字节"后加"（从 0 数，小端）"；第 2 步加"初值 h = 0，每字节 h += b; h += h << 10; h ^= h >> 6"；加一条"重建 / 新游戏里的命令号 = 从 0 起的命令计数（本检验用 tick）；要对 R5 录像时才用 R5 的 usercmd 号"。

## 5. 结论

- 04 章的滑铲（§4.1 – §4.7）、斜坡（§4.5）、滑铲跳（§4.6）、眼高（§4.8），03 章的地面 / 空中 / 起跳 / 落地，07 章的弹簧和落地 kick 公式，**只看手册就能逐命令重建**：凡是规则本身，没有一处错。
- 唯一的错是 07 §1.4 的随机种子符号（§2），一句话能改。
- 题目要改 S5、L2、S4 三处（§3）。
- §4 的 14 条是"写死以免猜错"，建议 hb-integrate 一次改完。改完以后建议用同一套题、改过的 S5 / L2 再跑一轮：按现在的数据预计 10 / 10。
