# TF2 研究总报告与 Unity 改动提案（T6）

日期：2026-10-29。本报告收尾 TF2 研究计划（[TF2-PLAN.md](TF2-PLAN.md)），把 T0–T5 的结论压成一份，并列出给 HSD-Unity 的改动提案。

- **提案只是提案。** 每一项都要你单独批准；批准后另外安排实现，本计划不改 Unity。
- **R5 仍是基准。** 所有 TF2 来源的功能都做成开关，默认关；Reference 配置和 R5 回放不受影响。
- 细节和证据：规则对照见 [TF2-VS-APEX.md](TF2-VS-APEX.md)，TF2 实现见 [TF2-MOVEMENT-SUMMARY.md](TF2-MOVEMENT-SUMMARY.md)，实测见 [runtime/T5-REPORT.md](runtime/T5-REPORT.md)，逐项账本见 [ledger/ledger.csv](ledger/ledger.csv)。

## 1. 结论

1. **Apex 的移动代码几乎全部来自 TF2。** 地面、空中、滑铲、lurch、镜头的代码结构相同，41 项对照里只剩 1 项（攀爬公式 T-M01）没有定论。两边的手感差异主要来自三件事：
   - 参数不同：Apex 的冲刺加速段只有 100（TF2 一档 2500 到底），跳得更低（56 u vs 75 u），减速 1250 vs 1500。
   - Apex 收紧了连跳：窗口 0.1 → 1.0 s，每跳 −12 → −100，最低 450 → 冲刺上限，另外加了 antiMultiJump 和硬着陆减速。TF2 bhop 能保速、Apex 不能，就是这个原因。
   - Apex 关掉了蹬墙跑和二段跳。代码都还在，只是 setfile 里关了。
2. **TF2 的蹬墙跑规则已经完整读出并实测。** R5 里的同一套代码和残留数值也已查清，所以 HSD 可以有一个"有原版依据"的蹬墙跑，替代 M7 的纯设计版。
3. **实测发现的几处 Apex 改动**（静态时没看出来）：
   - TF2 的加速不乘移动倍率，Apex 乘；
   - TF2 的滑铲跳不抬速，Apex 抬到 350。
4. **TF2 独有、值得做成开关的**：蹬墙跑（两套数值）、TF2 二段跳、TF2 连跳、TF2 兴奋剂。其余（地面加速段、跳跃高度、滑铲减速）只作手感参考，不建议做开关，因为它们和 R5 基准直接冲突。

## 3. 实测更正的静态结论

| 项 | 静态结论 | 实测（2026-10-29） |
|---|---|---|
| 加速和减速乘不乘移动倍率（T-G04） | 都乘 player+0x1600，不知道它是什么 | 都不乘：ADS 和兴奋剂只改速度上限。Apex 的加速乘 msc，归"改过" |
| 滑铲跳（T-S06） | 速度上限 350 | 水平速度不变，350 不起作用；Apex 抬到 350 并返还加速，归"改过" |
| 蹬墙跑起跑提速 | 提到至少 250 | vz' = min(250, vz + 250)；而且只在跳起后贴墙时有（掉落贴墙没有，重力爬升也没有） |

## 4. 蹬墙跑：三套版本的数值

用户决定（2026-10-28）：**B 是基准，A 做成可开关的预设**。M7 是现在 Unity 里的设计版。

| 项 | A：TF2 原版（MP） | B：TF2 规则 + R5 残留值 | M7（现状，[design]） |
|---|---|---|---|
| 起跑条件 | 空中、朝墙移动、脚离墙 ≤ 13；不需要按键，没有速度下限 | 同 A，贴墙距离 17 | 按住 W、沿墙 ≥ 200、下坠 ≤ 450、视角条件 |
| 起跑提速 | vz + 250，最多到 250；只在跳起后 | 同 A（R5 `wallrunUpWallBoost` 250；R5 代码同一公式，R-1） | vz 夹到 [60, 150] |
| 重力 | 从起跑开始 0 → 满重力线性爬升，0.7 s | 爬升 1.0 s（R5 `wallrunGravityRampUpTime` 1） | 恒定 0.15 g |
| 水平上限 / 加速 | 420 / 1500（实际被摩擦压到约 375） | 225 / 200 | 300 / 400 |
| 竖直上限 / 加速（按前进时向上） | 225 / 360，向上输入 0.65 | 112 / 450 | 无 |
| 摩擦 / 减速 | 4 / s 指数摩擦；无输入时 70% 的下坠不受摩擦 | **没有摩擦**（R5 没有 `wallrunFriction`），改为线性减速：无输入时水平 500；竖直 300（下坠时乘 (1 − 重力系数)(1 − 滑落)）（R-1） | 超速时 60 u/s² |
| 朝后上限 | 50 | 50 | 无 |
| 时长 / 滑落 | 1.75 s；1.5 s 开始滑落，1 s 到满 | 2 s；滑落参数同 A | 1.6 s，无滑落 |
| 墙跳 | 离墙 ≥ 205、输入方向 80、vz = min(230, vz + 345)，原沿墙速度保留 | 188 / 75 / 240 | 法线 280、vz 300、上限 480 |
| 同一面墙 | 只能在上次接触点以下重贴 | 同 A（R5 `wallrunSameWallHeight` 0） | 落地前不能重贴 |
| 二段跳恢复 | 起跑时恢复 | 同 A | 同 |
| 视角侧倾 | 15°，速度 6，提前 0.25 s | 10° | 只在离墙时 |
| Apex 新增限制 | — | 接触点比起跳高度高约 147（175 − 28）以上不能起跑；法线 z 下限 −0.5（TF2 −0.35）；按蹲脱墙。公式见 [wallrun/R1-R5-WALLRUN-KEYS.md](wallrun/R1-R5-WALLRUN-KEYS.md) | — |

R5 值来自 N4-A 的 classvar 普查（`Apex-MovementAnalysis/research/phase2-local/data/20261023_200358_N4A_classvars/report/census.csv`）。这一步顺带关掉了 T3 未解项 4：R5 的爬升时间是 1 s，同墙高度是 0。

## 5. Unity 改动提案

每项给出：做什么、依据、放在哪、对 Reference 的影响、我的建议。提案编号用于批准。

### P-01 蹬墙跑"TF2 规则"模式，带 B / A 两套数值

- **做什么**：在 `WallRun/WallRunAbility.cs` 加一个规则模式枚举：`M7Design`（现状）、`Tf2Rules`。`Tf2Rules` 按第 4 节的规则实现：
  - 起跑条件、提速（只在跳起后）、从起跑算的重力爬升、摩擦和滑落；
  - 按前进时向上推、朝后上限、时长；
  - 墙跳公式、同墙高度规则。
  - 数值做成两个预设：`WallRunParams.Tf2B()`（R5 残留值）和 `WallRunParams.Tf2A()`（TF2 MP 值）。
- **依据**：T3 第 2 节的静态规则 + T5 第 5 节实测；B 的数值来自 R5 普查。
- **默认**：Reference 仍是关。Fun 配置在你决定前保持 M7，不自动换掉。
- **影响**：只影响打开跑墙的会话；回放和 Reference 逐字节不变。
- **前置**：
  - B 里 Apex 新增的 5 个键已读（R-1，[wallrun/R1-R5-WALLRUN-KEYS.md](wallrun/R1-R5-WALLRUN-KEYS.md)）：B 用 R5 的线性减速，不用 TF2 的摩擦 4。
  - "提速只在跳起后"的开关条件是推断 [inf]。实现时按"上次着地后是否起跳过（含墙跳）"处理，并在 README 里标注。
- **建议**：做。这是 TF2 研究最主要的产出，也是计划第 0 节"补 R5 缺的原版实现"的第一项。

### P-02 二段跳"TF2 规则"预设

- **做什么**：在 `DoubleJump/DoubleJumpAbility.cs` 加 TF2 规则：
  - vz 直接设为 √(2·g·H)，替换下坠速度（现状是 max(vz, …)）；
  - 水平"沿现速度扣 180，再沿输入加 180"，慢于 180 时整个换成输入方向 × 180（现状是"转一半"）；
  - 没有"离地 0.1 s 后"限制。
  - 两组数值：TF2（H 60 → vz 300，水平 180）和 R5 残留 Sparrow 值（`superjumpMinHeight` 112 / `MaxHeight` 200 / `HorzSpeed` 240）。
- **依据**：T3 2.6 + T5 5.5（水平规则逐帧吻合）。
- **默认**：Reference 关；Fun 保持现状，等你选。
- **未验证**：TF2 里"已在上升且余量足够时只叠加 0.25H"的分支 T5 没触发，可以先照静态规则实现，标为未实测。
- **建议**：做，和 P-01 一起，因为 TF2 的蹬墙跑起跑会恢复二段跳，两者是一套。

### P-03 "TF2 连跳"开关

- **做什么**：给电机的原生 skip 规则（`R5MotorV2Params.groundJumpSkipTime/Reduce` 和下限 R）加一个 TF2 预设：
  - 窗口 0.1 s、每跳 −12、下限 450、窗口内跳高 ×0.75；
  - 同时关掉 antiMultiJump 和硬着陆减速（TF2 没有这两项）。
- **依据**：T-J03，T5 4.4 实测完全吻合；R5 侧规则已在 N7 原生化。
- **默认**：关。Apex 玩家对 bhop 很敏感，只作为单独开关。
- **影响**：这是改电机参数，打开后地面手感明显偏离 R5 基准，所以只在会话开关里出现，不进任何默认配置。
- **建议**：做，但优先级低于 P-01、P-02。

### P-04 兴奋剂"TF2 预设"

- **做什么**：`Stim/StimAbility.cs` 增加 TF2 预设：速度上限 ×1.8，持续 3 s，冷却 25 s，加速和减速不变。
- **依据**：T5 4.1 实测（走 312.3、冲刺 468，加速 2500 不变）。
- **冲突**：SKILL-RULES §4 的加速上限是 ×1.40，×1.8 会被压掉。要么给这个预设开例外，要么接受 ×1.40。另外 Unity 现在沿用 R5 的 `speed_boost`（加速也跟着倍率变），TF2 预设要单独处理"只改上限"。
- **建议**：先不做，只作手感参考。等 P-01–P-03 用过之后再看有没有需要。

### P-05 蹬墙跑视角侧倾

- **做什么**：跑墙时镜头朝墙外侧倾，最大角度 B 10° / A 15°，速度 6，提前 0.25 s 开始（现在只在离墙时有滚转）。
- **依据**：T3 2.2（client.dll）、T2 T-C08；R5 ConVar 是 10°。
- **注意**：镜头属于 M5.5 / N8-CAM 的范围，你对镜头有单独的验收流程，所以单列。
- **建议**：随 P-01 一起做，作为 P-01 的子开关。

### P-06 挂墙（wall hang）

> **用户决定（2026-10-29）：留存，低优先。**
>
> 用户的想法（2026-10-29）：理性上看，挂墙现在用不上，以后也不一定需要；但直觉上觉得应该把它留着，等以后想到这个方向时有东西可以接着做。可能的方向是把它做成游戏里的道具（或被动），到时候会用到这个功能。对现在的 HSD 帮助不大，可以开一个分支去研究，但不重要，不是高优先级。
>
>以后想做时单开一个分支：先在 TF2 实测（需要带 `pas_wallhang` 被动的职业），再写提案。不进当前的实现。

- **做什么**：ADS 键挂墙。0.5 s 内停住，3 s 后开始下滑，4 s 掉落；手离墙 ≤ 18。
- **依据**：只有 T3 静态规则，T5 没测（需要 `pas_wallhang` 被动）。
- **建议**：暂不做。和现有"抓边悬挂"（ledge hang）不是一个机制，而且没有实测依据。
