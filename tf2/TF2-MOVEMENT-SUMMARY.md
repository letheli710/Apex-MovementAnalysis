# Titanfall 2 铁驭移动：研究汇总

2026-10-28。逐个动作说明 TF2 是怎么实现的、用了哪些数值。和 Apex 的对比另见 [TF2-VS-APEX.md](TF2-VS-APEX.md)。

**范围和来源**

- Titanfall 2 v2.0.11，Northstar 1.31.14。
- 静态分析，数值来自三层，后一层覆盖前一层：
  1. 代码默认值（`server.dll` 里的设置表）
  2. 玩家设置文件 `pilot_base.set` → `pilot_mp.set`
  3. ConVar，再加上 MP 模式的 `spmp.cfg` 覆盖
- 函数地址都是 `server.dll` 的（镜像基址 0x180000000）。
- ⚠ 表示推断或需要实测确认。
- 2026-10-29 起，大部分规则已在游戏里实测（T5，[runtime/T5-REPORT.md](runtime/T5-REPORT.md)），标"T5 ✓"。和静态结论不一致的地方注明了更正日期。

**符号**

- `dt`：一帧的时间。
- `h`：水平速度。
- `v`：速度向量。
- `msc`：移动倍率，等于主武器和副武器的 `move_speed_modifier` 相乘，再乘状态效果（兴奋剂、减速）。

## 0. 每帧的流程

```
PlayerMove (0x180179950)
 └ 按移动类型分派：
    ├ 走路/空中（类型 2）→ 如果正在翻越 → TraversalMove (0x180180780)
    │                     否则 → 空中外壳 (0x18016a9f0)：
    │     1. 重力半步：v.z −= ½ · g · gravityScale · dt · 蹬墙重力系数
    │     2. Jump (0x180172870)
    │     3. 蹬墙检测 / 维持 / 脱落 (0x180186d60)
    │     4. 钩爪 (0x18016fa80)，绳索 (0x18017f640)
    │     5. 有"地面"（包括正在跑的墙）→ 地面/墙面移动 (0x180185230)
    │        没有 → AirMove (0x180161170)
    │     6. 落地判定 (0x180163830)，再一次重力半步
    ├ 滑索（类型 0xc）、noclip（9）、观战（10）等
```

**关键设计**：蹬墙跑不是单独的移动模式。跑墙时，墙被当成"地面实体"，走的是地面移动函数，只是换成蹬墙跑的参数。

## 2. 走路、冲刺、停下（地面）

实现在地面/墙面移动 `0x180185230`，按顺序：选加速度 → 摩擦 → 加速。

### 2.1 加速度选择（`0x18016ea60`）

```
滑铲中：                                   accel = slideAccel (50)
否则如果 sprintAcceleration ≥ 0 且 h > msc·speed − 1：  accel = sprintAcceleration
否则如果 lowAcceleration ≥ 0 且 h < msc·lowSpeed：      accel = lowAcceleration
否则：                                     accel = acceleration
accel ×= player+0x1600（T5：ADS 和兴奋剂下都是 1，不是移动倍率）
```

MP 铁驭：`lowSpeed`、`lowAcceleration`、`sprintAcceleration` 都是 −1（关），所以 **accel 始终是 2500**。

T5 ✓：走路、冲刺、ADS（上限 86.75）、兴奋剂（上限 312.3 / 468）下加速都是 2500，减速都是 1500。**移动倍率只乘速度上限，不乘加速和减速**（R5 的加速乘 msc，这点 Apex 改过）。

### 2.2 减速度选择（`0x18016eda0`）

```
decel = −1
h > msc·speed 时：      decel = sprintDeceleration；还是 −1 就用 sprintAcceleration
滑铲中：                松开蹲或反向输入用 slideWantToStopDecel (400)，否则用 slideDecel (50)
仍 < 0：                decel = deceleration
仍 < 0：                decel = acceleration × 0.6
decel ×= 冲击低摩擦系数 × player+0x1600
```

MP 铁驭：**decel = 2500 × 0.6 = 1500**。

### 2.3 摩擦（`0x1801696b0`）

1. 速度在输入方向上的分量会保留，最多保留到目标速度，不受摩擦。所以边走边转不掉速。
2. 其余部分：`s' = max(0, s − decel · 表面摩擦 · 摩擦倍率 · dt)`。
3. 滑铲中，结果再乘 `slideVelocityDecay ^ ((1 − 0.75·x) · dt)`。

`sv_friction`（4）只在 noclip 和观战移动里用，正常走路不用。

### 2.4 加速（`0x180160230`）

```
add = wishspeed − v·wishdir
如果 add > 0：v += wishdir · min(add, accel · dt · 表面摩擦)
然后 |v| ≤ max(加速前的 |v|, wishspeed)
```

最后一步的意思是：转弯可以改方向，但不能凭空提速。

### 2.5 冲击后的低摩擦（`0x1805dd500`）

受到冲量（击退、爆炸）后，记下 T = 现在 + |冲量| × `impulse_low_decel_duration_scalar`（0.003）。
- T − 0.5 s 之前：减速为 0。
- 之后线性恢复，到 T 时恢复满减速。

蹬墙跑的摩擦也受这个系数影响。

### 2.6 速度倍率（`0x1805d2510`）

```
msc = 主武器倍率 × 副武器倍率 × player+0x1e90 × (1 − 减速效果) × 加速效果
```

武器倍率：ADS 时用 ADS 倍率。**这个函数里有 Denuvo 防篡改触发器（`Denuvo_SlowSpeed`）**，检测到篡改会降速。

## 3. 空中

### 3.1 AirAccelerate（`0x180160f40`）

```
wishspeed = 输入大小 · msc · airSpeed (60)
add = wishspeed − v·wishdir
add > 0：  v += wishdir · min(add, airAcceleration (500) · dt)        ← 不乘 wishspeed
add ≤ 0：  v += wishdir · player_extraairaccelleration (2.0) · dt
          然后 |v| ≤ max(原 |v|, wishspeed)                             ← 3D 速度上限
```

第二个分支的引擎说明是"帮助开始蹬墙跑"。它让你即使已经很快，也能慢慢把方向扳向墙。

### 3.2 lurch：起跳后的方向修正（在 AirMove `0x180161170` 里）

TF2 叫"keyboard grace"。

| 参数 | ConVar | 值 |
|---|---|---|
| 满强度窗口 | `jump_keyboardgraceperiodmin` | 起跳后 0.2 s |
| 强度降到 0 | `jump_keyboardgraceperiodmax` | 0.5 s |
| 强度 | `jump_keyboardgrace_strength` | 0.7 |
| 速度改变上限 | `jump_keyboardgrace_max` | 0.7 × msc × 冲刺速度 |

规则：
1. 起跳后的窗口内**新按下**方向键时触发（T5 ✓：起跳前按住的键不触发）。
2. 把水平速度方向朝"按键方向"插值，速度大小不变。
3. 每次修正的速度改变量不超过上限。

T5 ✓：起跳后 0.11 / 0.31 / 0.46 / 0.61 s 新按右键，反推强度 0.70 / 0.437 / 0.097 / 0，和 0.7 → 0（0.2–0.5 s 线性）吻合；速度大小不变。

## 4. 跳跃

### 4.1 普通跳（`Jump` 0x180172870）

```
v.z = √(2 · g · gravityScale · H)
H = jumpHeight (60)；滑铲中用 slideJumpHeight (50)
```

注意 g 用的是 `sv_gravity`（750），**不乘 gravityScale**；gravityScale 0.8 只用在下落（重力半步）。

MP 铁驭：v.z = √(2·750·60) = **300 u/s**（T5 ✓：记录值 293.7，等于 300 减去起跳帧的记录偏移），下落重力 600，理论最高 75 u。

### 4.2 落地后马上再跳（skip）

```
如果 现在 − 落地时间 < skip_time (0.1 s) 且 不在蹬墙跑：
    H ×= skip_jump_height_fraction (0.75)
    如果 h > skip_speed_retain (450)：
        h = max(450, h − skip_speed_reduce (12))
```

`skip_replenish_double_jump` 1：这种连跳也会恢复二段跳。

T5 ✓：落地后 0.007 / 0.063 / 0.090 s 起跳都触发（−12、高度 ×0.75），0.131 s 不触发；460 → 450，440 不变。注意落地帧起就有正常地面摩擦（约 1500 u/s²），只有落地当帧起跳才几乎不丢速。

### 4.3 二段跳（Jump 的 superjump 分支）

| 参数 | 值 |
|---|---|
| 次数 `superjumpLimit` | 1；落地、蹬墙跑起跑时恢复 |
| 高度 `superjumpMin/MaxHeight` | 60 / 60 |
| 水平 `superjumpHorzSpeed` | 180 |
| 最低高度比例 `superjump_min_height_fraction` | 0.25 |

```
高度：如果正在上升，且"现有能升的高度 + 0.25·H"已经 ≥ H：只叠加 0.25·H
      否则：v.z 清零，按 H 起跳（v.z = 300）——下坠会被直接取消
水平：有输入时，从现有水平速度里扣掉 180，再沿输入方向加 180（T5 ✓：(166.1, 200.4) → (231.2, 61.8)，预测 (231.3, 61.8)）
```

水平规则的效果：
- 原来比 180 快：等于把 180 u/s 转向输入方向。
- 原来比 180 慢：整个换成"输入方向 × 180"。

## 5. 滑铲

### 5.1 起滑（`0x180183180`）

| 条件或效果 | 规则 |
|---|---|
| 位置 | 在地面上（`slide_whileInAir` 0） |
| 速度 | h ≥ `slideRequiredStartSpeed` 200 |
| 方向 | 移动方向和视角夹角 ≤ 53°（`slide_max_angle_dot` 0.6） |
| 加速 | 距离上一次**起滑**超过 `slide_boost_cooldown` 2 s 时：h' = min(h + 150, 400)，只在变快时生效 |
| 冷却计时 | 每次起滑都会重新计时，包括没有拿到加速的那次 |

### 5.2 滑行

| 项 | 规则 |
|---|---|
| 减速 | `slideDecel` 50 |
| 速度衰减 | 每秒保留 `slideVelocityDecay` 0.7 |
| 松开蹲或反向输入 | 减速改为 400 |
| 转向 | 按 `slideAccel` 50 加速，只能改方向 |
| 结束 | h < 125（`slideStopSpeed`）时结束；h > 350 时不会结束 |
| 上台阶 | 每单位台阶高度减速 10（`slide_step_velocity_reduction`） |

### 5.3 滑铲跳（slide hop）

- 跳跃高度 50（`slideJumpHeight`）。T5 ✓（vz 273.9）。
- `slideMaxJumpSpeed` 350：**T5 实测不起作用**（2026-10-29 更正）。滑铲跳时水平速度在 251、354、389 都保持不变，既不抬到 350 也不封顶，也没有加速返还。

配合 4.2 的连跳规则（每次只扣 12，扣到 450 为止），"滑铲 → 跳 → 落地马上滑铲"可以维持很高的速度。这应该就是 TF2 slide hop 的来源 ⚠。这是从规则推出来的，还没实测；而且滑铲加速有 2 s 冷却，连续 hop 时拿不到每次的 +150。

## 6. 蹬墙跑

### 6.1 起跑条件（`0x180174890`）

1. 在空中，职业有 `wallrun 1`，`wallrun_enable 1`。不在滑索或梯子上。
2. 某个计时 < 0.5 s 时不能起跑 ⚠。T5 已排除"离地时间"：跳起后 0.09 s 就能起跑。它计的是什么仍未知。
3. 墙面法线 z 在 [−0.35, 0.7]。
4. 正在朝墙移动（`wallrun_minAngle_air` 180°，即半角 90°）。
5. 脚离墙 ≤ 13 u（`wallrun_allowed_wall_dist`）。
6. 同一面墙（法线点积 > 0.9）：只能在上次接触点以下重新贴。
7. 不需要按键，也没有最低速度要求。
8. 失败后每 0.07 s 再试一次。

### 6.2 起跑瞬间（`0x1801835c0`）

- 竖直速度 **vz' = min(250, vz + 250)**（`wallrun_upWallBoost` 250）。2026-10-29 按 T5 更正，原写"提到至少 250"。下坠中贴墙只加 250（−114 → 134），不会直接变成 +250。
- T5 新发现：**只有跳起后（包括墙跳后）贴墙才有这次提速和下面的重力爬升**。传送到空中（相当于从边缘掉下）贴墙时两者都没有，第一帧就是满重力。推测由"着地后跳过"一类的标志控制 [inf]。
- 二段跳次数恢复。
- 蹬墙次数 +1（用于强度衰减，阈值 1000 次，实际不会触发）。

### 6.3 跑墙中（地面/墙面移动 `0x180185230`，重力 `0x180186c70`）

| 项 | 规则 | MP 值 |
|---|---|---|
| 重力 | 系数 = t ÷ 爬升时间，从 0 线性升到 1，之后满重力。t 从起跑算（T5 ✓：反推 41 → 598，t = 0.03 → 0.71 s） | 爬升时间 0.7 s |
| 摩擦 | \|v\| ×= (1 − wallrunFriction · dt) | 4 |
| 输入映射 | 前后左右映射到墙面平面；按前进时额外加"向上输入" = 前进量 × 0.65（`wallrun_upwardAutoPush`） | |
| 水平加速 | 朝上限加速（× msc）；输入和视角朝后（点积 ≤ −0.6）时上限改为 50 | 上限 420，加速 1500 |
| 竖直加速 | 朝上限加速，滑落越多越弱 | 上限 225，加速 360 |
| 滑落 | 1.5 s 后开始，1.0 s 内线性到 1；没有输入时至少 0.7。滑落时下坠速度不受摩擦 | |
| 视角侧倾 | 最大 15°，速度 6，提前 0.25 s 开始 | |

### 6.4 结束（`0x180186d60`）

| 触发 | 结果 |
|---|---|
| 跑满 `wallrun_timeLimit` 1.75 s | 脱落（被动 `pas_wall_runner` 延长 2.5 s） |
| 朝外推超过 0.05 s | 脱落 |
| 墙没了 | 沿法线推出 70 u/s |
| 快到墙顶且在上升 | v.z 按 3000·k 减速，不会冲出墙顶 |
| 墙面转折超过 cos 0.8（约 37°） | 脱落 |

### 6.5 墙跳（`0x180173a00`）

```
水平 = 输入方向 · 80 (wallrunJumpInputDirSpeed)
离墙分量补到至少 205 (wallrunJumpOutwardSpeed)
    视角和输入都朝墙时，205 最多减 80%
竖直：v.z = min(230, v.z + 1.5 · 230)
把上面的结果加到原速度上（原来的沿墙速度保留）
之后 0.2–0.4 s 不能贴回同一面墙（wallrun_repel*）
```

### 6.6 挂墙

| 项 | 规则 |
|---|---|
| 触发 | ADS 键（需要 `pas_wallhang` 被动） |
| 距离 | 手离墙 ≤ 18 u |
| 停住 | 0.5 s 内速度降到 0 |
| 下滑 | 3 s 后开始，1 s 到满 |
| 掉落 | 4 s（`wallrun_hangTimeLimit`；`pas_wall_runner` +21 s） |

### 6.7 废弃参数

`wallrun_slipvel`、`wallrun_slipslowdown`、`wallrun_hangslipvel` 三个 ConVar 在客户端和服务端都没有任何代码读取。
