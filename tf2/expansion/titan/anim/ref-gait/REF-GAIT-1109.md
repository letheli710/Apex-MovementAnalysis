# 泰坦步态补测（ref-titan-gait，2026-11-09）

本地 Northstar 1.31.14 私服实测，中型（Ion，`titan_atlas`）。只借规则和数值。原生规则来自同批会话 `ref-titan-native`（研究仓库 PR #111，[`../ref-native/REF-NATIVE-1109.md`](../ref-native/REF-NATIVE-1109.md)），这里用实测去核对。路径写法：工作区 `TF2-Research/…` = 仓库 `tf2/…`。

## 先说结论（白话）

1. **A2 走和跑：按速度换，门槛是站姿速度的 0.45 倍（中型 112.5 u/s）。** 实测 110.8 u/s 还是走片段，112.7 u/s 已经是跑片段。所以泰坦满速 250 u/s 走路时，**身上播的是跑片段，不是走片段**。冲刺片段只看冲刺键，不看速度：按下后 0.06–0.08 s 换上，跑→冲刺交叉淡入 0.56 s。原来"跑片段只出现在 250→380 冲刺加速段"的推断不对。
2. **A6 / F7 停步：起作用的是待机的混入 0.2 s，不是走的混出 0.55 s。** 松键后速度 0.07–0.35 s 到 0；到 0 之后 0.02–0.07 s 主序列换成待机；再过约 0.2 s 身体回到待机姿势（< 1 u）。32 次停步，0.2 s 模型的误差只有 0.55 s 模型的约 1/3.5。规则是"混合时长 = min(旧序列混出, 新序列混入)"，同样适用于起步（待机→走也是 0.2 s，不是 0.95 s）。
3. **F6 播放速度：v ÷ 片段地速，但有 0.15 的死区。** 只有新算出来的值和当前值差超过 0.15 才改写，所以匀速走时播放速度停在"加速过程中最后一次改写的值"，比目标慢最多 0.14（或在减速来的时候快最多 0.08）。同样 250 u/s，不同次测到的周期在 1.35–1.60 s 之间；160 u/s 从下面加速上来是 0.424，从上面减速下来是 0.600。速度低于 61.5 u/s（走）时播放速度停在下限 0.25。**脚会滑**：滑速 = |v − 播放速度 × 地速|，实测和这个式子对得上。
4. **F20 斜坡和台阶：脚 IK 只在身体被画出来时才做。** 第三人称下站立脚贴着 9° 坡面（脚高随前后位置的斜率 ±0.045 以内，不贴地应为 ±0.16–0.19），踏上 11 u 台阶的脚被抬到台阶上；第一人称下自己的身体不做 IK，脚会插进坡里或悬空。台阶是碰撞体一个 tick 迈上去，身体有平滑、不跟着跳。上坡骨盆比平地低约 11 u（下坡约 2 u），两种视角一样，不是 IK 做的，原因没查清。脚掌转到坡面法线没确认；13°、17° 的陡坡没测成。
5. **测量上的两个发现（以后测 TF2 泰坦都会碰到）：** 第一人称下自己的泰坦身体每 7 帧（约 0.049 s，约 20 Hz）才重新摆一次姿势，交叉淡入期间才每帧摆；`mp_homestead` 上第一次出生是运兵船空降，空降后上机的泰坦不能移动，要先让铁驭死一次。

## 1. F6：播放速度随移动速度怎么变

**规则（原生，`ref-titan-native`；实测全部符合）：**

```
目标 = clamp(v ÷ 地速(当前片段), 0.25, 10)；冲刺再 ≤ 1.25
     v = 水平速度；地速是当前主序列的地速（直走时 move_yaw = 0）
只有 |目标 − 当前| > 0.15 才把当前改成目标；否则不变
停下（v ≤ 0.5）时当前 = 1.0
```

**实测（`out/f6_segments.tsv`，31 段匀速直走）：**

| 速度 u/s | 片段 | 一个完整左右步（周期）s | 播放速度：实测 / 目标 | 差 | 脚滑 u/s：预测 / 实测 |
|---|---|---|---|---|---|
| 50 | 走 | 4.53 | 0.250 / 0.250（下限） | 0 | 11.5 / 10.8 |
| 75 | 走 | 4.53 | 0.250 / 0.307 | +0.057 | 14.0 / 14.3 |
| 100 | 走 | 2.79–2.83 | 0.401–0.406 / 0.406 | 0–0.006 | — |
| 105–110.8 | 走 | 2.74–2.79 | 0.406–0.413 / 0.430–0.450 | +0.017–0.044 | 4–11 / 9–13 |
| 112.7–120.6 | 跑 | 2.63–4.27 | 0.250–0.406 / 0.362–0.387 | −0.035…+0.137 | 11–43 / 11–33 |
| 125 | 跑 | 2.58–2.65 | 0.403–0.413 / 0.403 | 0 | — |
| 140–160 | 跑 | 2.51–2.66 | 0.401–0.424 / 0.450–0.516 | +0.04–0.12 | 13–36 / 17–37 |
| 160（从 250 减下来） | 跑 | 1.78 | 0.600 / 0.516 | −0.084 | 26.1 / 25.9（往后滑） |
| 175 | 跑 | 1.89 | 0.563 / 0.563 | 0 | — |
| 200 | 跑 | 1.85 | 0.576 / 0.642 | +0.065 | 20 / 26 |
| 225 | 跑 | 1.53 | 0.700 / 0.724 | +0.024 | — |
| 250（6 次） | 跑 | 1.35–1.60 | 0.668–0.793 / 0.802 | +0.009–0.135 | 3–42 / 13–49 |
| 380 冲刺（4 次） | 冲刺 | 1.00–1.14 | 0.733–0.837 / 0.868 | +0.031–0.135 | 13–59 / 75–84 |

- 31 段的"目标 − 实测"都在 −0.084…+0.137 之间，没有一段超过 0.15。
- 下限 0.25：50 和 75 u/s 的 cycle 速度完全一样（0.2206 /s = 0.25 ÷ 1.133）。
- 历史决定停在哪：同样 160.8 u/s，从下面加速上来 0.424，从 250 减速下来 0.600（`gait_c`）；冲刺 380，原地起冲 0.754，从 250 走着起冲 0.837 / 0.830。
- 脚滑：预测 > 15 u/s 的段，实测和预测差 ±3 u/s 以内（例：160 u/s 预测 28.5、实测 30.0；从上面来的 160 预测 26.1、实测 25.9）；预测很小时实测有 8–14 u/s 的底（20 Hz 姿势刷新和片段本身的脚动）。冲刺的实测比预测大 15–35 u/s：冲刺片段本身带"提早解锁"的 IK 规则（`TITAN-ANIM-FEEL` §1.4），脚本来就会滑。
- 冲刺匀速段只有 1.0–1.9 s（约 1–1.7 个周期）：stacks 上没有 1900 u 的直道；`gait_c` 想用的更长起点贴着道具，泰坦被卡（见 §5）。

**和推断值比：** 推断"播放速度 = v ÷ 地速"只对了一半：漏了 0.15 死区。按推断，250 u/s 走路应是走片段、周期 1.115 s；实测是跑片段、周期 1.35–1.60 s（中位 1.37 s）。`TITAN-ANIM-FEEL` 里 11-03 实测的"Ion 走路一周期 1.154 s"是在有起停和转向的路段里量的，那时片段和死区都没分开。

**照做：** 播放速度每帧算目标，但只有差超过 0.15 才改；起步时当前值从 1.0 开始。想要脚不滑可以把死区改小，但那就不是 TF2 了——TF2 的泰坦脚是会滑的（最多约 40 u/s）。

## 2. A2：什么速度从走片段换成跑片段

**规则（原生，`ref-titan-native`）：** v ≤ 0.5 待机；冲刺标志开着就冲刺（不看速度）；否则 v ≥ 0.45 × 站姿速度就跑，不然走；没有滞回。中型站姿速度 250 → 112.5 u/s（轻 121.5、重 94.5，原生会话推算，没实测）。

**实测（身体形状判定，`an_a2.py`）：**

| 速度 u/s | 脚前后摆幅 L / R u | 骨盆起伏 u | 片段 |
|---|---|---|---|
| 50、75、100、105、110、110.8 | 137.6–138.1 / 139.7–146.7 | 14.6–16.0 | 走 |
| 112.7、115、120、125、140、150、160、175、200、225、250 | 155.6–157.4 / 139.6–142 | 13.5–13.7 | 跑 |

门槛在 110.8 和 112.7 之间，和 112.5 一致。

**切换怎么混（`an_blend.py`，每帧摆姿势那段的长度）：**

| 切换 | 实测 | 规则 min(旧混出, 新混入) |
|---|---|---|
| 待机 → 走（100、110） | 0.194 s | min(0.2, 0.95) = 0.2 |
| 待机 → 走 → 跑（起步到 ≥ 125） | 0.58–0.64 s，从按键后 0.06–0.09 s 开始 | 走→跑 min(0.55, 0.95) = 0.55，叠在 0.2 后面 |
| 跑 → 冲刺（250 时按冲刺键） | 0.557 / 0.563 s，按键后 0.063–0.076 s 开始 | min(0.55, 0.95) = 0.55 |
| 待机 → 冲刺（原地起冲） | 0.195 s | min(0.2, 0.95) = 0.2 |
| 冲刺 → 跑（松键，还在 300+ u/s） | 0.208–0.215 s | min(0.2, 0.95) = 0.2 |

**和推断值比：** 推断"跑片段的 312 u/s 在走速和冲刺之间，最可能出现在冲刺加速段"——不对。250 u/s 稳定走路就是跑片段；冲刺加速段从按键起就是冲刺片段（加速段里播放速度受死区影响，见 F6）。

## 3. A6 / F7：停步时谁起作用

**规则（原生）：** 换序列的交叉淡入时长 = min(旧序列混出, 新序列混入)；旧姿势权重 smoothstep：w = (3 − 2x) x²，x = 1 − 经过时间 ÷ 时长。走/跑 → 待机 = min(0.55, 0.2) = 0.2 s，从速度降到 0.5 u/s 起算。

**实测（`an_a6.py`，4 次运行 32 次停步，50–380 u/s）：**

| 量 | 实测 |
|---|---|
| 松键到速度 0 | 50 u/s 0.035 s，100 0.07，175 0.12，250 0.17，380 冲刺 0.35 s |
| 速度 0 到主序列换成待机（cycle 跳变） | −0.01…+0.07 s（速度判 0 用的是 < 1 u/s，原生是 ≤ 0.5；姿势刷新 0.05 s 的分辨率） |
| 换序列到身体回到待机姿势（< 1 u） | 30 次 0.189–0.208 s，2 次 0.24–0.25 s |
| 换序列到身体离待机一半 | 0.10–0.16 s（两次 0.20 s：换序列的时刻没认准） |
| 身体离待机的距离 D(t)/D(0) 对模型的 RMS（换序列后 0.8 s 内，32 次平均） | 0.2 s smoothstep 0.084，0.2 s 线性 0.087；0.55 s smoothstep 0.294，0.55 s 线性 0.288（`gait_a` 13 次：0.058 / 0.061 / 0.304 / 0.294） |
| 冲刺停步 | 先冲刺 → 跑 0.21 s（松键 0.06 s 后），再 → 待机 |

**选中：0.2 s（待机的混入）。** 没选：0.55 s（走的混出）——误差大约 3.5 倍，而且实测一半时间在 0.10–0.16 s，0.55 s 的 smoothstep 一半要到 0.275 s。smoothstep 和线性在 0.05 s 的姿势刷新下分不开（RMS 差 0.003）。

**和推断值比：** `TITAN-ANIM-FEEL` §2.6 写"走的混出 0.55 s（待机自己的混入 0.2 s，谁起作用没核实）"、"实测停下约 0.5 s 速度到 0，约 0.9 s 回到站姿（GAPS §7）"。新实测：250 u/s 0.17 s 速度到 0、约 0.4 s 回到站姿（松键起算）。GAPS §7 的数大概是镜头或舱框量的，不是身体。

**照做：** 停步不做专门的混出时长，用"min(旧, 新)"这条规则；对 HSD 就是走/跑 → 待机 0.2 s、待机 → 走 0.2 s、走 ↔ 跑 0.55 s、跑 → 冲刺 0.55 s、冲刺 → 跑 0.2 s。仍然不加回弹（F7 原结论不变）。

## 4. F20：斜坡和台阶上的脚和骨盆

**测了什么。** `mp_homestead` 上一段约 9° 的坡（从 (−3456, −2336) 往 −x 下坡 620 u，再原地转身走回来），跑片段 250 u/s 和走片段 100 u/s 各上下一次，第一人称和第三人称各一遍（`gait_f20d`）；`mp_lf_stacks` 上一个 11 u 高的平台，从南边走上去（`gait_step`），走 100 和跑 250，第一人称 3 个落点 × 2 种速度、第三人称 3 次。更陡的 13°、17° 坡没测成：传送上去泰坦都被锁住（§5）。地面高度用 32 u 的道具地图双线性插值（误差几 u），所以脚的结论看"随前后位置怎么变"，不看绝对值。

**最重要的一条：脚 IK 只在身体被画出来时才做。** 第一人称下自己的泰坦身体不画，引擎每 7 帧才摆一次姿势，也不做脚 IK；第三人称（`hsd_cheats` + `thirdperson`）下每帧都摆，脚 IK 生效。对 HSD 来说，"别人看到的泰坦"和"第三人称"应该照第三人称的结果做。

**斜坡上的脚（`an_f20.py`）。** 看站立脚的"脚掌离地高度"随它在身体前后的位置怎么变：脚不贴地时，坡度 θ 下这个斜率应是 −tan θ（9° 上坡 −0.16，下坡 +0.19）；脚贴地时应是 0。

| 段 | 坡 | 第一人称：斜率 L / R | 第三人称：斜率 L / R | 不贴地应为 |
|---|---|---|---|---|
| 跑下坡 | −10.9° | 0.269 / 0.257 | 0.012 / 0.024 | 0.193 |
| 跑上坡 | +9.0° | −0.281 / −0.214 | 0.038 / −0.044 | −0.157 |
| 走下坡 | −9.9° | 0.238 / 0.143 | −0.004 / −0.011 | 0.174 |
| 走上坡 | +9.1° | −0.235 / −0.253 | 0.007 / −0.045 | −0.160 |
| 平地（stacks） | 0 | 0.009 / 0.013（跑）、−0.021 / −0.043（走） | — | 0 |

- 第三人称斜率都在 ±0.045 以内：**站立脚贴着坡面**。第一人称和"不贴地"一样甚至更大：脚没有 IK，前脚在下坡时悬空、上坡时插进坡里，最多约 20 u。
- 脚掌角度（`foot_*_sole` 的俯仰）在坡上变了 2–9°，但左右脚方向不一致、挂点的轴定义不清楚，**"脚掌转到坡面法线"这条没能从角度上确认**（推断值 100 °/s 保留）。

**斜坡上的骨盆。** 骨盆代理（`exp_torso_base`）相对原点的平均高度：

| | 平地 | 9° 上坡 | 9° 下坡 |
|---|---|---|---|
| 跑（250） | 109.0–109.4 | 96.8–97.1（**−12.2**） | 106.6–107.4（−2.2） |
| 走（100） | 113.3–113.7 | 102.8–103.1（**−10.5**） | 111.7–112.6（−1.4） |

- 上坡骨盆（头也一样）比平地低约 11 u，下坡只低约 2 u；**第一人称和第三人称一样**，所以不是脚 IK 做的。起伏范围也变大（上坡 28 u，平地 13.7 u）。原因没查清：看起来像身体落后于不断上升的原点（模型的渲染原点有平滑），下坡原点往下走时没有这个滞后。原点本身在坡上离地面 1.4 u（碰撞盒中心着地），和上下坡无关。
- 水平速度在 9° 坡上不变（250 / 100）。

**台阶（11 u 平台，`an_step.py`）。**

| 量 | 实测 |
|---|---|
| 原点 | 碰撞盒前沿碰到平台时（原点离边约 60 u）一个 tick 内抬高 10.6 u：引擎的"迈步"（`stepheight` 80），不是斜坡 |
| 骨盆和头 | 不跟着原点跳：原点抬高的那一帧之后，骨盆世界高度只比之前高 +2.5…+3.5 u，骨盆相对原点立刻低 8–12 u，之后在走路起伏里慢慢回来。第一人称和第三人称都这样，所以是模型渲染原点的平滑，不是脚 IK |
| 踏上平台的脚 | 第三人称：站立时离平台面 +6.4…+7.9 u，和平地上离地 +5…+9 u 一样，**被 IK 抬到台阶上**；第一人称：−3.9…−7.5 u，插进平台里 |
| 留在下面的脚 | 两种视角都离地面 +5…+9 u |
| 跑和走 | 一样（跑 250 也只用一个 tick 迈上去） |

**和推断值比：** 推断"脚 IK 每秒按步长 2 倍修正骨盆高度、脚掌 100 °/s 转向地面法线、`stepheight` 80，表现没实测"。新实测：脚确实贴地（第三人称），台阶是一个 tick 的迈步加身体平滑；骨盆在上坡会低约 11 u，但这不是 IK 造成的；脚掌转向法线没确认；IK 只在身体被画出来时做。

**照做：** 脚 IK 用"站立脚锁在地面高度"即可（斜率 0）；台阶让碰撞体一次迈上去，身体（骨盆、上身、镜头以外的模型）用一个平滑把 10 u 级的跳变吃掉；上坡把骨盆放低约 10 u 是 TF2 的样子，要不要照做由 HSD 自己定（原因不明，可能只是平滑滞后的副作用）。第一人称看不到自己的腿，可以不做脚 IK（TF2 就没做）。

## 5. 遇到的问题（给以后测 TF2 泰坦的会话）

| 问题 | 原因 | 办法 |
|---|---|---|
| 地图扫描全是 z ≥ 400 的平面 | stacks 头顶有看不见的玩家碰撞天花板 | 从 300 u 往下扫，或用"世界刷子 + 上方 250 u"模式 |
| homestead 上泰坦哪都不动（服务端速度 0、悬空不落、在地面标志 1） | 第一次出生是运兵船空降，空降后上机的泰坦一直被锁住 | 先 `hsd_gait_die`，重生后再上机 |
| 传送后泰坦不动（stacks 和 homestead 都有） | 起点让泰坦的碰撞盒（120 × 120 × 235）插进道具或地形；有几处净空检查说是空的也不动，原因没查清 | 尽量不传送：从能动的起点走过去、用键盘原地转身再走回来 |
| homestead x < 约 −5700 | 界外，约 10 s 后被世界杀死 | 只用 x > −5400 的坡 |
| 两次运行没进地图 | Northstar 主服务器拒绝 token（外部问题） | 过几分钟重跑 |

## 6. 能脱离 TF2 照做的 / 还缺的

**能照做的：**

- 片段选择：待机 / 走 / 跑按 0.45 × 站姿速度分，冲刺按键，没有滞回。
- 播放速度：v ÷ 地速，限 [0.25, 10]，冲刺 ≤ 1.25，0.15 死区，停下时置 1.0。
- 交叉淡入：min(旧混出, 新混入)，smoothstep 权重；HSD 用的几种切换的时长见 §2、§3。
- 停步、起步的实测时间线，可以直接当 HSD 的验收值。

**还缺的：**

| 项 | 为什么 | 要补的话 |
|---|---|---|
| 冲刺 4 s 匀速 | stacks 没有够长的直道，只有 1.0–1.9 s | 换一张有 2000 u 直道的图 |
| 轻型、重型的门槛 | 只测了中型 | 原生规则推出 121.5 / 94.5，需要的话用 Northstar / Legion 各跑一次门槛扫描 |
| F20 脚掌转到坡面法线 | 脚掌挂点的角度左右不一致，轴定义不清楚 | 用骨骼角度（`def_l_ball` 等）代替挂点，或从模型里读 `foot_*_sole` 的局部轴 |
| F20 陡坡 13°–25° | homestead 上传送到坡顶泰坦都被锁住 | 换一张有坡的图，或从能动的起点走过去 |
| F20 上坡骨盆低 11 u 的原因 | 第一 / 第三人称一样，不是脚 IK | 原生里找模型渲染原点的平滑（`ref-titan-native` 方向） |
